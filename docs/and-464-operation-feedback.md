# AND-464 会话操作反馈生命周期

## 诊断与范围

公共反馈原先以会话和操作类型存储失败，以新命令时间隐藏提示，并在新轮开始或发送成功时清掉整个会话的失败。它无法区分已失效的审批与尚未解决的归档失败。快捷设置的 mutation 状态未按会话隔离，也可能把前一会话的错误带到后一会话。

原截图的审批变化时序没有历史请求快照；“成功发出新消息后仍残留”仍不能从截图直接证明。本次通过模拟状态与延迟接口覆盖这些分支，不归因于缓存或节点故障。

## 公共实现与入口

| 对象 | 行为 | 边界 |
|---|---|---|
| `agent-operation-feedback.tsx` | 每次尝试绑定会话、动作及目标；独立成功、关闭、取代状态 | 普通输出或读取成功不等于操作成功 |
| 控制台 | 审批、重试、归档、恢复、停止、提醒、撤回及送达确认使用同一反馈 | 不扩充权限或控制入口 |
| 条目内面板 | 发送、撤回及送达确认共用反馈与结算规则 | 不新增原本未有的停止或审批权限 |
| 快捷设置 | 按会话隔离 mutation；原请求携带原会话 ID；区分请求失败与来源应用失败 | 不改模型、模式、强度与草稿的既有语义 |
| 文案与诊断 | 本地化动作及可恢复说明；原始错误纯文本展开 | 未知错误不直接成为英文主提示 |

更新的成功详情才可以确认审批目标消失、替换或已处理；成功列表可对账归档状态、提醒 revision 与派单状态。命令目标替换使旧操作结果过期，但同一条消息已经送达仍表示“无法撤回”，不宣称撤回成功。没有可信状态时保留原失败并允许关闭。

已取代的反馈单向转成非阻塞说明，后来的旧缓存不能重新把它变回故障。请求序号保护同一目标的新尝试，关闭仅结算该条反馈，不影响其他操作。反馈的展开和关闭使用现有按钮、details、主题与字号；关闭后在可用时回到当前输入框。

## 审批重试的安全边界

节点已有 `historyLimited` 且缺少投递预留时会把重试标记为 failed，这表示无法确认送达，并不证明未执行。保留服务端同 review 的幂等返回与节点不重放保护。请求阶段网络失败可从原入口人工原样重试；已有重试或送达不明不开放新投递。界面明确要求在原 Codex 会话核实，原诊断可展开。本轮不改变节点投递协议，不自动批准或重发工具操作。

## 验证与限制

新增状态判定单测覆盖目标、来源时间、会话隔离、未知结果、独立失败及诊断转义；错误码测试覆盖失效审批与重复重试。UI 回归覆盖新消息后保留归档失败、同轮输出、目标失效、迟到设置失败、关闭后不复活、送达不明不重发及双击，并在明暗主题、320px/桌面、触控和三档字号下检查可达性与溢出。

同时运行既有审批、设置、撤回、停止和条目内会话回归及完整 `npm run check`。具体执行结果随本条交付评论记录；浏览器使用独立临时数据库与模拟节点，不代表真实设备或生产端到端已验证。代码与本地提交不等于已合并或已发布；正式发布后仍需在真实原会话核对。
