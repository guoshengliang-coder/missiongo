## 第一轮

独立审阅者发现三个 P2 问题（独立审阅为代码路径核验，测试由原执行会话运行）：

| 问题 | 实际影响 | 补修 |
|---|---|---|
| POST 成功后 GET 失败时优先使用旧缓存 | 页面误称未发送或保留旧失败 | 绑定决定请求保留成功回执，仅成功读取对应结果后替换 |
| 外部原生会话误走内部发送通道 | 真实外部会话被误报不可用，无法继续 | 复用既有内部/外部发送与命令读取分流，保留原权限及稳定键 |
| 旧批准优先于当前有效批准 | 历史过期记录遮住当前继续入口 | 优先当前快照最新批准，保留历史且不把旧回执串入新请求 |

外部路由补修同时区分无命令的暂时不可用与有幂等引用但命令记录丢失：前者可以同键重新验证，后者保留原命令引用并禁止盲目重发，避免旧版失败记录永久阻挡已恢复的原会话。原生未连接或未同步有独立本地化说明。

验证结果：11 个服务端专项通过，覆盖真实外部原生会话 HTTP 路由、旧 unavailable 记录、断连/重连、pending、送达未知、送达、幂等和原权限。8 个浏览器用例通过，新增旧批准并存，以及明确成功 POST 后立即 GET 失败的场景，保留草稿并检查三档字号。类型检查、lint 和差异空白检查通过。

## 第二轮

新的独立审阅者核对第一轮补修，独立运行四个服务端专项，全部通过。未确认新增 P1/P2 阻塞；发现一个 P3 指引问题：已有命令变为失败时，原提示仍说“可以重试”，但实际必须沿原消息核对。

补修将已创建命令的投递失败与尚未创建命令的发送拒绝分开，前者显示原消息恢复说明并保留命令引用；后者可以沿同键重试。新增失败终态浏览器断言，服务端 11 个专项、lint、类型检查通过。完整检查另发现的数组选择 lint 已修正，保持现有浏览器兼容目标。

普通在途旧 GET 会被 TanStack Query 的 refetch 取消，不能仅凭旧读取尚未结束就声称存在竞态。极窄时序未复现的假设保留为第三轮核查目标，不冒充已证实缺陷。
