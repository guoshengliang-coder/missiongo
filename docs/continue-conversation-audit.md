## 第三轮

第三个独立只读上下文通过实际 React/React Query 和实际组件的临时浏览器探针，两次复现一个 P2：已启动的旧 GET 恰好在 onSuccess/onSettled 微任务间隙成功落缓存，后续新 GET 失败，旧读取仍会清除较新的发送回执。普通取消在途 query 不能撤回已成功落入缓存的旧结果。

补修为读取分配模块共享、单调递增的启动序列，发送 ACK 按决定请求记录其边界。只有 ACK 后启动且成功读取到对应请求的结果，才能替换本地回执；较早启动的成功读取和所有失败读取都不能清除它。多个观察者及组件重挂载使用同一读取时钟，避免比较互不相干的实例计数。

新增确定性浏览器回归：POST 在途时启动旧 GET，在 ACK 边界释放旧结果，随后新 GET 失败；页面必须保留排队、命令引用及核对入口，并且不能重新发送。再进行 ACK 后的新成功读取，必须正常更新到已送达。固定时钟保证此测试不依赖真实日期或墙钟精度。测试只在临时构建的组件中注入网络完成钩子，不向生产代码增加测试开关。
