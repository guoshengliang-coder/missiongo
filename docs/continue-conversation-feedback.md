# 继续原会话反馈与消息表达

## 结论

“继续原会话”发送的是原集成会话的继续消息。批准保存、消息发送、节点接收和实际执行是独立事实。

原路由传给 SessionSendRequests 的键含冒号，但该接口只接受 16～120 位字母、数字和连字符；发送被拒后，catch 仅返回 queued:false，前端收到正常响应而继续显示旧提示。修复以批次及决定请求的哈希构造合法稳定键，保留原决定，独立反馈继续操作结果。

## 共用实现与入口

| 对象 | 变化 | 边界 |
|---|---|---|
| MergeContinuations | 原请求键、发送结果核对、安全失败分类 | 不创建会话，不重复批准，不绕过原发送权限 |
| MergeReconciliation | 从读取接口恢复状态，明确提示及核对入口 | 会话紧凑卡片与集成详情共用；详情批准不隐式发送继续消息 |
| SessionSendRequests | 复用现有持久化命令引用 | 原消息成功入队后不因重试、刷新或响应丢失创建第二条 |
| 原命令回执 | 排队、接收中、送达未知、送达、失败、取消 | 不将消息送达写成执行完成；终态消息不自动重发 |
| 两类节点启动指引 | 结论、变化与影响、必要待决项 | 保留关键风险、授权范围及源历史；正文不由控制台裁剪 |

批准后未发送的失败分类沿用既有 idempotency_keys 存储，不新增业务状态和数据库迁移。命令已经创建时以原命令当前状态为准；此前失败说明不能盖过成功回执。结果读取按原账号、原会话和原请求绑定，先完成批次权限校验。

发送请求中的错误分类仅使用公开的固定枚举，未知错误提供可重试说明；技术诊断留在服务端日志，不把堆栈或原始异常正文发给用户。范围变化或决定已应用时不发送。已有其他待确认回复时先核对其结果；归档、原执行授权失效和受管会话限制仍由原入口处理。

页面在正在发送时阻止重复点击；响应未知先核对已保存结果，读取失败保留上次结果并阻止盲目重发。原发送已确认接收后只提供核对；取消、失败和送达未知继续使用原消息的既有恢复流程，不为重试伪造新请求。组件状态按批次隔离。

## 用户可见表达示例

正常进展：

> 修复已完成，正在验证重试和刷新后的状态。

真实障碍：

> 批准已保存，继续消息未能发送。已有一条回复结果待确认，请先核对原消息。

送达结果：

> 继续消息已送达，实际执行进展以原会话为准。

正式方案：一句诊断与推荐，多个问题用“问题／诊断结论／修改建议”短表；必要风险、范围及待决项直接可见，完整依据与验证进入固定版本 Markdown。

最终交付：说明行为变化、实际验证、剩余缺口和产物链接。不逐条播报命令、提交和 CI 任务，不重复展示完整 QA。重大风险及授权边界不能仅放进文档。

恢复消息附带同样的简短表达指引，帮助运行中的原会话沿用用户偏好；不承诺能强制模型遵守，也不改写已存在的输出。启动指引更新只影响实际加载到该指引的会话。

## 验证覆盖

- 服务端真实 HTTP：按钮批准并发送，合法请求键，重复点击和送达后重试只保留一个命令及一份批准。
- 已有待确认消息：失败原因持久化，批准保留，障碍清除后可继续。
- 归档、授权失效、命令失败／取消／送达未知：刷新读回准确结果，终态不自动重发。
- 未知异常：安全分类，响应无内部异常正文。
- 已应用决定：拒绝通知，不产生继续消息。
- 浏览器：320px／桌面、明暗主题，失败原因、重试、刷新、响应丢失后核对、送达、读取失败保留旧结果及草稿。
- 节点指引：Node 与 macOS 的各种 Agent／模式、项目会话和条目会话均包含核心表达约定。

自动化及截图审阅不代表真实 Android WebView 或原节点的生产验证。本次没有恢复截图中的原集成会话，也没有取得其完整历史和具体操作回执；历史消息冗长的具体来源仍未核实。真实设备及线上效果在后续获授权发布后核对。
