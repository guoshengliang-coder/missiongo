# 个人消息中心（AND-358）

首页保留现有布局。PC 顶栏固定为搜索图标、消息入口与录入；紧凑外壳中的消息入口在右侧。
角标是当前账号跨可访问项目的未读消息数，零时隐藏数字但保留入口，超过 99 显示 99+。
Agent 会话的未读数保持独立。搜索展开后自动聚焦，支持 Cmd/Ctrl+K 和 Esc；收起输入框不清除已有搜索条件。

## 阅读与业务处理

- PC 使用居中双栏消息中心；≤1023px 使用全屏列表与详情。两者共用数据和 `overlay.tsx` 的返回层级。
- 打开列表不标已读。详情请求成功并显示后才提交单条已读；失败可重试。支持按项目、类型和未读筛选。
- 全部已读只处理当前筛选内、不晚于列表快照序号的通知；之后到达的消息不被误清。
- 进入业务条目仍在中心内打开现有 `DetailPane`，评论按原始 ID 定位，回复与状态操作使用原有权限规则。
- 嵌入详情复用 `Modal`、草稿登记、请求中保护、`Select` 和现有评论组件。暂存附件未发送时退出需确认。
- 消息中心与原工作区使用不同的评论草稿存储范围；处理消息不会替换原工作区的未发送文字、回复对象或附件。
- 关闭业务详情返回消息，手机详情返回列表，列表再返回原工作区；关闭中心保留原筛选、选中项、阅读位置及焦点。
- 读取和外部发送不会推进业务状态。计数和消息每 5 秒刷新，后台标签页恢复焦点也会更新；不使用系统推送权限。

## 接收人与通道

沿用现有接收规则：显式 @（含显式 @ 自己）、直接回复（自动排除自己）、待验证提需者。
最新主线已有的业务决策外部提醒也同步留存在中心，不新增其他流转广播。
同一评论的 @ 与直接回复合并为一条，显示明确 @ 的原因；普通评论及 AI 进度不自动广播。

项目原钉钉配置区分别控制评论、待验证及业务决策的外部推送；不勾选时仅站内。
评论外部推送默认延续已启用行为，待验证及决策保留原项目开关。通道选择在事件入队时确定，只影响后续事件。
钉钉未配置、未绑定或发送失败不影响站内记录。人工补发沿用原外部任务，不创建另一条站内通知。
发送前仍核对当前账号与项目权限、评论是否撤回及业务任务是否有效。

## 存储与接口

迁移 `202611030125` 增加 `notification_events` 与 `personal_notifications`，外部任务通过
`personal_notification_id` 关联接收记录。事件、个人通知及外部任务在原业务事务中写入。
事件与接收账号唯一约束负责幂等。使用单调递增序号分页和限定全部已读的边界，不依赖客户端时间。
迁移不扫描历史事件、不补历史未读，也不重发历史外部通知。

以下接口仅接受已登录账号，客户端不能指定其他接收账号：

- `GET /api/v1/notifications`：最新 50 条；支持 unread、productId、kind、beforeSequence，返回下一页游标及 throughSequence。
- `GET /api/v1/notifications/unread-count`：当前可访问消息的未读数。
- `GET /api/v1/notifications/:id`：详情，只读。
- `POST /api/v1/notifications/:id/read`：幂等标已读。
- `POST /api/v1/notifications/read-all`：throughSequence 与 filter 限定范围。

列表、详情、计数和已读操作均重新检查项目访问能力。撤回评论的文本与摘要不返回；权限失效返回空列表或不可访问。
消息正文从当前源记录解析，不存储额外的历史正文副本，也不加入浏览器持久查询缓存。
