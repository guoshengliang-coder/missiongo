# 个人待处理中心（AND-358）

首页保留现有布局。PC 顶栏固定为搜索图标、待处理入口与录入；紧凑外壳中的待处理入口在右侧。
角标 = 未处理待办数 + 独立有效未读通知数。
零时隐藏数字但保留入口，超过 99 显示 99+。兼容字段 `coveredUnreadCount` 固定返回 0。分类数量显示在项目筛选里，不重复放在「待办 / 通知」标签上（AND-493）：
每个项目显示自己的待办数或有效未读通知数，「全部项目」显示当前分类的总数。

## 待办与通知

中心默认打开「待办」，「通知」保留全部、未读、类型和项目筛选及历史记录。
本轮待办接入当前业务已有明确责任的「交付待验证」：当前账号为非 SDK 提需者，条目处于 pending_verification，
项目未归档、条目未转移且账号仍可访问。管理员有验收权限不等于被指派了所有条目的个人待办。
其他任务类型需要明确责任人与结束条件后再接入；业务决策结果、普通 @ 和回复不自动变成待办。

待办从当前业务状态派生，包含通知功能上线前已存在的待验证工作；不补发历史通知或钉钉消息。
打开待办或将通知全部已读都不完成待办，必须由用户在原条目中执行验证等业务动作。
普通交付待验证只生成待办，不再生成重复站内通知；再有一条独立评论则合计为 2。

历史普通交付验证通知保留数据库记录及按 ID 读取、已读兼容，但不进入列表、计数和全部已读范围，不伪造 `readAt`。
协作验证通知由独立协作事件产生，接收人与普通交付待办不同，尚无对应个人待办，继续保留原通知与筛选能力。
待办 ID 包含最新交付事件 ID；打回后重新交付产生新轮次，旧轮次不会复活；同一条目上的独立评论不被自动清除。
归档、转移、权限变化均实时影响待办范围；查看业务详情时继续使用现有权限与并发版本校验。
Agent 会话的未读数保持独立。搜索展开后自动聚焦，支持 Cmd/Ctrl+K 和 Esc；收起输入框不清除已有搜索条件。

## 阅读与业务处理

- PC 使用居中双栏待处理中心；≤1023px 使用全屏列表与详情。两者共用数据和 `overlay.tsx` 的返回层级。
- 打开列表不标已读。当前通知及条目、时间线加载成功并显示后才提交单条已读；失败可重试，过期选择响应不标已读。支持按项目、类型和未读筛选。
- 全部已读只处理当前筛选内、不晚于列表快照序号的通知；之后到达的消息不被误清。
- PC 点击列表直接在右侧嵌入现有完整 `DetailPane`；手机点击进入全屏详情，不再通过摘要二次打开弹窗。评论按原始 ID、待办和业务结果按来源事件定位，回复与状态操作使用原有权限规则。
- 嵌入详情复用公共草稿收集器、请求中保护、`Select` 和现有评论组件。换项、切分类、筛选、返回、关闭及跳转关联条目或会话均保护未发送附件和草稿。
- 消息中心与原工作区使用不同的评论草稿存储范围；处理消息不会替换原工作区的未发送文字、回复对象或附件。
- 手机详情返回列表，列表再返回原工作区；保留列表滚动与焦点。已读或业务处理导致选中行移出列表时，当前详情继续显示处理结果；关闭中心不改变原工作区上下文。
- 读取和外部发送不会推进业务状态。计数和消息每 5 秒刷新，后台标签页恢复焦点也会更新；不使用系统推送权限。

## 接收人与通道

沿用现有接收规则：显式 @（含显式 @ 自己）、直接回复（自动排除自己）、待验证提需者。
最新主线已有的业务决策外部提醒也同步留存在中心，不新增其他流转广播。
同一评论的 @ 与直接回复合并为一条，显示明确 @ 的原因；普通评论及 AI 进度不自动广播。

项目原钉钉配置区分别控制评论、待验证及业务决策的外部推送；待验证外部队列和开关不受站内去重影响。
评论外部推送默认延续已启用行为，待验证及决策保留原项目开关。通道选择在事件入队时确定，只影响后续事件。
钉钉未配置、未绑定或发送失败不影响站内记录。人工补发沿用原外部任务，不创建另一条站内通知。
发送前仍核对当前账号与项目权限、评论是否撤回及业务任务是否有效。

## 存储与接口

迁移 `202611030125` 增加 `notification_events` 与 `personal_notifications`，外部任务通过
`personal_notification_id` 关联接收记录。事件、个人通知及外部任务在原业务事务中写入。
事件与接收账号唯一约束负责幂等。使用单调递增序号分页和限定全部已读的边界，不依赖客户端时间。
迁移不扫描历史事件、不补历史未读，也不重发历史外部通知。

以下接口仅接受已登录账号，客户端不能指定其他接收账号：

- `GET /api/v1/attention/count`：待处理合并计数、待办数、独立有效未读数，兼容重合字段固定为 0；`todoByProduct` 与 `unreadByProduct` 按可访问项目给出各自数量，供筛选框展示。
- `GET /api/v1/attention/todos`：最新创建的待验证条目优先，每页 50 条；支持 productId、beforeSequence，返回下一页游标。
- `GET /api/v1/notifications`：最新 50 条；支持 unread、productId、kind、beforeSequence，返回下一页游标及 throughSequence。
- `GET /api/v1/notifications/unread-count`：当前可访问且尚未结束提醒的未读数（不等于首页待处理数）。
- `GET /api/v1/notifications/:id`：详情，只读。
- `POST /api/v1/notifications/:id/read`：幂等标已读。
- `POST /api/v1/notifications/read-all`：throughSequence 与 filter 限定范围。

列表、详情、计数和已读操作均重新检查项目访问能力。撤回评论的文本与摘要不返回；权限失效返回空列表或不可访问。
待办及验证提醒结束时间从业务记录派生，本轮不新增表、不进行历史通知回填。
消息正文从当前源记录解析，不存储额外的历史正文副本，也不加入浏览器持久查询缓存。
不新增公告数据源、关注条目完成广播或普通状态变更通知；业务决策继续沿用现有事件。
