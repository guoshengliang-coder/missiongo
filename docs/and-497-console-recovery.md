# AND-497 控制台刷新与恢复交付记录

本次把聊天补读与附属清单请求解耦，连接状态只反映实时传输；会话卡片改为读取本会话交付，并保留页面内缓存、草稿及已有阅读位置行为。

## 诊断与实施

| 问题 | 实施结果 | 边界 |
|---|---|---|
| 慢交付读取挡住后续聊天刷新 | 按查询键记录在途版本、待更新状态和独立退避，优先登记正文读取 | 在途期间的新事件保留为后续一次补读；未完成的读取不推进重连游标 |
| 数据读取失败误报断线 | 读取错误不再改连接状态，握手截止 15 秒、静默流截止 60 秒 | 服务端心跳为 25 秒；没有空闲业务轮询 |
| 项目待集成清单错误进入普通聊天 | 共用 DeliveryCards、SessionDeliveryNotice、IntegrationDetails 使用带 sessionId 的交付读取 | 真正的本会话交付错误显示本地化提示与重试，已有交付卡片保留；项目清单仍独立报错 |
| 前台恢复重复、缓存返回空白 | 前台、focus、online 与事件补读使用同一调度器，健康流不重复建立 | 最近未观察的正文缓存最多 12 份、估算 16 MiB、最长 15 分钟；活动视图不被驱逐；正文不写磁盘 |
| 旧请求影响新授权状态 | reset/access 取消旧请求，任务按代次失效；账号变化清理会话缓存 | bootstrap、会话列表/详情及交付读取消费取消信号；取消与请求超时同时有效 |

真实传输为 HTTP SSE。改动没有替换传输协议，也没有改变消息发送协议、节点执行、原生权限、数据库会话列表/历史读取或 Android 宿主。

定向刷新利用规范会话 ID 和 relatedSessionIds。无法识别的资源通知仍保守刷新，避免漏掉身份合并。交付过滤使用已有账号/项目投影，仅缩小范围，不改变完整清单接口；无条目交付仍可见。

## PR 558 的 CI 补修

用户后续授权推送及登记待集成，原提交 fc26b059 已进入 PR 558。远端 CI 的两项 SSE 刷新测试分别测得 1367 ms、1359 ms，超过既有 1000 ms 门槛；本地通过不代表远端 CI 通过。用户明确要求继续修复后，在原任务分支处理。

隔离对照保留同一页面与测试，只替换 SSE 实现：主线实现快进浏览器时钟 180 秒后仍保持一次连接，刷新测得 80/84 ms；当前实现按新增的 60 秒静默检测断开，发送期间发生第二次连接，测得 836/825 ms。服务端时钟未前进，不能在这一跳跃中发送 25 秒心跳。旧测试将静默断流后的 1 秒重连退避计入健康连接刷新预算，这是本次失败的已复现测试前置条件错误，不是生产延迟基准。

补修仅改浏览器测试：明确断流提示、快进重连退避、等待真实 SSE 响应与连接恢复，并断言恢复没有空闲业务读取，然后测量健康连接下的刷新。原 1000 ms 阈值保留，生产静默检测和退避不变。暂停时钟控制中间状态，并给暂停命令预留传输时间；使用唯一消息避免重复运行命中旧评论。过程中的暂停时钟采样竞争已修正，未把它归因为产品问题。
