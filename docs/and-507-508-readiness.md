## 行为与范围

| 对象 | 变化 | 边界 |
|---|---|---|
| 集成启动 | 原批次计划前先调查全量候选、历史缺证、正式工具、产物来源及版本/说明 | 未选发布也能只读调查，不授权构建、安装或部署 |
| 就绪工具 | 正式入口增加readiness，独立检查分别保留事实与失败 | 不是check/deploy通过凭据；输入错绑和分页不全拒绝 |
| 前瞻影响 | 核对冻结/执行head与PR实际head、目标分支，再列预计产物 | 不将未合并代码冒充已集成或已发布；未知对象保留缺口 |
| 版本收敛 | 启动先列已知缺口，合并后使用既有patch算法统一准备版本与说明 | 后来新增候选仍需重新对账，不自动改版本或账本 |
| 交付报告 | report按完整显式范围逐份列代码、发布、本机效果、人工状态、缺口与责任 | 不自动改变条目、验收或通知状态 |
| 本机效果 | 摘要逐文件匹配原证据，实际入口成功且检查新鲜才呈现执行端已核实 | 脚本不读取任意目标文件、不执行安装，不替执行者取得原证据 |
| 等待汇报 | 突出阶段变化、失败、待决及责任变化，无变化降低轮询 | 不隐藏或改写原生源消息，不拦截用户询问 |
| 安装依赖 | 安装器与调查共用固定文件清单，并校验实际执行依赖 | 清单上的名字不算CI/覆盖门禁仍可执行的证明 |

共用现有候选分页、覆盖率、Git集成、版本与发布说明算法；不新增数据库迁移、
UI布局、浮层、业务状态或状态看板。原会话使用现有MarkdownText呈现结果，未扩大样式豁免。
`checkArtifacts`的单产物模式只供只读调查分别收集；原plan/check/deploy默认仍检查全部原产物。

实现主要位于scripts/release-readiness.mjs、scripts/delivery-report.mjs、scripts/release-tool-files.mjs、
原missiongo-release协调入口、安装器、release-preflight及服务端集成启动指令。
初次实施时Skill声明与服务端期望同步为5.71.0，后续与主线并行变更合并为5.72.0，内容摘要锁同时更新；没有修改正在运行的已安装Skill或服务。
操作与输入契约见 [发布范围](release-coverage.md#集成启动就绪报告and-507)、

## 证据边界与人工复核

- readiness输出checkedAt、HEAD/main、批次修订及摘要、完整候选摘要、独立checks与needsFollowUp。
  observed仅表示得到了结果，其内仍可有版本/覆盖阻碍；非零也要读全报告，零退出不是部署许可。
  调查首尾核实checkout和远端main一致性，变化要求刷新，不复用跨提交证据。
- report只能核对调用方明确给出的完整范围与原证据，不能替调用方证明scope已覆盖全部原授权范围。
  脚本检查scope/items一一对应，多份交付不按条目去重。CLI要求当前HEAD与远端实测main一致，
  不能把未合并分支的commit存在误报为目标主线已集成。
- 正式发布逐必需产物匹配原公开回执及来源祖先关系；调用方仍须核实原回执真实且适用于当前交付。
  脚本不重新下载每个包，不把卡片状态、过程文字或批次结束视作凭据。
- 本机已生效是执行端对限定目标、摘要、时间和实际入口的核查声明，不是脚本独立安装或系统证明。
  通用测试通过、单有无需发布原因、旧记录、失败/未运行均不足；remainingVerification与limitations保留。
  暂停、取消与已发生的合并/发布事实分开，是否恢复由用户决定。
- 每项都有下一步责任；发布/安装不等于人工验收。通知默认未核实送达，不伪造消息送达事实。
- 合成测试验证确定性输出、输入边界、正式安装副本与启动指令，不能证明所有模型在真实长会话中都遵守。
  发布后的真实集成会话、正式安装及各目标设备效果仍需在授权环境核对。
