# AND-524 项目下拉计数

控制台项目下拉选项将单一未读数字改为两个带标签的会话计数：“待处理 N”“未读 N”。零值弱化但保留文字，非零使用既有警告及未读语义色。数量分别说明，不合并相加。

## 范围与复用

- 共用 `ProductSwitcher`、`ProductBadge`、`Select.fitContent`、i18n 和主题令牌。新增样式仅作用于项目选项内的计数，未增加样式豁免。
- 覆盖桌面控制台及紧凑控制台的同一项目切换入口；菜单可按内容适配，在视口限制内换行，长项目名及精确计数保持可读。
- 仅展开时展示两项计数。收起值及其紧凑零值隐藏、99+ 和无障碍精确数量不变。非控制台项目切换不展示会话计数。
- 列表上方黄色提示、左侧导航、选择项目及关闭浮层行为不变。不新增接口请求或改变缓存、刷新、后端、权限及状态判定。

## 统计边界

`agentAttentionCounts` 使用与现有控制台相同的项目归属、归档排除及 `needsAttention` 判定，以会话 ID 和项目去重。数据来自 App 的同一 `allAgentSessions` 快照；未加载时不伪造零值。

未读继续由 `agentUnreadCounts` 计算，排除归档和 `active` 会话。异常未读按现有规则保留。待处理与未读可能重叠，各自独立计数。

跨项目会话可在多个项目各计一次。黄色提示 `agentOtherProjectCounts` 对其他会话计数，并排除任何关联当前项目的会话，因此不是其他项目数字之和。左侧数量还受 Agent、关联类型及搜索影响。只有无跨项目会话、无额外筛选、相同快照时才检查数字直接对应；其余按既有范围核对。

## 上线后的紧凑布局补修（2026-11-15）

用户审阅基于真实上线界面的设计图后，选择紧凑左右排版并明确要求开工。仅调整原展开菜单的布局，统计、收起值、其他区域、主题及交互规则保持原样。

现有 `product-switcher-option` 把资料和计数放在同一纵向容器；只加宽菜单不会改变排列。本轮将名称和简称归入独立的 `product-switcher-identity`。有计数的展开选项使用可换行布局，项目资料与计数组间距 24px。空间足够时左右排列，当前菜单的两类计数分别按各自最大标签自然对齐；空间不足或名称过长时计数组换行，继续显示完整内容。≤520px 视口沿用既有窄屏断点统一上下排列，避免同一菜单短名称横排、长名称竖排；桌面缩窗与触控设备使用同一视口规则。

菜单复用 `Select.fitContent` 的真实内容测量、视口限制、内容及字号变化监听，没有改动公共 Select 的定位、关闭或选择逻辑。计数尺寸用同样字体的不可见伪元素按当前最大标签占位，避免固定标签宽度或预留未来大数；不增加可访问名称或复制可见计数。保留原标签字体、背景及选中态，不添加样式豁免。

补修验证包含短项目名、24px紧凑间距、左右及计数列对齐、打开菜单后计数增至120、三档字号和桌面窗口缩至320px再恢复，以及全部原计数/项目切换/紧凑顶栏回归。

本轮实际结果：相关三份浏览器审计共36项通过（计数与布局20项、项目切换2项、紧凑顶栏14项）。实际查看了最终代码渲染的1440px浅／深色及320px窄屏截图，短项目名场景无多余中间留白，两类计数对齐；窄屏统一上下排列。截图使用临时测试数据及生成的项目字母图标，不是生产账号或此前AI设计图。
