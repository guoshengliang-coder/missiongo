# AND-422 方案表达与阅读验证

## 范围与实现

复用 AgentPlanContent / MarkdownText，不改审批协议和已保存正文。macOS、Linux 的派单和项目会话启动指导覆盖三个 Agent；MCP 的实际 plan / validation schema 描述及分发 Skill 同步约束提交正文。现有长度仍为 3000 / 700，先消除重复、后展示准确审阅内容，不截断已批准方案。Skill 版本随行为更新。

表格保持原生 table 语义，增加可聚焦滚动区，继承字号并允许单元格换行；宽表只在内部滚动。方案验证区直接可见，短方案不强制表格。结构化评论的网格列使用 minmax(0, 1fr)，避免宽表撑开卡片；共用变更回归会话、评论和文档预览。

## 验证方法

- 九组内容经过 Markdown 与正式方案组件渲染，检查关键限制、验证内容、短方案无表格、旧计划模式进度不会变成正式方案。
- MCP 真实 tools/list 返回字段说明，提交后再读正文验证结构与边界未变。
- 节点启动测试遍历三个 Agent、原生模式与派单/项目会话，检查表达要求不丢失且保持既有授权边界。
- 浏览器两个会话入口：320/375/1440px、明暗、三档字号，使用短中长样例及长链接验证宽度、字号、横向键盘滚动、可读正文、验证区和草稿保留；保存截图供人工查看。
- 原有审批可见性、批准后位置和去重回归继续运行。

## 证据边界

编辑样例和自动测试不是新模型生成结果。三种 Agent 在更新节点与 Skill 后的新会话生成质量、真实 Android WebView 及移动设备触控效果仍需上线前抽验。此次不自动启动其他 Agent 或生成额外审批；不宣称提示约束能保证所有模型稳定遵守。
