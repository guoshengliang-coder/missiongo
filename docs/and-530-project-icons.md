# AND-530 项目图标加载

条目列表与 Agent 控制台的项目选择器共用 `ProductBadge`。原组件在存在上传图标时只挂载懒加载图片，等待期间没有备用标识。延迟图标响应可在两个入口稳定复现：名称仍可读，图标位置空白，响应恢复后才显示图片。整行名称消失未复现。

## 展示与加载边界

- 图标外框固定为调用方指定的22/40/48px。等待、失败、解码失败时显示原项目颜色和前缀；当前图片成功解码后显示图片，并隐藏底层文字及底色，透明图片不会透出备用文字。
- 图标版本URL作为内部就绪边界的key。替换、删除、不同产品与卸载使旧回调失效；已缓存图片在监听器安装后复查complete/naturalWidth，不只依赖load事件。
- 项目菜单及收起值使用eager图片；设置页保留lazy加载。图片仍为装饰性内容，辅助技术读取项目文字，不增加菜单内按钮、spinner或交互焦点。
- 失败保持简称，不在一次菜单打开中自动循环重试；关闭后重开的新图片实例可重试。不增加随机URL或永久失败缓存。

## 有界后台预热

`useProductIconPreload`在已登录App持有账号生命周期内的单一队列。取可访问产品列表中未归档且有上传图标的项目，优先当前项目，再按原列表顺序取最多8个，最多2个在途预热。200ms延后启动，不阻塞首屏或菜单；单次8秒超时，超时/取消清除图片请求。

相同版本在途去重，成功预热不反复发起；候选变化取消移出的请求并替换待启动队列，成功标记也只保留当前有界候选。失败不立即重新入队，后续有变化的快照可再次尝试。账号变化/卸载销毁队列，StrictMode清理会取消尚未启动的工作。不保留图片字节或新增磁盘缓存，仅使用原URL与浏览器私有缓存。

取消时立即移除该请求的活动登记，不等待Promise回调；若相同URL随后重新入队，旧请求的完成结果必须匹配原AbortController才可结算。旧成功或失败不能删除新请求、更新其完成标记或错误释放并发名额。

预热上限只约束后台工作；用户打开菜单后，其余可见选项按正常图片加载。网络失败时的可用性由简称兜底保证，预热不保证所有项目真实图标立即出现。

## 共用入口与范围

共用实现为ProductBadge、原ProductSwitcher、现有颜色函数和CSS；附带覆盖设置项目列表40px标识、图标编辑48px标识。保留项目名称、排序、控制台计数、选中态、键盘/返回/焦点及原菜单定位。没有改动公共Select、服务端权限/缓存、数据库或原生客户端，没有新增样式豁免。
