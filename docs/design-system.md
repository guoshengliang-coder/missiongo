## 1. 原则

1. **令牌优先。** 组件只引用令牌，不写裸色值、裸字号、裸圆角。主题切换只改令牌，组件不感知主题。
2. **按容器适配，而不是按设备猜。** 布局随所在容器的宽度变化；全局断点只负责「单栏 / 双栏 / 三栏」这一层外壳切换。
3. **触控与指针分开对待。** 可点击区域在触控设备上不小于 44×44；任何只靠悬停才出现的操作，在触控设备上必须有常驻入口。
4. **可读性是底线，不是优化项。** 最小字号 11px，文字对比度不低于 4.5:1，焦点指示不低于 3:1。
5. **一个概念一个名字。** 状态、类型、派单阶段在三端使用同一套中英文文案。

## 2. 颜色

### 2.1 分层

| 层 | 令牌 | 用途 |
|---|---|---|
| 页面底 | `--canvas` | 应用最底层背景 |
| 面板 | `--surface` / `--surface-strong` | 卡片、列表、弹层 |
| 下沉 | `--surface-sunken` / `--surface-inset` / `--surface-field` | 分组区块、输入框底 |
| 侧栏 | `--sidebar-bg` | 桌面侧栏 |
| 交互反馈 | `--row-hover` / `--skeleton` / `--tile-bg` / `--badge-bg` | 悬停、骨架屏、附件占位、计数徽章 |

### 2.2 文字

| 令牌 | 浅色值 | 对 `--surface-strong` 对比度 | 用途 |
|---|---|---|---|
| `--ink` | #172033 | 16.4:1 | 标题、正文 |
| `--ink-2` | #2b3341 | 12.7:1 | 次级正文 |
| `--muted` | #4a525f | 7.9:1 | 说明、元信息 |
| `--muted-soft` | #5f6570 | 5.9:1 | 最弱的可读文字，不能再浅 |

需要「更淡」的文字时，用字号或字重拉开层级，不再新增更浅的灰。

### 2.3 品牌与操作

- `--navy` #172033 与 `--mint` #67e3b4 是品牌色，**两端恒定，不随主题反转**；`--on-mint` 是放在薄荷底上的文字色。
- 产品标识与中英文宣传语由 `product.json` 声明；图标以其 `iconSource` 的斜火箭为源。Web 共用 `Brand`，Android 与 macOS 使用生成资源，PWA maskable 图标另留安全区；SDK 验证 Sample 保持独立身份。生成及校验见 [品牌资源](../assets/brand/README.md)，界面覆盖登录、首次使用与工作区，回归见 `tests/ui/branding.audit.spec.ts`。
- `--primary-bg` / `--primary-fg` 是主操作按钮，**随主题反转**：浅色为 navy 底白字，深色为 mint 底深字。
- 一个视图里只能有一个主操作（实心主按钮）。其余操作一律用次级按钮或图标按钮。

### 2.4 语义色

- 强调：`--accent-bg / -line / -text / -text-strong`
- 危险：`--danger / -bg / -bg-strong / -line`，只用于不可逆操作和错误
- 警告：`--warn-bg / -line / -text`
- 状态：`--status-{inbox|ready|progress|hold|verify|done|cancelled}-{fg|bg}`，一状态一对
- 类型：`--type-{idea|requirement|bug|task|note}-{fg|bg}`，一类型一对
- 状态与类型**不能只靠颜色**表达，必须同时有文字或图标。

### 2.5 代码与日志区

`--code-*`、`--tile-log`、`--viewer-bg` 在两套主题下都保持深色，像编辑器一样。

### 2.6 深色模式

- 由 `index.html` 在首帧前把 `data-appearance` 写到 `<html>`：优先 `?appearance=` 参数（Android SDK 用），否则跟随 `prefers-color-scheme`。
- 这段脚本必须以同源外部文件的形式同步加载，不能内联：部署的 CSP 是 `script-src 'self'`，内联脚本在生产环境会被拦截（见复盘 B12）。
- 焦点环统一用 `--focus-ring`（取当前主题的 `--blue`），2px 实线，覆盖按钮、输入框、链接、`summary` 和可聚焦元素。
- 深色块只重定义令牌。**组件样式里不允许出现 `rgba(255,255,255,…)`、`#fff` 这类只在一种主题下成立的值**；需要半透明时，新增令牌。

## 3. 字体与字号

- 字体栈：`Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", sans-serif`。项目不加载字体文件，Inter 只在本机装了时生效，其余机器用系统字体；中文字体显式列出，不交给各浏览器自己挑。
- 字号阶梯（只能从这里取）：

| 令牌 | 值 | 典型用途 |
|---|---|---|
| `--text-xs` | 11px | 徽章、计数、眉标（下限） |
| `--text-sm` | 12px | 元信息、按钮小号 |
| `--text-md` | 13px | 列表摘要、辅助操作 |
| `--text-base` | 14px | 正文、表单标签、标准按钮 |
| `--text-lg` | 15px | 列表标题 |
| `--text-xl` | 18px | 弹层标题、区块标题 |
| `--text-2xl` | 23px | 页面标题（窄屏） |
| `--text-3xl` | 27px | 页面标题（宽屏） |

- 触控设备上的输入框（`input`、`textarea`、`select`）字号不小于 16px，避免 iOS Safari 聚焦时自动放大页面。这是阶梯之外唯一允许的例外。
- 文字截断统一用单行省略号或 `-webkit-line-clamp`。被截断的内容必须有一个触屏上也能用的途径看到全文，例如点开详情或展开；`title` 只能作为桌面上的补充，因为触屏上没有悬停。
- 不要假设用户装了哪种字体。组件高度用 `min-height`，不用固定的 `height`，这样微软雅黑、苹方、思源黑体这些行高不同的字体都能放下；中文标题不用负字距。

## 4. 圆角与阴影

- 圆角阶梯：`--radius-xs` 6 / `--radius-sm` 8 / `--radius-md` 11 / `--radius-lg` 14 / `--radius-xl` 18，另外胶囊形用 999px。
- 对应关系：徽章与小控件 xs–sm，按钮与输入框 md，卡片与列表容器 lg，弹层与抽屉 xl。
- 阴影只有两档：`--shadow`（浮层）和 `--shadow-soft`（面板）。
- 品牌页头的细边框及装饰性硬阴影是标识专用样式：由 `.brand-mark` 的 CSS 边框与 `drop-shadow` 提供，不烙入应用图标资源。应用图标保持无边框、平面、居中，各平台自行裁切与添加系统效果。

## 5. 布局与适配

### 5.1 外壳断点（现行）

| 宽度 | 外壳 |
|---|---|
| ≥ 1280px | 列表与详情双栏 |
| 1024–1279px | 侧栏 + 单内容区 |
| ≤ 1023px | 紧凑外壳：顶栏 + 抽屉导航 + 底部浮动录入按钮 |
| ≤ 520px | Agent 控制台切为单窗格 |

JS 中的 `useMediaQuery` 必须使用与 CSS 相同的断点值。

### 5.2 安全区与视口

- 外壳高度用 `100dvh`，并以 `100vh` 作为回退。
- 刘海和手势区通过 `--safe-top/right/bottom/left` 引用，不直接写 `env()`。
- 弹层和抽屉必须设置 `overscroll-behavior: contain`，防止滚动穿透到底层页面。

### 5.3 设备模型：四个维度分开判断

| 维度 | 判断依据 | 决定什么 |
|---|---|---|
| 宽度 | `max-width` / `min-width` 外壳断点、容器查询 | 布局：单栏、双栏、三栏 |
| 输入方式 | `(pointer: coarse)` / `(hover: hover)` | 触控尺寸、输入框字号、悬停效果 |
| 可用高度与方向 | `(max-height: …)` / `(orientation: landscape)` | 吸顶、吸底元素是否收起 |
| 内核版本 | 构建基线（`vite.config.ts` 的 `build.target`） | 能用哪些 CSS 和 JS 特性 |

**不能用宽度去推断输入方式。** iPad 横屏有 1024–1366px 宽，但它是触控设备；缩小的桌面浏览器窗口可能只有 800px 宽，但它用的是鼠标。

### 5.4 触控

- 触控设备（`pointer: coarse`）上，可点击元素不小于 44×44，包括筛选胶囊和图标按钮；输入框字号不小于 16px。**这一条和宽度无关。**
- 悬停效果写在 `@media (hover: hover)` 里。只在悬停时才出现的信息或操作，在触控设备上必须常驻显示。
- 任何宽度下，长表单的提交操作都要吸底，不能要求用户滚到表单末尾才能提交。
- 包在 `<label>` 里的勾选框、单选框，以 label 的尺寸作为点击区域；这样的 label 必须加进外层可点击容器的点击豁免，点到 label 留白处只切换勾选。
- 软键盘弹出后，吸底元素和聊天输入框必须仍然可见。

### 5.5 浏览器基线

- 当前基线是 **Chrome/Edge 90、Firefox 90、Safari/iOS 15.4**，以 `vite.config.ts` 的 `build.target` 为准，README 里的说法必须和它一致。
- 可以使用基线之外的 CSS 特性（例如 `color-mix()`、`@container`），但必须保证旧浏览器上**功能不受影响**：
  - 颜色类的特性，在同一条规则里先写一条普通令牌作为回退，再写新写法，例如 `background: var(--warn-bg); background: color-mix(...);`；
  - 布局类的特性（例如容器查询），必须保证不支持时退回到的默认布局本身也是可用的。
- 只有当某个特性缺了会让功能失效、并且无法回退时，才考虑提高基线。提高基线要同时更新 README，并给出不依赖内联脚本的提示页（部署的 CSP 是 `script-src 'self'`，禁止内联脚本）。
- 附件预览不能假设浏览器支持所有格式：HEIC 图片要转码后再预览；浏览器无法播放的视频，给出下载入口。

### 5.6 测试矩阵

发版前在 7 个档位下验收：小屏手机、手机竖屏、手机横屏、平板竖屏、平板横屏、笔记本、桌面，每档都分浅色和深色。具体视口和真机要求见 [复盘与改进方案 §5.2 DC](ui-ue-review-2026-09.md)。

## 6. 组件约定（现行）

| 组件 | 类名 / 实现 | 约定 |
|---|---|---|
| 主按钮 | `.primary-button` | 每个视图一个 |
| 次级按钮 | `.secondary-button` | 取消、返回和其他次要操作；可点击边界必须清楚 |
| 危险确认 | `.danger-button` | 删除、撤销等有明确后果的确认；使用主题危险色令牌 |
| 图标按钮 | `.icon-button` | 必须有 `aria-label` |
| 弹层 | `Modal`（原生 `<dialog>` + `showModal()`） | 有标题 `aria-labelledby`；Esc、遮罩和返回遵循草稿保护；保存期间禁止关闭；打开时聚焦 `[data-initial-focus]` |
| 灯箱 | `MediaLightbox` | 全站唯一的媒体预览 |
| 更多菜单 | `OverlayMenu`（原生 details） | 接入共享返回；危险项放最后，并用分隔线隔开 |
| 状态 / 类型徽章 | 使用 `--status-*` / `--type-*` 令牌对 | 必须带文字 |
| 空状态 | 图标 + 标题 + 一句说明 + 一个主操作 | —— |
| 错误提示 | 使用 `--danger-*` 令牌 | 文案必须经过 i18n，不能直接显示服务端原文 |

### 临时编辑与确认

| 场景 | 容器 | 生效方式 |
|---|---|---|
| 昵称、邮箱、密码、短配置、新增账号或模块、创建凭证 | 短表单弹窗 | 一个明确的保存／创建按钮，取消放弃本次草稿 |
| 选择大量条目、配置多个对象 | 宽弹窗或独立配置页 | 显示作用范围，集中保存，提供取消／还原 |
| 字号、会话快捷选项等简单且可逆的选择 | 原位控件 | 明确自动保存，失败恢复并提示 |
| 日志、环境、历史记录、明细与帮助 | 原位展开 | 只承担阅读或现有表单的可选字段，不开启另一项编辑任务 |

- 查看模式保持页面稳定。点击编辑才进入临时任务，不把整块独立表单插入列表或详情。
- 一个编辑任务只有一个主要提交动作。取消与提交使用不同层级，退出登录采用独立区域中轮廓清楚的正常尺寸按钮。
- 显式取消放弃当前草稿；关闭按钮、Esc、遮罩、浏览器或 Android 返回若可能丢失输入，先提供「继续编辑／放弃修改」。确认留在当前弹窗内，保留输入和焦点。
- 请求提交后，输入、取消、关闭和返回都不能把进行中的请求伪装成已取消。失败在弹窗内说明并保留可重试内容；成功关闭并更新原位置。
- `Modal` 的 `dirty` / `pending` 属性可登记父组件拥有的草稿；弹窗内表单用 `useDialogDraft`，设置表单通过 `useSettingsDraft` 自动接入。浮层统一由 `overlay.tsx` 管理返回层级，录入面板也使用同一机制；不得自行 pushState/back 或复制旧的 `historyManaged` 模式。
- 账号资料与权限分别进入编辑、分别保存。设备昵称与仓库映射、产品图标与产品名称也各自说明保存边界，不能用一个「取消」暗示能撤销其他已保存任务。
- 条目编辑内已有附件的删除、图片标注都先暂存，点击「保存修改」后提交；取消不会删除或覆盖已有附件。一次保存包含多个服务端请求时，部分失败须说明已完成的部分，并允许重试剩余操作。
- 创建访问令牌与 SDK 凭证后，在弹窗中展示仅一次的明文和复制入口；「我已保存令牌」结束流程，关闭后清除明文。
- 删除、归档、停用、撤销等操作使用产品确认弹窗，写明对象与影响范围。保留浏览器对刷新和关闭标签页的原生未保存保护。
- 手机使用适配视口的底部弹层；长内容可滚动，操作栏保持可见。桌面居中弹窗。macOS 短编辑使用原生 sheet，未保存内容与请求期间禁止意外关闭。

### 交付状态操作

- 独立状态检查弹窗及产品、条目入口已取消；列表和详情的开发完成、提交验证直接走普通状态操作，不打开查找、关联或人工补证表单。
- 共用 `itemTransitionActions`、状态流转接口和现有权限、版本及幂等契约；人工操作不伪造集成与发布凭据。历史检查结果不再生成卡片进度或阻塞提示。
- 取消回归见 `status-checks-retired.audit.spec.ts` 与服务端 `status-checks-retired.test.ts`，覆盖产品工具栏、列表、详情和旧客户端请求。

### 同行控件与分层筛选（AND-334/335/336）

- 标准工具栏的下拉框、按钮、图标按钮和输入框以 44px 最小外部高度对齐，圆角使用 `--radius-md`。
- 条目列表紧凑筛选使用 38px 外部高度（36px 下拉触发器加容器边框），触控下统一 46px 外部高度（44px 触发器加边框）。同行按钮与外部边框对齐，不只对齐内部文字。
- 快捷维度顺序为 Builder、提需者、类型。根据列表容器宽度依次收起类型、提需者，极窄时保留总筛选入口；已选条件仍可在摘要和总览查看、清除。
- 更多筛选先展示维度及已选摘要，进入维度页编辑草稿，返回总览继续组合；统一应用，取消放弃本轮编辑。

### 条目评论（AND-346）

- 原评论与每条回复各有独立的主题色块，讨论组继续保留关联和具体回复对象。卡片内统一容纳作者、正文、附件与提醒结果。
- 回复入口常驻在每条评论顶部右侧，使用图标加“回复”文字；更多菜单保留次要操作。窄容器与大字号下作者可截断并点开全文，操作入口必须完整可达。
- 卡片上内边距 2px、下内边距 8px（AND-370 压缩后）。作者按钮、回复与更多入口使用同高首行并垂直居中，时间与来源标记位于下一行；桌面最小高度 36px，触控至少 44px。回复与更多入口共用主题底色反馈，支持悬停、按下及键盘焦点，不能只用轻微文字变色表达可点击。
- 作者下方的时间、来源标记与“回复谁”共用可换行的元信息行；空间足够时同行显示，长名称仍可点开查看。回复与更多入口保持首行对齐。

- 接手事务一次留存条目级历史关系、撤销旧执行凭据。旧会话恢复只显示历史活动，不恢复条目操作权；其他条目保持隔离。
- 复用 `Modal`、`Select` 及现有草稿/请求保护；不增加 CSS 豁免。验证见 `execution-stop.audit.spec.ts`、`agent-handoff.audit.spec.ts`、服务端执行与迁移测试。原生设备实际停止不在本功能保证范围内。

### 会话消息反馈与图片产物（AND-371）

- 消息正文与投递反馈分层：时间置于顶部，底部只显示发送中、排队中、送达中或已送达待执行。送达不能表示已经执行；失败与送达不确定继续明确展示恢复操作。
- 可取消的排队消息在状态文字右侧显示常驻下划线的「撤回编辑」文字按钮：与状态同字号、字重 600、无图标无边框，悬停、按下和焦点有反馈。取消成功后恢复文字与附件，取消失败保留原消息；恢复中的草稿不能再次发送，切换会话不串入附件。
- 排队、发送、送达中统一使用旋转图标，已送达用静止对勾；正常状态与撤回操作位于用户消息气泡外下方，不用隐藏度量层为最长状态预留空间。触控回执文字与操作靠上对齐，保留 44px 点击区，不能因操作垂直居中而在气泡下增加视觉留白。气泡正文不因回执切换而增高或增宽，回执本身按内容收宽并可换行（AND-441）。投递完成后仍显示「已送达，待执行」，等回复出现在对话记录里才整行消失（AND-421）。
- 空闲挂起属于常规资源回收（AND-424）：节点给出的挂起说明收进「运行详情」展开区，折叠时只保留中性的「已挂起」状态；红色错误条只留给 stalled、unavailable、failed。控制台与条目内面板共用同一判定。
- 消息级详情合并到唯一的“运行详情”。默认按内容收宽，只显示简短运行状态；等待原因、耗时、同步诊断和活动明细原位展开。权限请求及异常恢复提示不放进折叠区。复用 `AgentReplyFeedback`、`AgentRunDetails`，控制台和条目内会话面板共用。
- 正文沿用 `--console-text-sm`（默认12px、行高1.6），时间与状态使用 `--text-xs`，编辑操作与状态同字号并加粗到 600；独立会话字号与全局字号均保持现有缩放和11px下限。气泡内边距上下12px、左右16px，气泡与外部回执间4px，消息间12px，图标文字4px。触控操作至少44×44；气泡按内容收宽并保持用户消息右边缘一致。
- 完成的 Codex 图片生成记录通过同一条原生记录明确给出的 `savedPath` 生成图片产物引用，不转发生成提示词、Base64或无关工具日志。普通 Agent 明确输出的本地图片链接也自动显示缩略图；普通文档继续按需预览。复用既有账号/会话/节点绑定、产物存储和预览弹层，不把本机路径交给浏览器直接读取。
- 图片必须有加载、失败和重试反馈；预览可查看原图并下载，关闭恢复触发器焦点。已保存的图片可在原节点离线后查看；尚未保存时仍需要原节点和原文件，旧版节点需更新才能同步图片生成事件。Linux 节点的图片产物读取同样校验精确原生会话引用、文件类型、大小和符号链接。
- 回归来源：`and-371-session-feedback.audit.spec.ts`、`and-421-reply-status.audit.spec.ts`、`and-424-suspended-idle.audit.spec.ts`、`agent-artifacts.audit.spec.ts`、`and-360-session-health.audit.spec.ts`、`agent-approval-visibility.audit.spec.ts`，以及 `AgentArtifactTests`、`CodexProtocolTests` 和 Linux `artifacts.test.ts`。浏览器覆盖明暗、320px窄屏、触控、三档字号、状态变化、投递状态几何稳定、挂起说明归属、撤回附件恢复与图片加载/失败/重试。

### 聊天图片与状态反馈（AND-377/378/379/380）

### 单选控件（AND-322）

- Web、Android/macOS 内嵌 Web 页面及反馈 SDK 页统一使用 `Select`（`apps/web/src/select.tsx`），提供可访问的 select-only combobox。独立原生选择器保留系统行为，详见[覆盖清单](and-322-select-audit.md)。
- 默认使用 `--surface-strong` 底色、`--select-border` 边界、`--ink` 值文字、`--muted` 箭头；边界在明暗主题单独声明，不把普通分隔线用作控件边界。箭头与值分开布局，左右留白 12px、间隔 10px。
- 表单至少 44px 高；紧凑筛选、Agent 快捷设置至少 36px。触控设备上统一至少 44px、字号至少 16px。使用最小高度，让字体放大后仍能容纳文字。
- 工作区 Builder/类型将标签与当前值视作一整个有边界的控件。产品切换器保留产品图标、名称、前缀及未读数；与表单共用箭头、焦点、菜单定位和状态规则。
- 菜单优先在控件下方留 6px；空间不足时向上，按可用视口限高并滚动，左右至少保留 8px。普通页面挂载在 body，模态弹窗中挂载在 dialog 下，避开内部滚动容器裁切并保留模态可操作性。兼容现有浏览器基线，不依赖 Popover API。
- 当前选中项使用语义强调底色和勾选图标；活动项使用焦点边框。悬停只在支持 hover 的设备生效。禁用项不可提交、不可被键盘导航选中，禁用分组同样适用。
- 键盘方向键打开和导航，Home/End 到首尾，Enter/空格确认，Escape 取消并保留原值，Tab 关闭并继续正常焦点顺序；支持文字前缀跳选。菜单点击选择后焦点回到触发器；点外部关闭且不抢走外部焦点。
- 收起值可截断，打开菜单后长选项必须完整换行。原生隐藏 select 仅负责表单序列化、必填校验和 reset，不向用户弹出系统选择器。校验失败时聚焦可见触发器并显示错误信息。

| 规则 | 产品行为 | 共用能力与验收 |
|---|---|---|
| NAV-01 顶层优先 | 有浮层时，返回只处理最上层；菜单 → 预览/表单 → 详情/会话 → 列表/工作区。无浮层时区分页面“上一级”与浏览器历史，不假设两者目的地总相同 | 共用浮层生命周期；关闭、Esc、浏览器/Android 返回；打开/关闭重复循环和前进后退。对应原审计 UIA-01 |

### 公共实现与接入方式

- 表单使用 `Modal`，通过 `dirty` / `pending` 或 `useDialogDraft` 接入保护。它内部调用 `useModalSurface`，不单独管理历史。
- 预览使用 `OverlayDialog`，传入可访问名称及关闭回调。浏览器原生顶层负责背景不可交互与焦点边界；关闭恢复触发器，触发器被移除时回到当前弹层或内容区。
- 特殊原生 dialog 仅保留已登记的媒体灯箱、图片标注和更新提示；必须调用 `useModalSurface`。新增场景优先组合公共组件，不扩大登记表。
- 菜单使用 `OverlayMenu`；单选使用 `Select`；其他非模态浮层调用 `useOverlay`。关闭回调返回 `false` 表示仍在保护或提交中，不能撤掉该层。普通内容展开仍用原生 details。
- 菜单操作进入弹窗时，先将返回焦点交给仍可见的菜单触发器；关闭弹窗不能回到已收起的菜单项。编辑途中窗口缩窄、触发器被隐藏或禁用时，回到顶层弹窗或当前可见内容区，优先于外层工作区；回归须覆盖这种布局变化。
- 设置页离开确认通过 `holdOverlayHistory` 等待原页面历史恢复，通过 `afterOverlaysClose` 等待确认层退栈后导航；业务组件不得复制协调代码。
- 详情工具栏使用 `useToolbarOverflow`，以展开状态的实际宽度决定是否将次要动作放入更多菜单。保留返回、主操作、更多入口，不截掉按钮；新增工具栏复用此能力并测试自身标签和状态。
- 字号令牌随用户设置缩放，`--text-xs`、`--text-sm`、`--console-text-sm` 以 `max(11px, …)` 保底；禁止另建绕过下限的缩放字号。
- Android SDK 编辑器通过 `setBackDepth` / `setEditorBusy` 分别上报浮层和提交状态；宿主先退出浮层，提交期间等待，未完成的编辑根页面保留放弃确认。旧 SDK 需要升级才能获得完整返回行为。

### 自动检查及例外处理
