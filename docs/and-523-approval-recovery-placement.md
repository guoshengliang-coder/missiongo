# AND-523 原批准恢复入口与反馈

聊天底部不再持续展示原批准恢复提示；可恢复操作收进“方案与审批”，诊断留在对应版本详情。

## 诊断与实现

原 `DocumentPlanRecovery` 同时挂在控制台消息流和条目会话底部。即使服务端返回 `history_incomplete`，仍提供核验按钮；重复得到相同结果时用户看不到新的结果。恢复 API 只核验已有记录，不自动补读原历史，因此重复点击不能补齐证据。

两入口移除底部组件，改由共用 `AgentPlanRecords` 承载。概览仅在当前精确文档/修订对应 `ready_to_restore`、尚未批准、未归档且服务端授予恢复权限时展示“恢复之前的批准记录”。证据不足、未找到原批准、来源冲突、范围变化及身份不可用仅在匹配的版本详情提供诊断与下一步；旧版本不展示当前版本诊断。

`DocumentPlanRecovery` 区分处理中、网络请求失败、领域核验未能恢复、恢复成功。网络重试复用原请求键，同步锁合并重复点击；领域失败不继续提供无效操作。成功保留明确反馈，刷新会话、概览及版本记录；后续独立的有效批准可清除旧失败。反馈取得焦点，提交中通过 `useDialogDraft` 使用既有 `Modal` 关闭保护；不清除聊天草稿。

共用组件：`AgentPlanRecords`、`DocumentPlanRecovery`、`Modal`、`BackButton`、`useOverlay` 与既有 `agent-plan-record` / 主题令牌。无新增 CSS、样式豁免或服务端写能力。

## 授权与边界

用户在原项目会话确认条目全文后明确要求“提交，并处理这个条目”。沿用该实施授权，未再次索批。服务端原账号、原会话、文档、修订、权限和证据核验保持，不恢复其他会话的实际批准，不排执行命令、不启动新回合、不改变人工验收。

基线为最新主线 `d1505397`，调查时公开健康提交与主线一致；交付前再次 fetch 确认主线未前进。主工作区已有内容保持，本次独立分支开发。此次授权不含 push、merge 或生产发布。
