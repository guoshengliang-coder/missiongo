# 会话历史分页

普通与外部 Codex 会话默认读取元数据和回合状态，再通过 `thread/items/list` 按消息分页读取可见正文。回合摘要不能作为正文来源：它可能省略中间消息及独立方案。轮询不请求全量历史，不恢复原生会话，也不为读取发送任何输入。受管执行仍使用完整执行证据路径。

完整记录留在 Codex；服务端已保存的消息不删除。每次同步按现有来源消息 ID 更新，另带 `history` 元数据：来源续页游标、是否到达历史起点，以及可选的读取错误。正常近期窗口不是故障；较早页失败时保留已确认的最新回合与重试位置。

## 界面与服务端

- 新 Web 调用详情时使用 `history=recent`，最多返回 50 条、约 512 KiB 已存消息，以及可选 `history.nextCursor`。旧调用保持完整响应兼容。
- `POST /api/v1/agent-sessions/:sessionId/history` 携带服务端给出的 `cursor`。已有消息直接分页；原生旧页使用独立任务队列。`GET` 同路径带 `cursor` 只查询结果，不创建任务。
- 原生游标不直接交给浏览器。服务端只接受本账号、会话及当前节点/原生引用下已登记的续页标识。已有标识在实时窗口推进后仍可使用。
- 原生旧页按需保存在 `agent_history_pages`，最新同步边界保存在 `agent_history_sources`；两者不替换会话运行记录。成功页缓存可重复读取，失败后由用户重新请求。来源解绑后旧节点不能提交结果。
- 原节点通过 `GET /api/v1/node/agent-history` 取最多 2 个待处理只读请求，并向对应页回报可见消息。源读取按消息数量、字节和时间预算分页；上传内容超过预算时报告 `too_large`，保留原始记录。服务端拒绝未登记目标、跨账号/节点结果、重复游标和游标环。

`useAgentHistory` 与 `AgentHistoryLoader` 供控制台和条目内面板共用。前插历史保持阅读锚点；实时窗口推进保留已显示内容，来源消息 ID 去重。失败保留正文和草稿，重试不自动发送消息；切换会话后迟到页失效。未知来源时间留空，不编造历史时间；有回合开始时间时使用该来源时间。

历史提问只读。历史读取不占回复/停止通道，不改变运行状态、任务阶段、活动或未读，也不作为旧回复未送达的证据。发送继续使用原子预留和未知交付保护。历史消息中的产物链接仍须核验精确来源消息；节点可分页查找该消息，不能将任意路径作为读取权限。

## 兼容与边界

- 旧服务忽略可选详情参数与同步字段，新的独立节点端点返回 404 时节点跳过该通道。默认轻量同步及完整交互需配套更新 Mac 与服务端/Web。
- Codex 不支持消息分页 API 或原节点暂不可用时，保留可核实运行状态和已有内容，显示说明及重试入口；不回退为无界全量历史读取。
- MCP 会话读取继续读取已经同步的记录，同时通过 `knownGaps` 明确近期窗口可能不完整，不能把缓存声明成完整原生历史。
- 新会话启动提示要求等待 CI 时优先查状态和结论，失败后再按需读取日志片段；完整日志留在文件或产物中。该提示不会改写已有原生历史。

验证来自 `CodexAppServerControlTests`、`APIClientTests`、`NodeLoopTests`、服务端 `agent-history*.test.ts`、活动/权限回归和 `codex-history-pagination.audit.spec.ts`。浏览器覆盖两处入口、窄屏触控/桌面、明暗与三档字号，检查锚点、重试、草稿、去重、实时更新和会话切换。完整生产发布及原会话端到端复测另行核验。

## 正文与方案回归修复

- 原生消息游标使用 `items-v1:` 前缀。旧摘要游标只在同一已绑定会话中重启消息读取，以来源消息 ID 去重；新来源窗口替换旧续页入口，已保存消息及旧缓存证据不删除。消息分页结束才可声明该次来源读取完整；摘要结束不能证明正文完整。空消息页与非空摘要冲突时报告来源读取缺口。
- 每次最多读取 8 页、每页 50 个原生项；达到可见消息数量、字节或时间预算后保留消息游标，单回合也可继续分页。macOS 与 Linux Codex 保留中间正文、方案及明确图片产物；超大单条内容明确报告页面错误。Linux 历史请求走独立只读 IPC，不进入回复队列或修改投递日志。
- OpenCode 两端优先读取最新消息，达到数量上限或异常游标时保留最新内容并提示历史受限，不能从最旧端截取一段冒充当前正文。Claude 原有流式正文链路保持。普通 Hermes 外部接入仍仅有进展记录，不因此获得原生全文或控制能力。
- 已登记实施方案通过独立的 `implementationPlan` 字段读取，包含修订版、正文、验证目标、条目范围、批准与有效性；读取权限沿用会话授权。批准、断线或范围变化不删除方案正文，也不扩大审批权限。
- 控制台和条目会话共用 `AgentPlanContent`，直接呈现 Markdown 正文及验证目标。审批条只呈现决定与投递状态；同文原生方案去重，不隐藏普通正文或不同内容的原生方案。批准后保留内容、草稿和原位置。

验证：消息级原生协议回归、旧游标与缓存回归、Linux 只读来源绑定/预算、OpenCode 长历史、方案批准后读取，以及 `agent-plan-content.audit.spec.ts` 的两入口、320px/桌面、明暗和三档字号。原会话只读诊断使用显式传入的 socket/thread 环境参数，不在仓库保存真实会话身份或正文。

## 原文一致性约束

原生消息是会话正文的唯一来源；回合摘要只能提供运行状态、回合 ID 和错误信息。
消息接口失败时保留服务端已有原文并报告缺口，禁止把摘要写回正文。
MCP 进展上报以 `progressReports` 独立保存与展示，不再伪装为原生 Agent 消息。

普通派单、项目及合并会话、外部接入共用正文约束。节点不得截断单条正文后按原来源 ID
覆盖已存原文；单条文本上限为 4,000,000 UTF-16 单元，历史页编码预算为 30 MiB，
历史上传路由上限为 32 MiB。超过预算时报告缺口，原记录保留在来源端。
Linux 节点私有状态文件读取上限提高到 512 MiB。客户端与服务端须配套升级；旧服务仍可能拒绝超过原上限的消息。

Codex 原生工具执行记录随消息页保留；不读取加密推理内容。
Claude 节点不再从本地状态删除第 2,000 条之前的消息。消息首尾空白不在同步及存储时改写。
已有被裁剪或摘要化的缓存需要重新读取原生来源才能恢复；本次代码变更本身不等于线上历史已修复。
