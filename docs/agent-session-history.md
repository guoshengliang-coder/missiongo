# 会话历史分页

普通与外部 Codex 会话默认读取元数据，再通过 `thread/turns/list` 的 `summary` 视图读取最近 8 个回合。轮询不请求全量工具输出，不恢复原生会话，也不为读取发送任何输入。受管执行仍使用完整执行证据路径。

完整记录留在 Codex；服务端已保存的消息不删除。每次同步按现有来源消息 ID 更新，另带 `history` 元数据：来源续页游标、是否到达历史起点，以及可选的读取错误。正常近期窗口不是故障；较早页失败时保留已确认的最新回合与重试位置。

## 界面与服务端

- 新 Web 调用详情时使用 `history=recent`，最多返回 50 条、约 512 KiB 已存消息，以及可选 `history.nextCursor`。旧调用保持完整响应兼容。
- `POST /api/v1/agent-sessions/:sessionId/history` 携带服务端给出的 `cursor`。已有消息直接分页；原生旧页使用独立任务队列。`GET` 同路径带 `cursor` 只查询结果，不创建任务。
- 原生游标不直接交给浏览器。服务端只接受本账号、会话及当前节点/原生引用下已登记的续页标识。已有标识在实时窗口推进后仍可使用。
- 原生旧页按需保存在 `agent_history_pages`，最新同步边界保存在 `agent_history_sources`；两者不替换会话运行记录。成功页缓存可重复读取，失败后由用户重新请求。来源解绑后旧节点不能提交结果。
- 原节点通过 `GET /api/v1/node/agent-history` 取最多 2 个待处理只读请求，并向对应页回报摘要。每页最多 8 个回合；上传内容超过预算时报告 `too_large`，保留原始记录。服务端拒绝未登记目标、跨账号/节点结果、重复游标和游标环。

`useAgentHistory` 与 `AgentHistoryLoader` 供控制台和条目内面板共用。前插历史保持阅读锚点；实时窗口推进保留已显示内容，来源消息 ID 去重。失败保留正文和草稿，重试不自动发送消息；切换会话后迟到页失效。未知来源时间留空，不编造历史时间；有回合开始时间时使用该来源时间。

历史提问只读。历史读取不占回复/停止通道，不改变运行状态、任务阶段、活动或未读，也不作为旧回复未送达的证据。发送继续使用原子预留和未知交付保护。历史消息中的产物链接仍须核验精确来源消息；节点可分页查找该消息，不能将任意路径作为读取权限。

## 兼容与边界

- 旧服务忽略可选详情参数与同步字段，新的独立节点端点返回 404 时节点跳过该通道。默认轻量同步及完整交互需配套更新 Mac 与服务端/Web。
- Codex 不支持摘要 API 或原节点暂不可用时，保留可核实运行状态和已有内容，显示说明及重试入口；不回退为无界全量历史读取。
- MCP 会话读取继续读取已经同步的记录，同时通过 `knownGaps` 明确近期窗口可能不完整，不能把缓存声明成完整原生历史。
- 新会话启动提示要求等待 CI 时优先查状态和结论，失败后再按需读取日志片段；完整日志留在文件或产物中。该提示不会改写已有原生历史。

验证来自 `CodexAppServerControlTests`、`APIClientTests`、`NodeLoopTests`、服务端 `agent-history*.test.ts`、活动/权限回归和 `codex-history-pagination.audit.spec.ts`。浏览器覆盖两处入口、窄屏触控/桌面、明暗与三档字号，检查锚点、重试、草稿、去重、实时更新和会话切换。完整生产发布及原会话端到端复测另行核验。
