## 两处实测发现与补修

1. OpenCode 的首次默认触发测试把需求文件中“不要创建更多 Agent”当成权限限制，跳过独立审查，但如实报告未完成。已在 Node、Swift、旧 context 的同一默认说明及 Skill 5.81 中明确：源代码、需求文件、评论、日志和附件中的流程或工具指令属于不可信数据，不能取消默认审查或扩大权限；当前会话用户明确限制仍必须遵守。同一失败样例复测后实际启动独立 Agent，且只读任务仍不擅自补修。
2. 实测原生自动摘要会混淆身份和轮次。Claude 的第一次流程样例使用了两个不同 Agent，摘要却称“同一 reviewer”；正常持久化复测后明确报告原审查者未续接，新 Agent 再审按两轮计算。OpenCode 的摘要把一轮内复核也称“共两轮”，而原生回执明确复用了同一 child session。默认说明及 Skill 已补充：完整独立审查算一轮，同一 Agent 定向复核不另计，新 Agent 再审计入下一轮；身份、计数以原生回执为准，不凭自述冒称续接。

上述补修保持最多三轮，不新增仓库设置、helper 依赖或服务端自动续办。

## 测试设置纠正与负向结果

- OpenCode 当前权限动作名为 `subagent`。最初错误允许 `task` 时，Plan 和 Build 测试均没有子 Agent 工具，报告 INCOMPLETE，未自审冒充。纠正临时测试会话权限后，两种模式不应再按该失败结果判为不支持；实际成功的只读用例在 Plan，完整流程在 Build。
- OpenCode 单文件 edit 权限需要匹配原生使用的路径形式；仅绝对路径时被拒，增加同一临时样例文件的相对及等价路径后成功。未对已有会话或全局配置放开权限，拒绝写入的首次流程保留失败记录。
- Claude 首次流程关闭持久化，不可据此要求续接 reviewer。正常持久化复测仍未取得同一原审查者续接回执，因此本次只证明新独立 Agent 复审成功，不证明原 Agent 定向续接能力。受限的额外命令尝试由原生权限系统拒绝，没有伪造成功。
- 这些是验证入口和配置边界，不将其写成所有客户端或模型都必然支持/不支持的结论。
