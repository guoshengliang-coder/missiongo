# AND-542 会话图片提前准备与预加载

新图片消息同步后即可由原节点读取并保存，不再以打开会话作为准备前提。Web 控制台仅预取近期会话中已保存且符合预算的图片，行内和灯箱使用同一内容缓存。

## 范围与共用实现

- `AgentArtifacts.prepare`：派单、项目和绑定外部会话的已验证 snapshot 入口调用，只处理近期50条 agent/plan 消息中明确链接的图片；排除用户消息、execution 日志、文档和任意路径。
- 同账号、已证明为同一原生会话的镜像按 sourceId 和规范化路径去重；保存结果仍是首次 ready 的快照，不随重复心跳覆盖。
- 自动 pending 最多8份/会话、32份/节点，节点每次获取最多4份且手动任务优先。文件不存在时每隔至少15秒、最多追加2次自动尝试；其他失败不自动重试。大于20 MiB的文件继续由既有节点校验拒绝。
- 自动收集和节点报告保持账号、产品、操作/AI权限、Builder转交后的原会话撤权及原会话/节点绑定核验；只有查看权限仍可读取已保存内容，但不能收集更多文件。用户未读、草稿、活动时间和执行状态不因后台读取而改变。
- `/api/v1/agent-artifact-preloads` 只接受最多8个明确会话，逐个检查其聚合成员权限；只投影已保存的图片引用和内容包大小，不返回消息全文或图片字节，不标为已读。历史保存包没有大小元数据时仅 stat 原存储包，不读原节点文件。
- Web 最多预取12张图片、2个并发，单图内容包最多2 MiB、一批最多8 MiB；超出预算仍可按需打开。后台队列延迟300ms启动，隐藏页面、离开控制台或变更图片集合时取消无人查看的未完成请求；已打开图片的请求不受影响。
- 内容缓存只驻留当前页面内存；空闲内容包最多12份、按base64字符串估算最多16 MiB、5分钟GC，活跃预览不强制淘汰。不写磁盘持久缓存。
- 控制台与条目内面板继续共用 `AgentArtifactMarkdown`、`ArtifactImage`、`ArtifactViewer`、`MediaLightboxFrame` 和 `ZoomableImage`；图片成功、失败、等待、保存状态、重试及文档按需预览保持原交互。未增加样式或豁免。

## 兼容与限制

服务端迁移202611221407为产物记录新增自动尝试、延迟重试及内容包字节数；现有记录仍可读取。复用节点产物协议，不修改或要求升级 macOS、Linux/Windows 节点。旧节点对格式的实际能力仍以该节点版本为准。

后台预算是优化范围，不承诺所有历史图片或刚输出的图片立即显示；未保存时仍依赖原节点在线且原文件存在。已保存的大图可绕过后台预算通过前台正常查看，文档不自动准备。实际原生节点端到端及生产效果须单独核验。
