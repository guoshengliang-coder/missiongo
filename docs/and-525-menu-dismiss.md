# AND-525：公共菜单外点关闭

## 诊断与实现

加号菜单使用 `CommonCommandMenu` → `OverlayMenu`，原公共实现只登记 Back/Escape，未处理外部点击。条目、评论与协作入口各自复制了全局监听，造成行为不一致。

`OverlayMenu` 统一监听捕获阶段的 `pointerdown`；内部操作保持正常，外点只关闭本次手势开始时的顶层，不阻止原点击或恢复触发器焦点。Esc/Back 仍使用既有返回协调器与焦点恢复。页面 `.back-button` 仍由返回流程消费。

浏览器可在不同原生监听器之间执行 MutationObserver/React 清理，子层关闭后父层会立即成为顶层。因此在 window 捕获阶段以 WeakMap 保存本次事件的顶层 ID，菜单与 `useOverlay` 外点处理共同使用该快照，避免一次手势关闭两层。事件结束后记录可随事件回收，不保存输入内容。

删除 App 列表/详情、评论及协作的重复全局监听；保留业务动作、菜单定位、局部 blur、菜单转弹窗与草稿保护。普通 details 继续只承担内容展开，无新增样式或豁免。

## 共用组件与覆盖入口

| 对象 | 变化 | 验证入口 |
|---|---|---|
| `OverlayMenu` | 外点关闭及事件顶层快照 | 加号、嵌套状态、菜单转编辑器 |
| `useOverlay` | 使用同一事件顶层快照 | Select/设置与父弹层返回契约 |
| `CommonCommandMenu` | 自动继承公共行为 | 控制台、未发送的新会话、条目内会话 |
| 消息操作与常用指令 | 继承外点，保留内部动作 | 常用指令保存、管理、插入与草稿恢复 |
| 列表、详情、评论、协作 | 移除重复监听 | 嵌套菜单、评论复制/撤回、协作审批与编辑 |
| 控制台顶栏、设置更多 | 自动继承公共行为 | 代码复查；未逐入口专项交互验证，定位与业务动作未变 |

## 验证与限制

专项测试覆盖明暗、390px 触控及 1440px 鼠标：外点关闭、内部留白不关闭、重复开合、触发器切换、Esc、浏览器返回、窄屏页面返回按钮、内部动作、焦点、原 URL 与草稿。新会话回归另覆盖 375/768/1440px，条目会话回归覆盖草稿与展开祖先恢复。嵌套测试明确断言一次外点只关闭子菜单，之后 Back/Escape 逐层退出。

最终实现的 UI 回归分两组执行：51 项（加号、协作、评论、新会话、公共浮层与历史）全部通过；16 项（页面返回按钮补验与常用指令）全部通过。两组共有 4 项加号用例，合计 63 项不同用例。未更新视觉基线。

`npm run check` 对最终公共浮层实现退出 0，覆盖 lint、身份、原生契约、迁移、基础样式、脚本/工作区测试、类型、构建与性能门禁。补充测试后的 `npm run lint` 和 `git diff --check` 同样通过。

测试中使用输入框可见左侧点击位置，避免把被菜单覆盖的中心当作外点；后续插入场景显式设置光标位置，保留正常点击移动光标的产品行为。未使用 force 点击或降低关闭/焦点/草稿断言。

本机 Chromium 及隔离数据库验证不代表生产或 Android WebView 真机验证。首次沙箱完整检查因本机端口和进程诊断权限失败，获得技术权限后按原检查重跑。测试结果与最终提交一并记录在条目交付评论。

发布产物为 Web/Server；本改动不需要重新分发原生客户端包。未获推送、合并或发布授权；本地验证通过不代表已上线或人工验收。
