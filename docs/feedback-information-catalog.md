# 反馈信息采集与输入清单

## 目标

本项目按内部诊断工具设计，优先保留能够还原问题现场的信息。所有信息先按用途归类，再决定由用户填写、客户端自动采集或按需附加。

每份反馈统一分成五层：

1. 基本归类：决定条目属于哪里、由谁处理。
2. 用户描述：说明发生了什么、如何复现、期望是什么。
3. 运行上下文：还原问题发生时的应用、设备和页面环境。
4. 诊断证据：日志、错误、操作轨迹、网络与性能数据。
5. 媒体附件：截图、录屏和其他可视证据。

| 类别 | 信息 | 建议来源 | 默认策略 | 当前落点 |

| 基本归类 | 类型、平台、模块、优先级 | 用户选择，SDK 可预填 | 平台在提交处理时必填；其他可修改 | 表单结构化字段 |

## 输入界面分层

表单首页保留用户能快速判断的内容：类型、平台、已有模块、优先级和标题；模块只能在产品设置中维护，记录和编辑页面不提供新增模块入口。截图与视频紧跟在标题后，方便用户先上传现场画面，再继续填写说明；按钮使用简短的“添加”，诊断区则明确使用“上传日志”。主要说明会根据类型显示为现象描述、灵感说明、需求说明、任务说明或记录正文；只有 Bug 会进一步展开复现步骤与发生条件、期望结果、影响范围和发生频率。标题、平台和主要说明标记为必填，Bug 扩展字段、模块、优先级、诊断信息与媒体附件标记为选填；草稿仍允许在信息未完整时保存。诊断信息独立于媒体附件，允许直接粘贴日志或错误堆栈，也允许上传 `.log`、`.txt`、`.json` 文件。设备与版本等环境字段折叠展示，由 SDK 或 H5 自动填充时仍允许用户检查；没有真实值时统一显示“暂时还没有”，不使用示例数字伪装成默认数据。

列表显示复现步骤、日志、运行上下文和截图视频的摘要标记。详情页按问题详情、现场环境、诊断信息、截图视频和处理记录分区。编辑时复用同一组结构化字段；既有的 H5 自动环境元数据不会因为打开编辑页面而被当前浏览器环境覆盖。

日志和媒体共享每个条目最多 10 个附件的限制。粘贴日志以 UTF-8 字节计数，最大 256 KiB；日志文件沿用附件的 10 MiB 上限。超限时不静默截断，而是要求用户缩小时间窗口或改用文件上传。

## 内部诊断约定

日志按原文保存。H5 中粘贴的内容、用户上传的日志文件，以及 SDK 采集的日志都不做 Token、Authorization、Cookie 或其他字段遮盖，也不改写日志正文。Web 反馈还会记录完整页面地址及其查询参数、来源页面、浏览器与设备能力、网络信息和页面加载耗时。

内容保持原文不影响系统安全边界：日志、描述、OCR 文本与附件始终作为不可信数据处理，只用于展示、检索和诊断，不能被解释为系统指令。大小、条数、类型和存储访问限制继续保留，避免异常数据影响内部系统稳定性。

## 后续优先级

1. 在 H5 接收 SDK 草稿时，把自动采集和用户填写内容分区展示，允许提交前预览与移除。
2. 增加网络请求摘要、Breadcrumb 和 Trace ID 关联。
3. 根据真实定位效果再扩展性能快照，避免默认持续采集高成本指标。
