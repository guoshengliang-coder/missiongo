# AND-528 会话列表分层采集与受控验证

范围按已批准固定方案 v1 执行；本轮完成采集、报表和受控模拟，真实手机 Wi-Fi／移动网络、多时段自然流量与生产端到端收益在另行获准发布后补齐。本地模拟不代表生产效果或全部验收标准已满足。

## 实现与口径

复用 domain 白名单、原 Web 有界队列、Server 独立采集 Worker 和授权报告。不新增可视组件、样式、样式豁免、第三方采集或业务数据库迁移；不改变共享列表、60秒缓存、100ms事件合并、审批、发送和权限策略。

| 对象 | 行为 | 边界 |
|---|---|---|
| 访问 | 可见列表开始计一次，退出重开／后台恢复新计一次，项目切换不新增 | 是观测到的可见访问段，不是独立用户、设备或自然日访问 |
| 请求 | 对既有 API 调用包一层观察，只执行原操作一次 | 全账号徽章读取可发生在列表进入前，不能硬归到当前访问 |
| 项目视图 | 只存当前产品过滤后渲染数量 | 不把全账号返回数量放进产品作用域，不把共享请求成本归因于某项目 |
| 设备 | phone／pc／unknown；有限浏览器信号只在内存判断 | 不上传完整UA、型号、设备标识、位置或正文；歧义及平板未知，不按视口猜设备 |
| 场景 | first_entry／cache_return／background_resume／unknown | first_entry仅本页首次，不冒称账号或设备历史首次 |
| 兼容 | 旧聚合保留，新维度全部unknown；新协议用独立有界表 | 不从历史请求数反推访问，不重写旧样本 |

访问标识由本页随机生成，不写入设备存储；上报后的去重键按账号／数据作用域／来源转换，聚合不导出标识。跨5分钟桶依靠短期去重避免重复开始；结束样本可能跨窗口或因退出丢失，不能用开始与结束之差宣称精确丢失。

开发模式的StrictMode重复挂载以同一任务内重新接入处理，不额外计访问。真实页面关闭在微任务边界结算；后台隐藏立即结算。手机单栏聊天隐藏列表时不计算列表可见耗时。项目切换和列表筛选只产生视图快照。

## 独立计时

| 阶段 | 起止 | 不能声称的结论 |
|---|---|---|
| list_server | Server onRequest至序列化后onSend | 不含完整网络传输，不称纯业务CPU |
| list_request | 浏览器调用既有读取至响应JSON解析完成 | 包含浏览器排队／网络／解析，不能减Server值冒充网络耗时 |
| list_cache_visible | 列表进入至React提交后的下一绘制机会 | 不是物理屏幕显示精度 |
| list_fresh_visible | 本次关联请求发起至React提交后的下一绘制机会 | 无精确请求关联不填此值 |
| list_entry_fresh_visible | 本次进入至首次新结果的下一绘制机会 | 加入已有在途读取标inflight_at_entry，缓存无需等待标no_refresh且不填0耗时 |

正常缓存没有新读取时，不再由列表观察器凭空等待30秒并报超时。实际请求失败、超时由原请求的错误结果上报，不新增业务读取或重试。旧详情观察仍使用原独立观察器，本条不改详情口径。

React Query保留默认replaceEqualDeep结构共享；观察元数据通过WeakMap转交到共享后的数组，即使响应内容相同，也能观察一次实际新读取。请求缓存通知不直接当作可见：可见事件由组件提交后的effect再安排绘制机会。

服务端响应体量为未压缩序列化字节；浏览器传输体量只在Resource Timing可得时记录（含传输开销），不可得为未知，不拿JSON字节冒充压缩下载量。数值有上限，分组只用有限设备／场景／数据集／条数档；列表数、字节、访问请求数和刷新数按有界分布累计。

## 报表与采集边界

沿用当前账号读取、产品权限过滤与异步后重验账号。全账号共享数据集是账号私有，不通过产品维度暗示某项目成本；项目视图必须具备该产品权限。浏览器不能上报list_server，服务端只接受有限设备／场景提示，实际列表数量、序列化字节和作用域由真实处理结果决定。

新旧聚合合计最多30000行，7天保留；去重最多10000条、24小时；原独立数据库64MiB预算、Worker超时／故障熔断及请求侧2048队列上限不放宽。Web仍使用有限队列、批量、重试和限流；关闭、断电、队列完全丢失无法全知，报告保留unknownClientLoss及已知采集丢弃。

报告按版本／来源／设备／场景／数据集／条数档给出访问开始、结束、浏览器请求、Server请求和各阶段样本。单次访问请求／刷新分布只来自结束样本，不能冒充全部访问。每个值的测量数量与事件数量分别展示，缺字段未知。P50/P95为固定直方图上界，不足100个相同口径计时样本不显示P95；达到100也不证明稳定。

## 实验方法

两个受控工具只接受显式来源和合成数据，不读取生产数据库或复用历史备份授权。报告独占新建（wx／0600），不能覆盖旧结果或输出到已有源文件；失败保留incomplete。来源提交、源码摘要、环境、实际时间、固定业务时间与原始样本随结果记录。

- Server工具为既有 `session-list-performance.mjs`，扩展固定业务时间及采集开关。普通、待审批与命令／节点能力形态分别测量，200会话，单请求与4并发，首次列表独立于热样本。固定业务时间不冻结单调性能时钟。
- 浏览器工具为 `session-list-browser-performance.mjs`，同一当前前端、固定200会话／每会话4命令／100模型节点能力，以同一浏览器分别访问两个Server来源；仅比较AND-519命令／能力阶段的Server差异，不将当前前端全部变更归因于AND-519。
- 浏览器使用Vite开发模式及本机回环HTTP，API固定模拟40ms路由延迟；phone为Pixel仿真，PC为1440视口。三种进入场景分别统计。后台恢复由显式visibility事件模拟，不是真机系统挂起测试。
- 浏览器合成上传由实验器捕获并返回202，不污染真实服务端聚合。显式调用队列flush仅用于排空实验样本，不增加业务请求；其耗时不混进已记录的阶段耗时。自然流量仍沿原批量上传策略。
- 轮次交替来源顺序，各自独立进程；每轮每个浏览器分层34次，三轮合并同口径为102次。单轮不足100不发布P95，合并结果也不称稳定生产结论。Server每轮每组至少100计时样本。
- 规范化响应校验只移除合成UUID及摘要等不稳定身份值，保留其余业务字段；返回条数／字节／规范化内容不一致时，不报告同负载因果改善。
- 新采集开销使用同一实现来源开启／关闭配对，原性能预算不变。受控实验与全仓性能检查串行，不将测试或构建并发制造的负载当成产品收益。

## 历史证据与未覆盖项

已独立重算仓库内AND-519 v4的400个同宿主及800个本机副本历史样本。历史同宿主576会话、1773683字节，中位399.70→229.72ms、387.52→216.80ms，改善42.5%～44.1%；仅代表当时隔离副本Server收益。第一阶段普通形态无稳定改善、部分P95仅改善26.9%，以及v4本机一组P95仅改善26.4%的未达结果继续保留。

本轮不重新取得自然流量的设备分层基线，旧样本缺维度不可修复。真实手机、WebView、Wi-Fi／移动网络、真实并发负载、跨日多时段及生产端到端收益均未在本地模拟中被证明。是否发布及发布后安排真机验证仍由用户决定。
