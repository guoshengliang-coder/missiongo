# 项目统计：交付效率与固定批次

## 开工至交付周期

起点是条目首次进入 `in_progress` 的时间，终点是首次进入 `pending_verification` 的时间。按首次交付时间归入统计期，每条只提供一个首次交付样本；验收打回后的再次交付不重置该周期。

这是自然耗时，包含首次开工后的暂停、排队和发布等待，不包含开工前排期或首次交付后的验收等待。缺少首次开工记录、起止顺序异常的条目计入缺失，不作为零时长。页面显示合并所有项目样本后的中位数；有效样本达到 10 条才显示 P90。

接口新增 `startToDeliveryCycle`、`started_to_delivery` 明细指标，以及明细的 `firstStartedAt`、`firstDeliveredAt`、`startToDeliveryHours`。原有 `developmentCycle` 为兼容旧调用方保留，Web 不再用它作为主要处理效率指标；`deliveryCycle` 仍表示创建至人工完成。

## 每周交付吞吐量

统计周按查询时区的周一至周日划分，Web 固定使用北京时间。统计该周内进入待验证的不同条目数，同周多次交付去重，跨周再次交付分别计入。它与首次交付周期的样本数含义不同。

`weeklyDeliveries` 返回完整周边界、实际查询边界、交付数及 `partial`。本周或被查询范围截断的周标记“未满周”。点击某周按该周与当前查询范围的交集查询 `pending_verification` 明细；不修改页面主筛选。跨周明细范围写入统计 URL，刷新或从条目返回后可恢复。

## 固定批次

用户在当前项目、类型、创建日期筛选下跨页选择条目并保存名称。保存后的成员不可追加或删减，不随统计日期变化。批次属于创建它的账号，其他账号不能读写；只需对应条目的查看权限，不修改条目业务字段或状态。每批最多 500 条，每个账号最多保存 50 批。可以删除批次记录，条目本身保留。

- 已交付：待验证、已完成。
- 处理中：处理中、开发完成。
- 暂停：暂停。
- 未开工：草稿、待处理。
- 取消单列；当前交付率 = 当前已交付数 /（原始成员数 − 当前取消数）。暂停与低优先级不会移出分母。
- 验收打回导致当前交付进度回退；历史周交付记录仍保留。

成员保存内部条目 ID，读取时重新检查当前项目可见范围。已删除、迁出或失去查看权限的成员计为不可用，原始数量保留，不泄露标题、编号或所属项目。存在不可用成员时交付百分比不展示，避免缩小分母后误报进度。

收到后第 7/14 天交付率分别重建每个条目创建后满 7/14 × 24 小时时的状态。到期前的条目列为“未满观察期”，截止当时已取消的条目单列并排除；缺少历史状态列为缺失。有不可用或历史缺失成员时不计算该百分比。后续打回或取消不会追溯改变已经观察到的历史状态。

账号 Cookie 接口（不接受无账号身份的运维 Bearer）：

| 操作 | 地址 | 输入 / 输出 |
| --- | --- | --- |
| 列出个人批次 | `GET /api/v1/project-insights/batches` | 批次 ID、名称、保存时间、固定成员数 |
| 创建固定批次 | `POST /api/v1/project-insights/batches` | 严格限定 `{name, itemKeys}`，逐条检查查看权限 |
| 读取批次进度 | `GET /api/v1/project-insights/batches/:id` | 当前分组、分母、交付率、7/14 天观察、可见成员 |
| 删除个人批次 | `DELETE /api/v1/project-insights/batches/:id` | 仅删除自己的批次，返回 204 |

批次不作为 MCP 写入能力开放。所有查询由服务器生成固定 SQL 并绑定值，不接受 SQL 或任意字段修改。

## 保持原有积压口径

当前积压仍为当前状态非 `done`、非 `cancelled` 的条目；期末及每日积压仍按历史状态重建。新增周期、周吞吐和批次进度均不改变这些计算。
