# AND-483 控制台事件推送

控制台从周期业务查询切换为单页共享 SSE；写接口、审批和命令幂等不变，节点程序自身轮询不改。源节点上传延迟不计入服务器收到变更后的推送目标。

## 共用实现和边界

- `ConsoleChanges`：事务内写入持久化 `console_changes`，单调版本配合持久化 epoch；提交后的微任务唤醒连接，回滚不推送。变更目录仅保存种类、账号/项目作用域、条目键和必要资源 ID，不保存正文、凭据或文件路径。
- 触发器在当前 Server 的 SQLite 连接中以 TEMP 形式安装，覆盖该连接所有 Store 的 HTTP、MCP、SDK、节点上传和后台写入；日志本身持久化。迁移先完成，再安装触发器，避免旧触发器阻挡后续表结构迁移。数据库外部写进程和多副本通知不在本轮支持范围内。
- `/api/v1/console/events`：仅控制台登录态（及既有无认证本机开发模式），每次提交批次重新验证账号和资源权限。账号私有会话、项目、协作源条目保持原读边界；账号失效、凭据过期和退出登录关闭旧连接。撤销协作时通过目标项目发出权限失效信号，不能因为源条目已不可读就漏清缓存。
- 首屏 bootstrap 在读取前提供 `consoleCursor`，订阅从该版本续读，关闭首屏读/建连窗口且不重复重建首屏；旧响应缺少游标时才做一次快照重建。游标为 `epoch:version`；补拉仅覆盖其后的变更。每页最多 500 行，保留最近 10,000 个变更；窗口外、未来游标或不同 epoch 返回 reset，按当前授权重建快照。数据本身仍走既有 REST；列表/计数重新读取受影响查询，不提供通用 JSON 数据差分。
- SSE 每 25 秒写注释保活，无数据库读取；背压超过有界缓冲则断开，由客户端补拉。日志清理由写入触发，不新增定时扫表。
- 节点在线/不稳定/离线、会话健康、派单启动、命令投递/停止和发布阶段有效期使用已知截止时间的一次性调度。相同快照、纯接收时间与心跳时间不触发周期全页读取。

## 前端覆盖

`useConsoleEvents`、资源到 Query Key 的映射及串行补偿共用于列表、详情时间线、控制台/条目内会话、派单与执行、待合并、协作、消息中心、方案记录、钉钉可见状态、节点设置和草稿节点选择。

长断线导致 recent 消息窗跨过已显示边界时，使用已有 stored 游标补齐缺口，直到找到已显示消息；不自动请求未知来源历史。产物等待移除周期请求，历史 pending 任务由 `QueryObserver` 等待 SSE 定向失效，保留一次追赶读取和有界超时。静态发布与版本检查改为初始化、前台恢复、连接建立/断开及已知有效期触发，不修改 Service Worker 或丢弃升级草稿保护。发布标记由 Server 外部写入，明确升级阶段保留到有效期为止的静态状态退避重试；一旦 idle/失败/过期即停止，静止正常页面不做周期状态探测，也不以此触发数据库查询。

前端只确认已成功刷新版本，失败保留变更并退避重试；新变更在读取期间到达会追加刷新。重复/乱序版本不重放；重连/恢复不执行写动作。未激活查询只标旧。权限失效清除不可读缓存，普通断线保留已加载内容与草稿；共用 `offline-banner`、`text-button` 及 i18n 文案说明连接失败和重试，不新增 CSS 豁免。

## 人工验证建议

1. 两个页面打开同一项目/条目，在一端新增评论、变更状态，另一端应及时更新并保留未发送内容。
2. 打开会话及待合并页面，核对新消息、权限/方案卡、交付变化；已加载历史、勾选和阅读位置不应因通知丢失。
3. 断网期间从另一页面产生变化，恢复网络后核对数据一致；不重复发送消息、不自动批准或重启会话。
4. 撤销项目或协作源条目读取权限，旧页面停止读取并清理不可读内容。
5. 在无业务变更的稳定连接下，网络面板不应出现周期性业务读请求；保活帧不代表业务查询。
