# 项目会话（AND-369）

Agent 控制台允许在项目下直接发起会话，不要求工作条目。桌面入口位于现有右上角工具栏；工具栏容器不足 620px 时归入已有更多菜单。配置继续使用派单表单的项目、设备、Agent、原生权限模式、模型及强度选择，不增加“讨论/处理”分类。

配置完成只打开本页内存中的草稿，复用现有会话区域。返回、切换项目、重新进入控制台保留文字和附件；未发送时没有服务端会话或节点执行。刷新或关闭页面会触发未保存输入保护。草稿不会跨账号沿用。

首次发送分为两个幂等步骤：

1. `POST /api/v1/project-conversations` 携带稳定 `requestKey`、配置、首条文本和附件数量，建立项目归属的启动记录及会话占位。空文本必须有附件；重复请求必须匹配相同内容。
2. 原有会话附件接口完成上传后，`POST /api/v1/project-conversations/:dispatchId/start` 原子绑定全部附件、排入首条消息，并开放节点领取。重复确认不会重复投递。

上传或确认失败时保留当前草稿及已上传附件编号，重试继续同一次提交。已经领取但结果未确认的启动不能自动重建；只有确定失败或取消且尚无真实原生会话时允许重试。重试保留会话 ID、首条命令和附件。停止仍在排队的启动会取消首条命令，随后可归档；归档记录不会被重试恢复。

节点必须上报 `supportsFreeSessions` 才能被配置和领取此类启动。macOS 和 Linux 节点使用本机固定的项目会话启动说明，随后通过原有会话命令接收用户首条消息；无需领取或创建工作条目。原生计划模式、权限审批与仓库规则仍生效。Linux 附件能力保持其原有声明，不因项目会话而扩大。

项目归属独立于条目，参与列表、未读计数、Widget、读取和执行授权。控制与节点投递都重新校验权限。无条目的会话不会因空条目集合而被判定完成或自动归档，也不会自动与条目会话合并。转条目及绑定条目不在本期范围内。

验证包括服务端幂等、附件完整性、失败重试、停止/归档与权限撤回；Web 在 375、768、1440px 下验证入口、草稿返回、发送失败恢复与启动重试；macOS/Linux 验证独立会话提示和旧派单兼容。正式启用需要发布 Web/Server 与支持此能力的节点客户端；本地构建不代表已发布。
