# AND-527：发送回执与原生消息身份关联

## 问题与证据

发送记录与 Codex 回传用户消息具有不同 ID。Codex 的输入参数
`clientUserMessageId` 在原生用户消息中以可选 `clientId` 返回；旧 macOS/Linux
解析器只保留原生 `id`，丢弃了客户端关联字段。服务端无法重建准确来源，
超过旧展示匹配窗口后会同时保留发送回执和原生消息。

已同步截图会话中，目标用户文字只出现一次；没有取得原始投递时间及原节点原始
`clientId`，不能把此缺陷等同于已经证明重复发送或执行。使用当前协议结构和
源码函数可复现字段丢失及双气泡，准确关联时只显示一条。

## 实现与边界

| 层 | 改动 | 边界 |
|---|---|---|
| macOS/Linux 解析 | 将原生 `clientId` 保留为可选 `clientMessageId` | 不改原生 `sourceId`、`turnId`、正文或来源时间 |
| macOS 上传与发送识别 | 上传裁剪保留关联字段；识别已收到的同命令输入 | 不改变发送预留、权限或未知送达保护 |
| Server 快照/历史 | 校验并持久化客户端身份，缺省旧字段不擦除原关联 | 同一来源的矛盾身份拒绝；历史补读仅补齐已存来源元数据 |
| 来源映射 | 同一会话、用户角色、非执行记录中按 ID 关联 | 客户端别名指向多个来源时不任选；不按文字或回合推断 |
| Web 两入口 | 在原生用户消息位置承接送达反馈 | 保留原文、原生时间、顺序、附件、阅读锚点和草稿 |

数据库迁移 `202611150551` 增加普通消息的可选 `client_message_id` 列，
以及普通/外部消息各自的会话与客户端身份索引。来源查询分支分别使用稳定来源
和客户端索引；列表批量映射与单条详情共用相同选择规则。

准确原生 ID 优先于旧版 `answer-<commandId>`，再使用唯一客户端别名。
旧数据缺少该字段时保持兼容；原有同文匹配只用于保守的展示降级，不能替代已知身份。
已知是另一命令的消息不能成为同文匹配候选。

原生历史页保留关联字段；如果相同原生来源已经存储，只补齐其身份元数据，
不插入额外正文、不重排历史、不刷新来源时间或推断执行完成。仅存历史页的消息仍
能在加载该页时通过准确别名承接回执。不扫描全库或强制回读全部原生历史。

## 共用组件与入口

- `replySourceState`、`agentChatMessages`、`withOutgoingReply` 和 `AgentReplyFeedback`。
- Agent 控制台、条目内 `AgentSessionPanel`、普通及外部原生会话、只读历史分页。
- 继续使用现有气泡、时间、消息菜单、附件与主题样式；没有新增样式豁免。
- 合并后的原生用户气泡继续显示“已送达”。旧 UI 断言“镜像到达后无回执”调整为
  “一个原生气泡承接一个回执”，原有唯一正文、顺序、阅读位置等断言保留。
