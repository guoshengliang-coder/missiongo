## 实现与保留边界

| 对象 | 变化 | 保留边界 |
|---|---|---|
| Server | 节点范围 `control-changes` 长轮询，最长 25 秒 | 节点鉴权、返回前撤权复验、每节点最多两个等待器；只返回游标提示，不领取或执行命令 |
| 通知来源 | TEMP 事务内提示、提交后集中唤醒 | 事务回滚不唤醒；正文与纯时钟更新不唤醒，真实空闲/等待输入转变会唤醒延后的控制 |
| macOS | 控制、镜像与停止分离；同会话单一控制所有者，跨会话限流 | 控制/镜像/停止各最多 4 个任务；同身份合并待处理更新；现有容量及受管所有权保持 |
| Linux | 同样的父节点调度；host 新增只读能力协商、`/observe` 与 `/control` | host 的控制副作用仍串行；原 `/sync` 保留；不为升级重启 CLI 或创建第二 host |
| 迟到结果 | 镜像代次及每会话上传排序；控制回执保留原观察代次 | 旧回执可以补确认命令、设置或归档结果，但不能恢复停止前的运行状态 |
| Linux 快照 | 成功指纹去重、失败重试、30 秒健康刷新 | 命令结果单独补报；健康观察不伪装成进展；心跳和派单结果恢复继续独立运行 |
| 适配器 | Codex/OpenCode 控制读取轻量运行元数据；Claude 控制上报仅带请求卡片 | 保留当前身份、回合、原生许可及设置校验；必要的不明投递核对仍保守执行 |

队列为按身份合并的 FIFO，不按 Agent 类型阻塞同类其他会话。停止不排在纯镜像读取之后。持久服务端预约仍先于本机输入，本机 journal 仍先于原生副作用；重复唤醒、旧列表和节点重启不会授权新一次发送。投递不明保持人工核实，不自动重发。

只读镜像保留来源存活判断：已停止 Claude 宿主不冒充在线、不写回或重启宿主；未加载的 Codex 外部会话仍可镜像历史，但报告运行时不可用。权限/表单卡片随独立观察继续同步；空闲 Codex 会话不会为审批观察隐式恢复。

没有新增持久数据库迁移、UI 样式或权限豁免。Linux 继续其既有派单会话支持，没有借本任务新增外部原生会话或受管执行接管能力。

## 新旧兼容与运行条件

| 组合 | 行为 |
|---|---|
| 新 Server / 新节点 | 启动协商后使用独立长轮询和控制队列 |
| 新 Server / 旧节点 | 原会话列表、快照和派单接口保持 |
| 旧 Server / 新节点 | 仅明确 404 回退原轮询；401/403 不当作旧版本 |
| 新父节点 / 旧 host | 只读能力探测明确缺失后回退 `/sync`；不重启存量宿主 |
| 控制请求响应不明 | 不改换入口重发副作用；沿原 journal 补确认或保留不明状态 |
| Server 重启或游标失效 | 重新读取当前持久工作；唤醒游标不是执行凭据 |

兼容回退不保证 500ms，旧 host 的串行 `/sync` 可能继续被慢读取拖住。启动时协商到旧 Server 的节点保持兼容模式，后续重启时重新协商；已启用独立通道的节点遇到 Server 滚动降级时使用原轮询节奏，不与镜像恢复混合副作用。

即时提示来自当前 Server 数据库连接的提交；外部进程直接写库等未被当前通知器捕获的变化，靠有限超时后重查恢复，不承诺此种写入的 500ms。当前生产部署版本在调查时与上述主线一致，但实际运行节点版本没有统一升级或逐台核验。

## 性能测量

在干净的上述源码提交独立运行 `node scripts/node-control-performance.mjs <仓库外输出文件>`。环境为 Node v22.23.2、darwin arm64、内存 SQLite、真实本机 HTTP；每种负载先预热 5 次，再采样 100 次，入队时刻分散在轮询等待注册前后。性能测量没有与本会话构建或测试并行执行。

计时从命令持久插入前开始，包含数据库提交、长轮询唤醒、鉴权后的节点会话 GET，直到取得该命令。不是模型响应、原生执行或全文镜像耗时，也不是公网 SLA。测试 HTTP 客户端模拟节点取命令，真实两端调度另由下表的夹具回归验证。

| 会话数 | P50 ms | P95 ms | 最大 ms |
|---|---|---|---|
| 1 | 3.397 | 6.019 | 11.316 |
| 10 | 4.594 | 8.324 | 22.629 |
| 50 | 4.946 | 10.057 | 16.604 |

三个负载均达到 P95 ≤ 500ms。原始样本及 `sourceDirty:false`、来源提交、计时边界保存在 `tests/performance/and-500-node-control-results.json`。未用 fake timer 的速度当作性能证据。

## 后续真机验证步骤

以下步骤只在另行获授权部署并升级测试节点后执行，使用可丢弃的测试会话，不操作用户正在处理的会话。

1. 核对测试 Server、macOS、Linux 版本与来源提交；确认新组合启用控制协议，旧组合仍可领取和同步。运行本机测量脚本复核计时边界，勿用模型首字或全文镜像时间替代取命令时间。
2. 同一 Agent 创建多个测试会话，让其中一个产生较长历史或执行长工具。在另一会话发送可识别的新输入，核对来源会话只收到一次、控制回执与后续正文一致；两个会话各自的设置、问题和输入顺序不串线。
3. 在目标会话执行长工具时发出停止，同时让另一会话继续读取历史。核对停止指向原 turn、结果以来源实际结束为准；释放旧镜像后状态不恢复为旧 active，新回合不受旧停止影响。
4. 模拟节点网络中断并重启父节点，保留原 CLI/host。核对仍关联原 sessionRef，已交付输入只补结果；无法确认的输入保持投递不明，未经人工判断不自动重发。再核对两端权限/表单回答、模型设置、历史和产物读取。
