# UI/UE 系统审计：从逐点修复到共同契约

审计日期：2026-10-31（Asia/Shanghai）。本报告是最新主线的代码、历史修复与隔离浏览器实测审计；不是全平台真机验收通过声明。

## 1. 结论与证据范围

**需要设计规范，但项目已经有规范。当前更缺的是让所有入口自动继承规范的组件和检查机制。** 再增加一份平行的 DESIGN.md 会增加漂移；应维护现有 `docs/design-system.md`，补齐交互契约、组件覆盖清单与交付门禁。

本轮发现 4 类可复现的产品问题，以及 3 类防复发机制缺口。建议先修浮层返回和焦点，再修极窄屏与字号，同时完善检测。保持现有中性背景、薄荷强调色、状态语义、紧凑工作区和各平台原生习惯，不需要全产品换肤。

后续实现与验证见 [2026-11 整改记录](ui-ue-remediation-2026-11.md)。本文保留审计时的证据与缺陷描述，不表示这些问题在整改分支上仍然存在，也不表示已发布。

## 3. 需要优先处理的产品问题

### UIA-01 / P1：返回没有统一遵循最上层交互

**高置信度，Chromium 实测。** 三种预览和一个子菜单没有完整接入同一返回契约：

| 复现 | 实际 | 应有行为 |
|---|---|---|
| 手机详情 → 滚动到附件 → 打开图片 → 浏览器返回 | 图片和详情一起关闭，URL 丢失 `item` | 只关图片，留在原详情和阅读位置 |
| 手机会话 → 点击条目编号打开预览 → 返回 | 预览和会话一起收起，回到会话列表 | 只关预览 |
| 手机会话 → 打开 Agent 文件预览（本次使用文件不存在状态）→ 返回 | 会话历史层已被退掉，文件浮层仍显示 | 先关文件预览，下一次返回才离开会话 |
| 设置 → 新建个人令牌 → 展开权限下拉 → 返回 | 下拉和无输入的表单同时关闭 | 先关下拉，保留表单；有草稿时也不应先触发表单放弃确认 |

证据：`App.tsx` 的 `MediaLightbox`（5289 起）、`agent-session-console.tsx` 的 `ItemPreviewModal`（1410 起）、`agent-artifact-viewer.tsx`（27 起）、`select.tsx`（121 起）；这些路径没有像 `Modal` 一样拥有完整的返回登记。`navigation.ts` 的深度计算列举了特定组件标记，新浮层不会自动获得返回行为。

Android 主 App 根据 Web 上报的深度执行返回，因此这些遗漏也构成原生返回风险；本轮没有在真机证明每一种表现。SDK 的 `MissionGoFeedbackActivity` 则直接调用 `confirmDiscard()`，需独立接入并验证，不能因为主 App 修好便宣布 SDK 已修。

整改：提供公共浮层生命周期/返回协调机制，让 Modal、Lightbox、文件预览、条目预览、菜单按层注册。页面“返回上一级”、浏览器历史返回和关闭浮层的语义需明确区分，但存在浮层时都先处理顶层。不要只再添加一个专用历史标记。

验收：上述每个入口分别验证关闭按钮、Esc、浏览器返回、Android 返回；覆盖子菜单叠表单、预览叠详情、有草稿、提交中、关闭后再次打开、前进/后退与宽窄屏切换。每次最多消费一层。

### UIA-02 / P1：条目预览的键盘焦点能操作背景

**高置信度，Chromium 实测。** 打开会话条目预览后，焦点仍在背景条目编号；按 Tab 后落到背景“归档”按钮，截图中可见遮罩下的焦点环。未执行归档操作。

`ItemPreviewModal` 使用 `div role="dialog" aria-modal="true"`，但没有初始焦点转移、背景 inert 或焦点约束。ARIA 声明本身不会产生模态行为。其内部媒体预览也是自建的 div。相对地，公共 `Modal` 使用 `showModal()` 并实现焦点恢复，值得保留。

整改：条目预览接入共享模态基础设施；文件预览已有部分 Tab 约束，应一起审查 iframe 内焦点、背景 inert 和关闭后的回焦。不要只补一个 `autoFocus`。

验收：打开后焦点在顶层；Tab/Shift+Tab 不能进入背景；关闭后回触发器；若触发器已卸载，回到稳定的页面标题或列表焦点。嵌套预览与 iframe 分别验证。

### UIA-03 / P2：320px + 大字号裁切详情工具栏

**高置信度，截图和几何测量。** 基准合成条目处于处理中，工具栏含“返回列表 / 标记开发完成 / 刷新 / 编辑 / 更多操作”。

- 320px、默认字号：“更多操作”边界为 x=275～319，虽能显示，但已侵占预期右留白。
- 320px、大字号：边界为 x≈290.02～334.02，约 14px 被裁掉；44px 宽的按钮实际上只露出约 30px。
- 同时 `documentElement.scrollWidth - innerWidth` 为 0；页面溢出检查仍然通过。

证据：`styles.css:1041` 的工具栏、`:1849` 的不可收缩动作组、`:1981` 的窄屏规则；[测量与截图](review-evidence/ui-ue-2026-10/README.md)。

整改：明确动作优先级，空间不足时把次要动作移入更多菜单，保留返回与主动作；不要缩小命中区域。按容器宽度和字体实际占用适配，避免为一个设备再叠加孤立断点。

验收：所有状态对应的主按钮文案、中英文、三档字号、320px 与窄列表/详情分栏均检查。控件完整落在可见容器内，同行外框对齐，裁切祖先不能隐蔽违规；不只断言页面无横向滚动。

### UIA-04 / P2：小字号选项突破自身规范下限

**高置信度，计算样式实测。** `--text-xs` 为 `11px × --text-scale`，小字号把比例设成 0.9，结果为 9.9px；12px 级别变成 10.8px。实测可见顶部计数为 9.9px。现有规范明确要求最小 11px，不能把提供“小字号”选项默认为该规则的豁免。

证据：`styles.css:104–111,139`、`font-scale.ts`；现有通用可读性矩阵没有系统参数化三档字号，部分大字号专项不能替代全局检查。

整改：字号令牌以 `max(11px, …)` 或逐档映射保护下限；保留用户字号偏好。若确实要例外，应明确哪些非正文元素允许、理由和验收范围，不能静默破坏现行规范。

验收：三档字号下检查实际可见文字，而非只检查 CSS 字面值；聊天独立字号也纳入。更大字号同时验证布局和按钮可达性。

## 4. 导致复发的系统缺口

### UIA-05 / P1：样式门禁存在新增文件和例外扩散盲点

**高置信度，实际运行和代码核对。** `npm run check:styles` 通过，报告 98 个已知违规出现位置、60 条基线签名。这不代表样式已完全符合规范。

1. `scripts/check-styles.mjs:33` 固定只读 `styles.css` 和 `sdk-feedback.css`。实际导入的 `managed-decision.css` 不受检查；将它交给同一个分析器，立即得到 25px 字号与 600px 断点违规（3 个出现位置、2 个不同签名）。
2. 非标准断点的基线签名由文件和断点构成，不含具体规则。已豁免的 640px 断点可以在同一文件的新组件中继续出现而不会成为新签名。
3. `compareToBaseline` 只比较当前源码与当前基线；CI 没有与 PR 基线版本比较“豁免是否增加”。文档要求“只减不增”，但修改基线并使用 `--update` 可以使新增豁免一起通过。

整改：自动发现产品样式入口/文件；每个豁免有稳定规则定位、范围、原因和清理项；在 PR 中比较基线的新增/扩张并阻止未经明确审查的增长。先修漏扫规则，不批量把新违规纳入基线。

### UIA-06 / P2：规范、实现和历史计划没有闭环

**高置信度，静态事实。** 规范仍标 v0.1/9 月草案；间距、层级、跨端导出仍列为待办。Web 主样式 3106 行、App 5372 行，多个页面靠选择器叠加和局部数值修补。体积不是缺陷本身，但修正的传播范围取决于人是否搜全。

跨端已有进步：macOS 有明暗自适应 `MenuPalette`；Android 有 `values-night`；公共 `BackButton`、`Modal`、`Select` 已存在。9 月历史报告中的“没有视觉回归”“Android 只有浅色”等不能再作为当前事实。`tests/ui/README.md` 仍写 4 档视口、允许 8 个小目标，实际是 5 档、允许 0 个。

整改：只维护一套规范，将“已实现事实 / 新增约束 / 待迁移例外”分开。优先收敛 `Overlay`、`PageHeader/Toolbar`、`FormActions`、`AsyncFeedback`，再分批提取间距和层级令牌。原生控件保留平台尺寸和行为，不强求三端逐像素相同。

### UIA-07 / P2：回归按页面和工单组织，共同交互没有覆盖登记

**高置信度，测试配置与复现对照。** 现有 CI 已运行 UI 实测和 Linux 截图，这是重要基础。通用截图矩阵是列表、详情、控制台 × 5 视口 × 2 主题；其他页面有不少专项，不能说“只测三个页面”。但仍存在以下缺口：

- 图库专项验证打开、左右切换和手势；文件专项验证预览、错误和下载，却没有共同的返回/焦点断言。
- 尺寸审计只知道页面水平溢出和元素外框大小，不确认控件是否被祖先裁切，也不测键盘焦点是否进入背景。
- Chromium 是当前 CI 唯一浏览器。Android 构建/单测和 Swift 单测/打包没有替代真机 UI 验收。
- PR 模板有尺寸和明暗截图要求，没有要求列出同类入口、退出矩阵和新例外。

整改：引入“组件 × 交互状态 × 宿主”覆盖表。新增入口要登记并运行通用契约；修某一类 bug 要列出其他入口的复查结果。对截图基线变更审查其交互含义，不以更新截图作为修复本身。

新增/修改界面的最小交付单元：**规则编号 → 共用实现 → 所有同类入口清单 → 回归证据 → 规范/例外更新**。每次复发记录漏在“规则、组件、覆盖还是发布版本”，避免只计修了多少问题。
