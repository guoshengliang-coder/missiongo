# 跨端核心内容可见性审计

## 证据与范围

基线为 d55a026b（审计时最新主线及线上 Web 1.1.41）。用户提供的 AND-459 同一会话截图及 11 条已同步源记录表明：正式摘要在 commentary，final_answer 只有等待提示。Codex 默认折叠过程，控制台展开同一源文本。前一轮只验证了消息保存和回放，不能证明原生默认界面核心内容可见。

审计覆盖 Skill、macOS/Node 派单及项目会话提示、MCP 准备/审批/通用审阅引导、双入口审批关联、Codex/Claude/OpenCode 适配、历史分页与现有测试。未扫描其他业务会话、未改写历史、未替其他会话批准。

## 发现与修复

| 对象 | 已核实缺口 | 修复 |
|---|---|---|
| 正式方案 | v2 允许过程展示后最终只写等待，造成默认可见内容缺失 | v3 强制最终答复包含原始摘要、边界及固定链接；误发过程时也须补齐 |
| 工具阶段 | prepare/request 指示先展示再登记，未区分 Web 登记与回合内原生确认 | Web 可先登记再最终展示；原生确认前保留审阅内容，未决状态最终仍自足，批准不重复 |
| 其他阶段 | 澄清、补修、交付、附件缺少统一的最终可见性要求（规范缺口，不冒充每项已有线上复现） | 未决选项、授权限制、补修变化、实际结果、验证缺口与产物链接不能只在过程、工具或卡片中 |
| 审批关联 | 最后一个含链接的过程消息可夺走正式答复的控件 | 优先当前文档的最终消息，兼容旧阶段；消息数组与正文不变 |
| 澄清选项 | Linux Codex 丢 description；两端 Claude 丢选项解释；两端 OpenCode 丢选项解释 | 适配层保留源说明；使用既有 detail 字段，选项原值及回答路由不变 |
| 授权资源 | Linux OpenCode 截断 4000 字符后仍可批准 | 支持既有 512000 字符 detail 上限内完整资源，超限明确缺口且界面/投递两层拒绝批准，仍可拒绝请求 |
| Codex 选项超限 | 新保留的描述必须遵守现有 4000 字符传输约束 | 超限标为不可确认，说明原生阅读入口，不静默截断后放行 |

## 保留与边界

历史分页保留源阶段并报告不完整；未发现本次需要改变它的证据。业务评论/执行活动与源消息不混为原生正文。既有权限请求若无法完整展示仍遵守拒绝或原生处理边界；不扩大授权、修改模式或伪造用户决定。客户端折叠样式不能由 MissionGo 强制统一，不能承诺所有进度像素一致。提示规范也不是模型绝对遵从保证。

本轮没有重新设计前端摘要、去重、过滤或阶段搬移。审批绑定变化只定位控件，不改写文字。未迁移或补写 AND-459 已有历史。

## 验证

- 全量 npm run check；macOS 定向测试覆盖三类客户端的派单/项目会话、选项说明与原回答路由。
- Node 测试覆盖原始选项描述、原值回答、超过 4000 字符的资源尾部，以及超过 512000 字符时拒绝批准。
- Web 单测与双入口浏览器回归覆盖正式消息之后再次出现过程链接、同版本审批定位、文档修订、同步延迟和历史兼容。
- 实际 Codex/Claude Code/OpenCode 使用纯虚构野餐选择题，均返回选项、取舍、推荐、问题及链接；OpenCode 还追加了运行约束，不能据此宣称各端输出完全相同。该测试只证明无敏感样例的生成结果，不等于已完成真实业务的原生桌面默认界面与生产批准往返。
- 验收必须在实际客户端回合结束后，不展开过程，确认正式方案及待决内容可见，再与控制台逐字核对固定摘要与文档版本。不能仅凭消息数量或底层同步宣布通过。
