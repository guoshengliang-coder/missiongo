# 原会话合并与发布

原会话里的明确执行指令直接交给仓库托管平台和项目已有发布入口。由 Agent 核对当前会话目标，使用正常的 GitHub 合并方式和精确 PR head。CI 失败报告检查项、关键错误和运行链接。同一 PR、提交和版本的续办或 CI 重跑沿用原指令。只有目标确有歧义时才澄清。操作人明确停止时停止。仅发布不授权新合并。

MissionGo 在操作后登记实际结果。有条目时沿用已有开发完成与发布交接工具。无条目时在原会话记录实际 PR、合并提交和发布回执，已有独立交付可追加发布证据。项目正式发布入口如需候选数据，向它提供实际清单，遵守该入口的规则。无法回写时单独报告登记缺口，避免重做 Git 或生产操作。

新原会话执行无需准备快照、绑定聊天消息、创建 MissionGo 批次、重新批准或打开确认页。待集成仍是操作人选择清单和专门集成会话的独立入口。

## 核对一次实际执行

原会话中的 PR 和计划发布版本已明确时，操作人发出一次「合并和发布」即可。以 GitHub 的合并记录确认合并提交，以正式发布回执和公网版本确认这次部署，再核实 MissionGo 已登记结果。无关联条目时，原会话保留 PR 链接、合并提交、公开版本以及发布回执依据。有条目时，另回读实际交接状态。若某一步失败，报告失败的步骤和已有结果，沿用同一指令继续可恢复的步骤。

## 兼容已有批次

以下记录和恢复语义仅用于待集成和发布新版前已经启动的原会话批次。旧准备和启动接口只接受已有批次恢复或已受理请求重放，其他调用返回 `conversation_integration_use_platform`，提示使用直接入口。

## 门禁的职责

待集成控制台批次与原会话直接批次均使用服务端已保存的授权与原身份。已有授权、当前主线、通用工具状态和冻结候选不需要在批次前置表中再填一次。旧记录保留供审计，重复事实不会阻塞。真实跨交付依赖及项目专用前置条件仍按阶段处理。

合并仅使用当前精确提交、GitHub 检查及项目要求的验证。已发生的合并按精确提交登记，发布范围或前置快照失效时仍可登记 Git 事实。实际发布保留最终目标验证、完整覆盖、明确发布要求与回执核验；只有发布阶段会因这些发布条件而阻塞。

## 旧版准备与绑定记录

`prepare_conversation_integration` 只持久化受限快照。原 `identity` 只选派单 `dispatchId` 或已验证外部原生 `sessionId`。`scope` 包含产品、仓库、operation、新合并 deliveries 或已合并 selection。没有清单记录的历史条目发布允许空选择，不制造交付或工作条目。已有项目批次不抢占。

准备不创建交付提议、不确认清单、不执行 Git 或部署。新交付在 start 的事务内登记并绑定批次，失败连同状态、占用和投影一起回滚。配置来自原会话真实节点和已应用的模型、模式、effort，不接收另一设备或权限配置。

`start_conversation_integration` 只接收原 identity 和 preparationId。来源是服务端接受且已送达的人类命令，或原节点同步且带原始时钟的当前原生用户消息；不接收 Agent 自述 approved、quote 或历史。原命令和其已核实的原生镜像使用相同来源，重复同步不撤销授权。队列中、投递未知、停止、归档、撤权、旧来源或有歧义的指令不能授权新操作。

明确的“继续合并”“继续发布”“继续合并和发布”与对应动作匹配时可作为当前执行指令；该入口只接受完整动作指令（可带 PR 编号及句末标点），附带汇报或条件的消息拒绝；纯“继续”不授权新批次。否定、疑问、引用、条件、未来计划和完成汇报仍拒绝，已有批次的继续恢复沿用原协议。

指令语义仍由 Agent 理解；服务端的保守反例过滤不自动执行，不证明能理解全部自然语言。合并引用需在当前指令、紧邻的完成汇报或可核验的同范围审阅记录中有 PR 或提交依据，不允许把无关 PR 加入范围。未展示范围时先在原会话补齐。发布须完整展示准备返回的候选和范围摘要；已审阅且未变的决定不重复索取。不能只展示摘要标识却隐去候选或额外影响。真实 Git、来源提交和公开产物继续由执行端独立核实。

准备十分钟内可启动；源上下文、设置、交付内容和发布范围变化须重新核实。明确执行指令只授权它所指的动作，不能继承旧发布开关。仅发布禁止新增 Git 合并。服务端仅复用同一账号对完全匹配的历史缺证记录已有的人工确认；新增或变化的历史缺证需走既有受限处置流程。

## 固定范围确认与重试

完整展示范围后，已有原会话的可信同范围决定继续有效。缺少可绑定决定时，用准备工具返回的范围确认入口保存一次人工决定。该入口核对已认证账号、原会话执行身份、确认时的人类输入及精确范围摘要，保存确认本身不会开始集成、发送消息或创建会话。后续同范围刷新可以使用这一记录，准备快照时效与人工决定分开。项目产物的精确标识优先于别名，命中后仍须核对实际发布范围及版本。

对于明确重试，服务端沿原会话核对之前的同范围授权。无已建批次且只有历史文本作为证据时，仍需完整、可信的范围展示与明确指令；缺证继续阻断。已绑定批次使用原批次恢复。原设置、操作范围变化，停止、撤权及未知外部执行结果仍由对应门禁处理。

## 跨轮范围审阅

范围展示和执行授权分别核验。服务端从原执行身份的节点认证消息中定位当前指令之前最近一份带“原会话执行范围”的最终答复；普通进度或建单结果不会遮住该范围。正文须包含准备返回的完整 reviewText，且只有一份范围；来源消息与原始时钟须一致。较新的不同范围、多范围歧义、缺时钟或截断不得跳过回找更早的有利记录。

成功绑定时，原 preparation 的 JSON 保存 reviewEvidence：来源 ID、原始时间、正文摘要、稳定 reviewDigest、执行身份 binding、settings 及当前人类指令来源。账号、客户端、仓库、精确提交、候选、产物和实际执行配置继续由 preparation、完整正文及原身份共同绑定，无新增调用参数或 Agent 自述批准入口。旧记录可由原会话已有可信消息严格补证；不能补证就保留具体缺口。数据库重开仍可从这些持久记录核验，不扫描其他会话。

首次启动仍要求当前明确、与动作匹配的执行指令；独立“同意／批准”仅沿原来唯一待决范围规则处理，不能因中间无关答复而把普通批准解释成执行。未启动批次的纯继续或状态查询不能创建批次。当前指令中的完整 PR/提交 URL、简写编号及裸 SHA 按真实交付核对；URL 内的仓库名不作为裸 SHA。当前指令一旦明确点名目标，须无歧义地覆盖全部将执行的交付及额外发布候选，部分选择应刷新匹配范围，不能扩大成整批执行。当前含排除、缩范围、未解析的产物/分支等限定时拒绝旧完整范围；排除对象不计为正向授权，简单动作与精确引用、动作本身的“仅合并，不发布”仍可使用。中间停止、中断、范围变化、不同 PR 或含糊输入阻断旧审阅复用；明确状态查询及范围外建单输入允许保留审阅事实。已启动批次继续沿原 resumeBatchId 协议恢复。

新准备快照仍有十分钟时效；只刷新实时检查不改变稳定审阅范围，实质变化仍重新核验。审阅记录不代表 Git、CI 或生产已经验证，不绕过项目互斥、历史缺证、实时检查和正式发布覆盖门禁。此路径不发原生输入、不启动 Agent、不自动执行 Git 或部署。

## 身份与恢复

批次的 conversation.executor 使用 dispatch/external 联合身份；外部会话不伪造 dispatch。MCP 读取、集成、结果上报、收尾、无需发布交接及恢复均核对原账号、客户端和会话。旧记录没有 conversation 字段，继续使用原派单语义。

原生身份绑定与执行设置分别保存。设置变化阻止新操作，但不把同一真实会话变成另一执行者；设置已应用后，可以在原会话完整展示新配置与同范围，再消费明确执行指令恢复，追加配置决定记录，保留最初授权。服务端不更改模型、权限或供应商。

同一 preparationId 的重试返回已接受的原批次，不运行 Git、不再次创建会话。新人类输入先阻断新动作；已发生的外部合并仍可如实上报，后续交接缺口单独保留。明确继续或状态询问且范围未变时，prepare 使用 resumeBatchId 和空 deliveries/selection，然后 start 复用原批次；不重批、不重复授权。停止或变更不能当成普通继续。发布结果未知不重部署、不超时释放项目占用。

原批次的对账、外部合并接纳、部分发布与恢复依旧需要原有精确决定。支持 Web 或原生决定的既有入口保留；不能用新入口接管其他批次。

记录恢复决定与执行恢复分开核验。批准本身不使同范围快照失效；Web 批准命令尚未送达时不能执行，送达后仅允许与该决定来源完全相同的当前批准继续，后续停止仍阻断。普通同范围继续保留集成 revision，配置变化则使旧检查和恢复快照失效。外部原生会话尚无完整历史证明，聊天决定恢复明确返回 history_incomplete；可信原生确认仍可使用，已有有效决定不重复申请。

状态查询快捷恢复核查原绑定输入及中间用户消息、停止按钮指令；中间停止或范围修改不能被后续状态查询抹去。缺少原输入或有效消息时钟时保留缺证，新的明确执行指令仍按原动作和范围核验。原生时间区间与先前审阅上下文按实际时间比较，兼容合法 ISO 时区和毫秒格式。

## 展示与兼容

复用 IntegrationDetails、IntegrationProgress、SessionDeliveryNotice、MergeReconciliation、DeliveryCards 及公共浮层，不增加控件皮肤或样式豁免。控制台、条目内会话与项目会话共用实际 batch.sessionId。直接执行不把原开发会话永久改名为专门集成会话；清单入口仍创建专门集成会话。

仅历史候选发布没有新合并组，显示“仅发布”和既有集成核验说明，候选在发布责任区显示；不显示等待新合并。清单计数和活动占用沿用同一投影，正式发布候选不受待办资格过滤。

能力由 supportsConversationIntegration 和 writeTools 声明。旧节点缺可信身份、当前来源或原始时钟时，说明具体缺口；待集成作为可选兼容方式，不能宣称唯一入口。原生客户端使用新 Skill 必须重新读取当前文本；本地文件更新不代表旧上下文自动更新。全机安装、生产发布与业务验收各有独立授权。
