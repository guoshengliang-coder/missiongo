## 新契约

`completion.kind=local_change` 保存版本1、目标环境、摘要、1–32个安全相对资源名、前后 SHA-256、结果字节数、回退方式与验证记录。新增/删除的一侧为 null，至少有一侧存在且摘要不同；删除的结果字节数为0。不读取文件名指向的本机文件，不执行命令，不授予其他设备写权限。实际文件与运行效果由执行端核实，服务端验证结构和授权，计算规范化证据摘要。

本机依据只能用于 `requiredArtifacts=[]` 且有明确 `noReleaseReason` 的开发完成记录。Git 类型仍须独立核实集成；正式发布路径不接受本机依据替代 Git 与发布凭据。

`get_item_context.developmentEvidence` 提供当前开发事件、轮次、修订号、完成依据、摘要及发布范围。`submit_non_release_for_verification` 必须原样绑定这些字段，附实际检查、待人工验证和已知限制。相同键不同内容拒绝，同内容重试不重复写入；旧重试不恢复人工打回。

普通调用使用原领取身份。合并集成者仅可使用原合并派单及精确活动批次/delivery和当前集成修订，交接本批已登记合并、相同 PR、范围未变化的条目；不领取源条目、不跨批处理。结束批次后不接受此路径。

验证记录允许保留 passed、failed、not_run 的实际结果，不把它们升级成人工验收。已知未达标且仍需开发时不擅自交付；用户明确选择先交当前结果审阅时，仍须披露该决定和限制。`done` 仍只能人工操作。
