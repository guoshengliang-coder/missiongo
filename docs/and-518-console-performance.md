# AND-518 控制台持续性能测量

## 范围与口径

Web/Server、macOS 与 Linux 节点增加去内容性能观测，不改原发送、预留、幂等、审批、停止或SSE业务读取策略。共用 domain 白名单、页面持有的 SessionSender、两处会话的渲染观察和 QueryClient 只读观察器；没有新增可视样式、浮层或样式豁免。

| 对象 | 观测 | 边界 |
|---|---|---|
| 发送 | 逻辑启动、每次HTTP尝试、prepare/upload/submit/start | 同键恢复不增加逻辑启动；用户主动再发使用新键 |
| 服务端 | HTTP处理、接受命令、节点预留回执、相关回合首输出快照 | 全部区间由当前进程的单调时钟测量；重启不能恢复旧计时原点 |
| 节点／宿主 | 当前命令投递、确切回合首输出 | Linux新Codex回合及Claude命令UUID可直接绑定；macOS Codex须有此前观察及命令ID用户回显的新回合，Claude须有同一命令UUID回显；steer、缺少基线及OpenCode无可靠绑定时明确uncorrelated |
| 页面 | 当前命令首条回复的下一绘制机会 | 近似可见时间，非物理屏幕精度；旧消息和其他回合不触发 |
| 返回／恢复 | 列表及详情的缓存可见、新读取可见 | 无缓存、隐藏、取消、失败、30秒未完成分别记录；不新增业务读取或重试 |

`send_started`、`logical_accepted`、`http_attempt`分别来自客户端逻辑动作、服务端接受和HTTP尝试，分母不同，不相加。节点投递成功不表示模型已执行。Agent首输出包括客户端／宿主、提供方和模型等待，不称为纯模型耗时。不直接相减不同设备或进程的时钟，不相加重叠区间。

阶段、结果、Agent、发送类型是有限枚举；版本来自Web编译提交、Server发布提交及节点版本。旧Web不产生客户端样本；旧节点或无法关联回合不能填0。生产与合成环境在服务端固定区分，不能靠客户端参数把测试数据改为生产。

## 采集与隐私

- Web与节点使用独立有限上传队列（256批／项，Web每批最多32事件、请求最多32KiB，最多3次尝试）；异步上报不等待指标落盘才结束业务。Web清理账号草稿同时使在途旧观测失效。
- Server请求路径只校验并入列，最多2048个待确认事件。专用Worker持有独立SQLite；不在业务库提交路径新增指标写入。初始化、磁盘满、线程退出／5秒无确认、队列满均不改变已提交业务结果；故障报告明确不完整。
- 指标仅含阶段、结果、非负有界时长、有限维度和必要账号／产品隔离键；不保存正文、附件字节、原始URL／查询参数、凭据、路径或原生会话引用。事件ID与操作关联ID落盘前使用SHA-256转换，不导出关联明细。
- 这属于受权限保护的去内容聚合，不能声称完全不可关联的匿名化。暂存原生回合引用只在有界进程内用于关联和已授权详情响应。
- 读取只返回当前账号指标；多产品会话要求仍能读取整组产品；无产品外部会话保持账号私有。撤权后过滤旧聚合；不向其他账号输出全局使用／丢弃计数。节点上报校验账号、实际绑定节点、命令归属和外部绑定generation。
- Web与节点上报均限每身份每分钟120批；全局限流表也有上限。接收接口限制阶段来源，客户端不能写入服务端接受数；只读报告不授予发送或执行权限。

## 保留、容量与故障

5分钟聚合桶保留滚动7天，分钟级服务器采集存活覆盖另存。短期去重和未结算关联最多10000条、24小时；样本及健康计数各最多30000行。高基数与容量拒绝明确计入采集缺口，不静默挤掉有效基线。

独立数据库预算64MiB：SQLite主文件最大页数限制为预算的75%，保留WAL／SHM余量，WAL按128页自动检查点且每批TRUNCATE，临时处理在有界内存中。启动和每批清理过期数据；磁盘写失败熔断，不无限重试。关闭最多等待1秒排空；仍在途或进程崩溃的事件可能丢失。已持久的未结算Server关联在新进程记process_restart，不续接旧单调时钟。

采集健康计数按账号／产品作用域持久化。报告分别给出Worker接收到的事件尝试分子／分母、重复、持久接受、容量丢弃，以及当前Server进程观察到的上游拒绝。浏览器关闭、断电及队列完全丢失无法全知，不能据局部健康计数声称全链路零丢失。

## 配置与读取

正式服务入口默认启用，`MISSIONGO_PERFORMANCE=0`可停采，Compose显式传入；数据文件为主数据库同目录的独立`.performance`文件。直接嵌入buildApp的测试／工具默认关闭，可通过performance选项启用，不影响测试合成数据与业务基线隔离。无需业务数据库迁移。

- `POST /api/v1/console/performance`：当前浏览器登录态；使用受授权的sessionId或productId，最多32个白名单事件。
- `POST /api/v1/node/agent-sessions/:sessionId/performance`：当前节点凭据；命令及外部generation校验。
- `GET /api/v1/console/performance`：当前账号只读聚合，最多7天，支持from/to毫秒时间与productId；不支持任意SQL。默认截止上一个完整5分钟桶，窗口24小时。非对齐窗口明确含边界桶近似。
- 授权取得JSON后：`node scripts/console-performance-report.mjs authorized-report.json report.md`。工具只读取指定报告，不读取账号凭据或自动访问生产。

报告按相同产品作用域、来源、版本、Agent、发送类型、阶段、结果合并直方图；给出样本与计时数量、近似中位/P95上界、范围、实际覆盖、空档、业务桶、待结算和缺失。低于100个同口径计时样本不显示P95；达到100也不自动断言统计稳定。服务器有存活心跳但无业务样本，与采集故障不同；心跳不证明节点及浏览器都在线。

`coverageComplete`仅表示5分钟对齐的固定24小时窗口具备连续Server分钟覆盖；`complete`不自动变为验收通过。实际生产基线仍须核对客户端／节点版本及缺失、真实弱网／前后台场景，再由人工审阅，不用合成测试补齐缺失生产时段。
