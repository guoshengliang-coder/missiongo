# Agent 会话停止协议

“停止当前回合”保留会话与历史。停止确认后，用户可以主动发送下一条消息；旧停止请求不能用于新回合。工作条目状态不随停止变化。

## 服务端与节点

- 排队派单的取消与 claim-next 在事务内串行化。Mac 已取走的派单立即保存停止意图；还没有原生 ID 时用 pending 会话承载。
- 节点在调用适配器前请求 `POST /api/v1/node/dispatches/:id/permit-start`。停止先到则取消派单；检查之后到达的停止由启动回执绑定首个原生输入并继续交付。
- 启动回执携带 `initialTurnId`：Codex 为 turn/start 的返回 ID，Claude 为首条原生用户消息 UUID，OpenCode 为首条原生用户输入 ID。没有标识时保持未确认，不猜测后续回合。
- interrupt 与 message 各有独立的在途槽。节点优先拉取停止；新的普通输入预留会重新检查停止屏障。原消息的交付不确定记录不能冒充已送达。
- `delivered` 仍表示命令已交付。只有新节点独立确认前台回合结束、并报告 `stopConfirmed=true` 与 `turnActive=false`，才显示“当前回合已停止”并释放停止前的旧输入槽。旧节点应答显示为“停止请求已送达，节点尚未确认回合结束”。
- 停止异常以 failed/停止未确认收口，有人工重试出口，不进入仅适用于普通消息的 delivery_unknown 确认流程。迁移将历史未知停止转为未确认失败。

## 原生适配器

- Codex 使用精确 turn ID，中断独立于完整历史读取；通过不包含历史的状态读取确认结束。持久化停止尝试记录，节点重启只重新观察，不自动重放。
- Claude 宿主命令携带原生输入 UUID，在写 CLI 前核对目标并持久化 delivering；重复文件、轮询和迟到应答不重复发送。ACK 不等于结束，须等原生 result；等待授权也可停止，结束时撤下旧授权请求，后续消息进入新回合。宿主未回报结果时有超时出口。
- OpenCode 不先读取完整历史或待授权列表；使用 active 状态与至多 100 条消息的尾页识别原生用户输入，停止前再次核对。无法识别目标时不发中断；接口应答后重新观察，未空闲则显示未确认。停止尝试有持久化去重。
- Claude 与 OpenCode 的上游中断按会话执行，未提供本仓库已验证的原子 compare-and-stop；宿主串行处理与目标检查保护延迟请求及 MissionGo 管理的输入顺序，但不能宣称消除了外部客户端在检查与调用之间插入新输入的竞争。OpenCode 尾页中没有目标输入、来源不可读或无法确认时，保留未确认并要求核实，不扩大目标。
- Linux 节点保留宿主的持久命令日志，停止采用相同的精确目标、独立确认与未确认失败语义。

前台停止不代表已撤销工具副作用或所有后台进程结束。Claude 仍有后台活动时单独显示“前台回合已停止，仍有后台任务运行”；其他未知子进程不得被当作已确认退出。

## 验证与交付

自动化覆盖：启动前取消、启动回执绑定、回复交付中/未知、授权等待、停止结果丢失、节点重启、目标变化、未确认恢复、后台提示与原会话续聊。Claude 宿主集成测试启动的是本地模拟 CLI，验证真实宿主进程的协议行为，不是模型真机验证。

浏览器复用 `AgentStopFeedback`，覆盖控制台与条目内会话面板。停止状态与普通消息状态分别保留。测试见 `and-391-stop-lifecycle.audit.spec.ts`、`agent-stop-feedback.test.tsx`，以及服务端和 Swift/节点回归。

完整交付需要 Web/Server、macOS 与 Linux 节点制品。部署不等于用户设备已更新；真实 Agent、第三方网关和后台子进程仍需在对应新客户端验证。不要用旧客户端测试结果判断新协议已生效。
