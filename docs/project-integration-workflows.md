# 按项目现有流程集成与发布

本次改动取消把 MissionGo 专用 CI、自动合并设置和发布工具作为所有项目统一前提。默认读取当前仓库的现有可信规则，执行端记录实际能力与验证结果；项目无需新增必填配置文件。

## 行为与边界

| 对象 | 变化 | 边界 |
|---|---|---|
| 合并 | 支持直接合并、受保护的 auto-merge、squash/rebase/队列 | 不修改仓库设置，不绕过分支保护，绑定精确 head/base |
| 验证 | `not_applicable` 独立于通过、等待、失败和未知 | 无 CI 需完整规则和平台取证，读取失败或预期检查缺失不能冒充无 CI |
| 本地测试 | 允许有证据的无需自动测试 | 不强迫新建测试系统，实际验证与剩余覆盖如实保留 |
| 发布 | 采用项目自己的预检、构建、版本和分发入口 | MissionGo 自身仍保留现行工具、完整候选和发布门禁 |
| 前置要求 | 合并与发布分别判断并展示 | 未使用的工具不要求安装摘要，实际发布条件仍阻止发布 |
| 原批次 | 原身份、原授权、原修复与合并事实继续使用 | 显式追加适配证据和历史，不重建批次、不重复操作或索批 |

本轮保留 GitHub PR 的待集成入口，不新增 GitLab、本地无 PR 等其他集成入口。没有操作 Hermes GO 的原 PR、设置或集成批次；没有执行推送、远程合并、生产发布或人工验收。

## 共同判定与执行取证

`ProjectVerification` 保存仓库、目标分支、规则来源及摘要、CI/本地检查适用性、平台读取完整性、必需/已观察检查、合并能力和方式。证据由外层 head/base/checkedAt 绑定，服务端验证身份、一致性与时效，真实外部事实仍由授权执行端采集。

交付提议、刷新、批次 check、合并报告与外部恢复使用共同判定。`not_applicable` 不能只传一个豁免标志，必须有对应项目规则和完整依据；实际失败和未知不会转为成功。

`merge-delivery.mjs` 接受执行端从既有规则读到的 `projectRules`，并进一步只读核对仓库能力、分支保护和 active ruleset。项目自己要求的检查不等于受平台保护；只有保护覆盖所需检查时才生成 pending auto-merge 参数，否则先等待实际结果再直接合并。脚本不执行合并，不创建或修改配置。

squash/rebase 使用实际 PR 最终 head、MERGED 状态及目标分支包含真实落地提交来核验，不强求原 PR head 是目标祖先。外部恢复继续证明原批准 head 包含在实际 PR head，保留源提交范围约束。新版恢复对本地验证结果也如实区分，不在无本地自动测试时伪造 passed。

## 阶段与兼容

自有发布流程可以在前置取证中声明 `workflow.tools=project_native`，它是当前已有流程的证据，不是新增项目配置。仓库列表必须精确覆盖当前批次，规则来源和摘要变化使关联旧事实失效。

合并前保留主线、原授权和范围事实。项目实际工具、签名或发布凭据可列为 `pre_publish`，与代码合并分开；发布前重新检查通用必要事实和本阶段条件。原工具流程使用 `missiongo` 时保留现有完整性与能力要求。

原批次读取返回 `projectWorkflowInstructions`、`prerequisiteObservation` 和独立的 `publicationPrerequisiteGate`。新启动与原批次读取使用同一通用说明；不会改写历史首条消息。旧工具条件须显式更新适用性并保存原因和历史，未解除循环不能借换流程清除。幂等、原授权、未知操作与人工决定范围保持。

候选协议 v2 属于 MissionGo 的读取和交接记录，由执行端适配，不要求各项目发布工具实现该协议。发布成功与自动交接成功分别记录，不因缺少交接工具改写已合并事实，也不假报完整上线。

新字段由 `supportsProjectIntegrationWorkflows` 宣告。未升级执行端继续保持原状态语义，历史 unknown 不自动升级成无需检查；当前会话需要显式重读规则。旧 Web 页面需要加载新版资源才能展示新增状态，不把旧客户端显示当作已支持。Skill 已升为 5.77.0，版本与内容摘要契约同步更新；未安装到其他节点。

## 共用界面与附带修复

复用 `MergeDialog`、交付详情与 `IntegrationProgress`/`IntegrationDetails`，没有新增配置页面、浮层、控件皮肤或样式豁免。无 CI 与未知分别显示，技术依据保留适用性原因、规则来源和检查时间。合并前与发布前的实际阻碍沿用同一提示容器。

浏览器回归暴露了技术依据中原生 `small` 在小字号下缩至 10.5px 的问题；已统一接入已有 `integration-note` 字号令牌，适用于同一阅读面的元信息。规则来源与检查时间分行，避免相邻文字粘连。

覆盖入口：待集成弹窗中的交付与集成阅读、原集成会话右上角详情、同一批次的恢复与技术依据。返回、焦点和聊天草稿继续使用现有共享机制。

接口权限依据：[Get a branch](https://docs.github.com/en/rest/branches/branches#get-a-branch) 使用 Contents 读取权限并提供保护摘要；[Get rules for a branch](https://docs.github.com/en/rest/repos/rules#get-rules-for-a-branch) 使用 Metadata 读取权限。取证组合这两类信息，不调用要求 Administration 读取权限的完整分支保护端点；规则读取失败仍不能解释为没有 CI。
