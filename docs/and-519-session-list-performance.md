## 行为与边界

| 对象 | 变化 | 边界 |
|---|---|---|
| 列表方案状态 | 批量读取状态与来源位置，单次请求复用条目版本、交接／终态边界和返工轮次 | 不传输完整方案／文档正文；当前批准、来源权限、原生来源、新输入及归档语义保持；正式批准与详情仍独立校验 |
| 产品权限 | 同一请求按产品和能力复用检查 | 每个新请求实时核验；完整成员组需全部可读；无跨账号或跨请求结果缓存 |
| 列表事件 | 同 key 使用 100ms 固定窗口，持续事件不延长窗口 | 在途新事件仍需补读，失败退避及游标确认保持；详情与待集成独立调度 |
| 返回控制台 | 不再在关闭时无条件刷新；返回时先显示有效内存缓存 | 失效或超过 60 秒时后台校验；不增加磁盘持久化，不承诺刷新或重启恢复列表 |

共用实现为 `ImplementationPlans.listStates`、`PlanApprovalService.withAttentionForSessions`、现有 `AgentConsoleSessions`、`consoleRefresh` 与 `useConsoleEvents`。覆盖全产品列表与徽章、控制台返回、两处会话的共享事件机制；批次创建后的目标会话定位读保持。没有新增视觉组件、样式或样式豁免。

服务端没有分页、截短列表或改变镜像关联，没有重写发送、审批或停止协议。跨项目成员组权限、节点歧义、账号隔离和来源记录保留。人工验收、条目阶段与执行记录保持独立。

## 同负载前后对照

使用同一份 `scripts/session-list-performance.mjs` 对两个来源运行：基线从上述 Git 提交提取到隔离目录后编译，实现来自干净 checkout。两端共享相同外部依赖版本，contracts/domain 源码未改动；每份报告保留来源提交、四个服务端改动文件的 SHA-256 摘要、环境、形态及原始样本。第二轮反转前后运行顺序；所有请求串行测量批次，不同时运行本会话构建或测试。

运行环境为 Node v22.23.2、darwin arm64、内存 SQLite；客户端为已认证的 Fastify inject，不包含真实网络、WebView 渲染或节点传输。每轮每种形态，单请求取 100 个热样本，四并发取 100 批共 400 个样本。四并发耗时是每个请求含本机事件循环排队的延迟，不是单核独立计算耗时。

公共形态：200 个派单会话，目标 10000 条历史、其他各 20 条，每条 1024 字节。普通与派单待审批各带 40 个外部镜像；外部待审批带 200 个镜像，合并后均为 200 个会话。待审批形态额外有 200 份固定方案文档，每份约 40KB；普通形态无这些方案。各形态只与自己的前后版本比较，不能跨形态比较绝对数值。

### 未达目标及生产缺口

- 普通形态没有待审批查询放大，SQL 数保持不变；本次批量方案优化对此形态没有主要作用。单请求中位改善为 -10.6%／+4.7%，四并发为 -1.7%／-2.7%；P95 同样有波动。此处明确保留普通路径的目标未达和轻微回退，不以合并平均值掩盖。
- 外部待审批单请求第二轮 P95 改善 26.9%，未达 30% 下限；其他待审批热路径的 P95 改善 47.5%～62.0%。本机内存库、JIT／GC、进程与排队噪声影响尾延迟；这些是可能影响，不能当作已证明的单一原因。
- 需求记录的生产中位 391.55ms、P95 455.65ms 及原始分段样本未在本次取得。未核实生产中待审批会话比例，不能把上述比例套到生产，也不能承诺消除数秒等待。
- 持续采集及端到端价值复盘依赖 AND-518 的基线和后续获准发布。该条正文不在本次读取范围，未推断它已完成或已上线。本轮没有读取真实生产库副本、压测线上或变更生产采集配置。
