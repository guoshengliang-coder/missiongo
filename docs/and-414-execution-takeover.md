# AND-414：历史执行告知后接手

旧会话 `working`、失联或过期记录不足以证明进程仍在运行。新执行可在阅读风险提示后接手，不再填写停止证明。讨论、查询和调查的项目会话不触发条目接手。

## 判定与事务

`itemExecutionBlockers` 保留来源观察，新增 `blocking` 和 `superseded`。`hasBlockingItemExecution` 用于领取与派单门禁；`hasOngoingItemExecution` 仍用于取消、搁置等执行处置，不扩大本次放行到其他操作。

- 新鲜、节点在线的活跃回合或运行/停滞快照阻塞。过期、离线或撤销节点的旧快照作为未知状态提示。
- 排队、送达中、交付未知命令始终阻塞；尚未建立真实会话的启动派单仍阻塞。托管阶段及 AI 调度队列继续按其权威执行生命周期处理，不通过历史会话规则释放所有权。
- 无原生活动证据的进展记录和人工执行记录只提示。首次未领取派单的冲突保护保留；已领取过的旧派单在没有实际活动时可重新派单。
- 普通领取与处理中显式接手在事务内重查实际活动。迁移 `202611060020` 新建 `item_execution_takeovers`，只在成功领取时记录历史来源，不回填旧记录、不制造停止回执。
- 撤销该条目的旧执行凭据，旧执行安排记为 `handed_over`，新会话获得自己的凭据。会话进展/原生状态保持原样。旧身份不得再次领取或重新登记处理关系；其他条目的授权不受影响。旧会话仍可上报历史活动，但不能以此获得条目操作权。
- 显式交接继续冻结目标、条目范围和活动检查点；授权后观察变化会使待领取授权过期，领取事务失败时不留下部分接手记录。

## 界面及兼容

`ExecutionStopNotice` 为非阻塞记录显示风险和原会话入口，真实活动提示先处理；`AgentHandoffDialog` 保留范围与原因、目标、草稿和提交保护。`DispatchDialog` 在预检查显示旧执行风险，使用“启动新执行并接手”。Web、Android WebView 与 macOS 共用页面沿用同一实现，原会话链接使用现有主题令牌，无新增原生协议。

旧的停止确认接口保留以兼容已有客户端及审计，但新页面不再要求调用。没有 `blocking` 字段的旧服务响应在新前端保守处理。公开 Skill 更新同步说明未知状态不要求人工停止证明。

接手不能终止旧设备进程，不能撤销已发送到外部系统的命令；提示明确说明此边界。真实设备行为仍需后续发布后验证。

## 验证目标

- 历史 working、离线/过期（包括旧活跃快照）、多历史记录可接手；新鲜活动、三种待执行命令及启动占位继续阻塞。
- 普通领取/派单、处理中显式接手的权限与并发一致；旧凭据永久失效、旧身份不能抢回、共享会话其他条目仍有效。
- 数据库升级不补造接手；重启保留隔离与历史。
- 两处 UI 入口覆盖手机/桌面、明暗主题、触控、字号、诊断长文本、失败重试、草稿、焦点与提交期间禁用。

发布范围：`web`（Web/Server、数据库迁移及公开 Skill）。本地完成不代表已合并、发布或通过人工验收。
