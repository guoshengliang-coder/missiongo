# AND-515 固定文档批准恢复

## 结果与边界

原生同步只识别 Plan 协议，遗漏固定文档最终答复之后的普通文字批准。本次以共用领域核验器识别原决定，不让客户端直接提交“已批准”事实。

| 对象 | 变化 | 边界 |
| --- | --- | --- |
| 服务端 | 原节点报告与显式恢复复用同一核验器 | 只接受完整固定方案之后的独立“批准” |
| Codex、Claude Code、OpenCode | 保留最终完成标记、来源消息及时间 | 不完整、冲突或接收时间回退不作批准依据 |
| 两处会话入口 | 共用 DocumentPlanRecovery 和原有审批记录组件 | 读取历史不登记批准；恢复不派新回合 |
| MCP、Skill | 新增 recover_plan_approval，Skill 5.73.0 | 原账号、原会话、原文档及有效执行权限 |
| 审计 | 原决定与不可变来源记录同事务写入 | 区分原决定时间与核验写入时间 |

不同文档、范围变化、撤权、含糊或附条件回复均不恢复；现有有效批准保持不变。未开放跨账号管理能力，未修改工作条目实际阶段。

## 验证记录

- 领域回归 32 项：三种 Agent、实时与历史证据、HTTP/MCP、权限与撤权、范围变化、重复操作、来源冲突、实际旧版等待尾注。
- 浏览器 8 项：两处会话入口 × 320/1440 宽度 × 明暗主题，含重试、无新增执行命令及无横向溢出。
- Linux 节点 167 项通过。受影响 Swift 测试执行 98 项，跳过 1 项，无失败。
- 仓库检查：脚本 280 项及安装入口演练通过；各工作区测试通过（服务端 1570 项、2 项跳过，Web 745 项、节点 167 项、其他包 59 项，契约修正摘要后 9 项通过）。Skill 内容变更已同步版本及摘要。
- 类型检查、节点/Web 构建及最终性能门禁通过。完整检查曾因 Skill 摘要遗漏停止，修正后复核该契约及被阻止的后续检查；未重复已通过的无关测试。
- 原会话生产证据只读模拟返回 ready_to_restore；没有调用生产恢复、迁移或写入操作。该结果只说明原证据可识别，不代表生产记录已恢复。

详细规则见 [统一审批说明](agent-modes-plan-approval.md) 和 [MCP 契约](mcp-contract.md)。没有调低测试门禁或性能预算。

## 交付与后续验证

当前为隔离分支本地实现，尚未推送、合并或发布。涉及服务端/Web、macOS 节点和 Linux CLI；不包含 Android SDK 代码修复。

生产恢复仍需部署相关产物后，以原账号、原会话核验原决定；不要求原用户重复批准同一方案。真实三端模型交互和部署后恢复尚未进行；协议夹具、浏览器模拟及 Swift 测试不能替代这些验证。
