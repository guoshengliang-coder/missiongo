# 待集成清单：历史轮次、无需发布交接与待核对

## 范围与诊断

本轮为项目会话开发，复用用户已批准的迭代范围，不领取或修改任何工作条目。

- AND-501、AND-435 的旧轮次交付已有发布回执，但当前轮次读取会漏掉旧完成事件，使旧清单记录显示为待发布。
- AND-450 的早期无需发布交接缺少 developmentEventId；旧判断忽略了同轮次、同完成依据的正式交接事件。
- 清单原先将异常与正常待发布合并，角标因此包含不能直接执行的记录。

## 最终行为

| 对象 | 变化 | 边界 |
|---|---|---|
| 历史轮次 | 旧交付进入只读历史，保留原发布回执与后续返工说明 | 不将旧回执套给当前轮次 |
| 无需发布 | 精确识别正式交接，显示“无需发布／已交接” | 人工移动状态不能代替交接证据 |
| 待核对 | 单列异常、显示原因及原详情入口，禁止选择执行 | 不补造证据或自动恢复授权 |
| 计数 | 主角标只计待合并与待发布；全部列表包含待核对 | 历史不计待办 |
| 存量缓存 | 时间戳迁移标记显示投影待重建 | 不改写交付原文、条目事件、状态或验收 |

历史读取仅用于清单展示；默认领域读取仍限制在当前轮次。无 ID 的早期回执必须同时满足：同处理轮次、同完成依据、最近的前置开发事件，且必须是正式的无需发布交接。AND-450 实际早期回执还缺少完成引用；这种情况只接受同轮次唯一开发事件、显式无需发布范围、相同内容版本、直接衔接的修订号及 Agent 正式交接事件，任一条件缺失均不推断完成。不同轮次不能匹配。分组里仍存在当前轮次未完成内容时保留待核对，不能因其中某个旧轮次而隐藏整组。

## 共用组件与入口

复用 PendingMergeButton、QueueFacts、MergeDialog、QueueHistory、Modal、既有详情层与 i18n；不增加 CSS 或样式豁免。覆盖项目控制台入口、清单阶段筛选/全选/执行选择、详情返回与交付历史。Web 展示亦用于 Android 内嵌页面；原生包不在本次改动范围。
