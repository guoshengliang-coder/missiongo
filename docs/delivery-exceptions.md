# 交付异常核查迭代

待集成只保留可以执行的待合并、待发布；异常调查独立处理，用户能够发起核查、查看原始答复并记录结束结论。

| 问题 | 诊断结论 | 修改 |
|---|---|---|
| “全部”仍有不可执行项 | 原服务端与页面把 review 混入执行清单 | 全部与角标只计 merge/release，独立交付异常入口 |
| “请核对”没有动作 | 只有禁用复选框和详情 | 选择现有设备/Agent/原生模式，发起范围绑定的核查项目会话 |
| 核查没有收尾 | 无会话关联、答复或结论记录 | 展示核查状态/实际Agent/最新答复，人工记录理由后结束异常 |
| 结束容易误认正式交付 | 人工处置不能冒充发布或交接 | 单独核查历史，正式证据和发布门禁保持独立 |

## 已有授权与范围

用户已明确授权本轮迭代开发，复用原项目会话，不领取或创建工作条目。此文是实施/验证记录，不要求再次批准同一范围。源基线为已核实的 origin/main，线上 Web/Server 1.1.58 与该基线一致。主工作区较旧且有已有未跟踪目录，保持原状；改动在本会话独立 worktree。

核查发起使用当前账号已有的产品 view/operate/ai 权限和原交付归属；不是接手条目，不授予源开发会话身份。服务端生成只读调查任务，明确不领取、写代码/字段/评论、补证、合并发布或验收。原生模式/模型/强度由用户在共用配置中选择，原生权限并未被技术降为只读沙箱；“只读”是本次任务授权边界，不能声称能够强制约束任意第三方执行器。此次测试不启动真实 Agent。

## 流程与数据契约

1. 执行清单的 all 只返回 merge/release；review 保留为独立异常读取，旧客户端也不会再在 all 中取得异常。
2. 异常详情直接展示缺口、责任和可执行操作，不要求用户理解原始 Git/交接技术证据。
3. 发起核查校验精确交付修订与当前范围摘要。以交付+范围唯一约束关联一次项目会话，原请求键绑定配置；响应未知可沿原键恢复，另一点击也只回到同一会话。
4. 核查会话不关联条目执行。用户可阅读最新原始答复、打开完整会话，按真实运行/等待/失败状态继续讨论。最新答复不被自动摘要成正式结论。
5. 当前会话仍在运行、等待用户、投递未确定、读取失败或尚无当前答复时不能结束异常。人工记录非空处理理由并确认，仅关闭这条异常，不停止会话、不生成交接凭据、不改变条目状态或正式发布门禁。
6. 结论绑定实际交付和内容/Builder/轮次范围。内容变化不复用旧关闭记录；仍属异常的新范围可回看旧核查。若内容编辑已开启新交付轮次，原交付按既有规则归为旧轮历史，旧核查记录仍保留。正常人工阶段变化不会变造正式交付事实。
7. 已结束核查通过独立 reviewed 读取进入“核查历史”，不伪装成正式 history 交付；旧客户端不会将它误显示为已发布。所有动作只针对当前账号自己的交付，拒绝跨账号与过期范围。

表由UTC时间戳迁移创建；核查插入/结束触发显示投影及现有控制台变更通知。队列仍使用有界分页投影，不在列表热读取遍历原始时间线或加载核查全文。核查详情与答复按需读取，最多返回10份已变更范围的旧核查引用。

## 共用组件与覆盖入口

复用 PendingMergeButton、MergeDialog、QueueFacts、QueueHistory、Modal、DispatchDialog、Select、MarkdownText、公共 dispatch-form/form-footer 和现有会话导航。未新增样式豁免、并行权限模式或独立执行器。覆盖控制台/Android内嵌页面的执行清单、异常入口、设备与Agent配置、会话打开、短结论表单、核查历史及原详情返回。

核查记录仅作为异常处理审计，不承担工作条目正式交接；AND-450 仍须保留缺正式证据的事实，不能自动宣布验收或补造发布凭据。
