# AND-462：macOS 更新反馈与验证

## 诊断边界

原更新逻辑在复查更新信息、下载整个 ZIP、计算 SHA 时统一显示“下载中”，没有字节进度；下载使用 600 秒网络预算。替换应用以后还会等待节点完成在途派单启动/回传，再退出并重启。截图能证明旧客户端显示“下载中”，不能证明它已经安装完毕，也不能定位历史等待在哪个阶段。

调查时公开包为 12,207,190 bytes。两次有界只读探测分别在 45.003 秒收到 10,358,000 bytes（约 230 KB/s），在 30.005 秒收到 5,856,496 bytes（约 195 KB/s）；均因调查设置的时间上限主动中断，部分包未安装，也未用部分 SHA 判定包损坏。两个样本证明当时传输慢，不能定位网络瓶颈、解释所有历史快慢差异或认定代理故障。本修复改善反馈与恢复，不承诺线路提速。

## 变化与共用实现

- `UpdateDownload` 使用单次更新专属 URLSession，继承 `ServerConnection` 的系统/直连配置，独立取消，不影响通用 API 请求。下载期间检查声明大小与硬上限，完成后核对大小及 SHA。保持总预算 600 秒，60 秒无数据超时。进度约每秒节流，保留最终事件。
- `UpdateActivity` 区分复查、下载、校验、解压、安全校验、安装、已安装等待重启及重启失败。诊断最多 32 条，仅记录目标版本、阶段、耗时、字节和错误码，不保留原始 URL、请求头、用户路径或秘密。
- `AppModel` 保存单个更新任务并校验其轮次。安装前可取消并重试，迟到回调不能覆盖新状态；安装开始后不提供假取消。清单改变时重新展示说明，撤回时不继续下载。磁盘已安装与当前进程版本分别表达。
- `ClientUpdateService` 隔离 I/O 边界，生产继续使用原安装安全校验及重启命令。测试可验证 UI 生命周期而不替换真实 App 或退出测试进程。节点 drain 行为不变，不强退活动 Agent。
- UI 沿用 `VersionStatusSection`、`MenuGroup`、`MenuPalette`、原生 ProgressView/DisclosureGroup 与原外层滚动，不增加样式豁免。覆盖主窗口打开、菜单栏恢复到同一窗口及版本与更新区域；其余客户端入口不新增平行实现。
