# 会话消息顺序与投递回执

## 共用规则

控制台与条目内会话复用 `agentChatMessages`、`withOutgoingReply`、`AgentReplyFeedback`、`ChatAttachments` 和历史分页组件。
原生消息沿服务端顺序展示；用户发送记录按创建时间插入现有消息之间，缺少可信时间时保持稳定后备位置，不伪造时间。
附件镜像在原来源位置替换为原用户文本及文件；投递回执与正文分层，正常送达只显示“已送达”。
后续 Agent 回复、会话空闲或结束都不单独证明某条命令已执行。

## 来源关联

服务端为普通及外部原生会话返回可选 `command.sourceMessageId`，只从同一命令所属会话的已存用户消息取得：
原生客户端保留的命令 ID，或节点已确认应答产生的 `answer-<commandId>`。不匹配 Agent/执行记录，不按正文或时钟写入关联。
关联由现有持久化来源记录重建，不新增迁移或全量历史读取；同文重复命令仍有独立 ID。

macOS/Linux 的 Codex 普通输入和 Claude 支持链路已传递稳定 ID，macOS OpenCode 的已确认权限/表单应答也有固定应答来源 ID；本次复用这些契约，不修改节点控制能力。
OpenCode 普通 prompt 及旧节点未提供命令级来源证据时仍保守降级，不声称已经精确关联或确认执行，也不要求为本次 Web 修复自动安装节点。
旧数据的同文匹配仅用于展示，必须是时间范围内唯一候选；已知来源未加载时不能由其他同文输入顶替。
