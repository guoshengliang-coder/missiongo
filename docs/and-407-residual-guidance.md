# AND-407：状态与交付提示残留优化

本轮按获批 v2 实施，仅补现有提示和只读展示；已经解决的并行参与、领取、授权恢复、发布交接及人工验收机制保持。当前交付为本地代码和验证完成，未推送、创建远端 PR、合并或发布。

## 行为变化

| 对象 | 变化 | 边界 |
|---|---|---|
| 人工重新开始 | 有对应领域拒绝时显示来源、原因和处理角色 | 不把活动观察当作禁止独立派单的全局锁 |
| 原会话入口 | 服务端核对所有权及相关产品可见性后才显示链接 | 无权限/无会话时说明由原操作者或设备负责人处理，不新增解锁 |
| 领取文案 | 中英文及契约统一为领取与实施批准独立 | 不新增批准入口，不恢复已移除的常驻交接按钮 |
| 原身份恢复失败 | 兼容原错误码，安全返回有限失败子原因及下一步 | 账号、OAuth 客户端、原身份、轮次及撤权校验保持，不签发新凭据 |
| 交付说明 | Web 与 MCP 共用最近交付适用性及缺失依据说明 | 历史仍在原时间线，不加入本轮当前交付集合 |
| 部分发布 | 明确尚缺哪些发布产物 | 不把已有部分凭据说成完整发布 |
| 无需发布 | 单独显示尚待/已提交验证 | 不沿用“尚待发布/已发布”标签，不冒充人工验收 |

旧交付说明只依据明确事件：验收打回、完成后重开、取消、Builder/执行权交接、交付范围变化及轮次不符。历史缺少版本/轮次信息时明确依据不足，不猜原因。当前缺集成、未知发布范围、缺无需发布验证提交与缺发布产物分别显示。

恢复错误细分为回执未找到、记录关联不足、身份歧义、旧轮次及明确撤权。无法证明原身份或账号/客户端归属时仍通用拒绝；回执未找到不等于断言从未领取。读取说明和恢复失败均不修改条目、会话、轮次、凭据或交付事件。

## 共同实现和覆盖入口

- 共用 `ItemDeliveryPanel`、`ExecutionStopNotice`、`RecordDisclosure`、原控制台导航及 i18n，无新增样式或样式豁免。
- 原始写入校验不改；现有 delivery 响应仅补充 `manualClaimBlocked`、`canOpenSession` 和 `deliveryExplanation`。
- `DeliveryExplanation` 只读类型由 contracts 导出；服务端与 MCP 使用同一个函数，不另建通用诊断 API。
- 旧服务没有新标识时，不猜测原会话链接权限或人工阻塞，不假定新能力已安装。
- 正常首次领取、并行派单、原会话恢复、撤权拒绝、旧回执跨轮次拒绝及部分发布规则继续沿用。

1. 人工将已有活动会话的条目移回待处理，核对人工重新开始提示；独立派单资格保持，原会话入口仅本人可访问时显示。
