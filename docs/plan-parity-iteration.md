# 方案输出一致性迭代

## 已核实问题

实际派单仍使用“完整展示，不得只给摘要”的旧提示，同时新版方案已生成固定文档。源会话先输出长方案，再输出带修订说明的摘要，最后再展开长方案。旧 inlinePlanTranscript 仅匹配正文开头，未匹配时插入 submitted-plan 消息、缺验证时追加验证文本，造成控制台比原生端更多内容。

本机运行的客户端为 0.4.81，发布账本为 0.4.82；启动提示在节点二进制内生成。发布不等于运行中节点已更新。另发现 Linux 最新提示仍有旧结构化评论要求，现已一并清理。

## 改动与兼容

- Skill 5.60.0、Node/macOS 启动提示、MCP 方案字段和账户能力响应共同声明阶段契约：每版正式摘要只输出一次；进度报新增发现，最终不重贴；详细读取清单、QA 与技术限额留在文档。
- 原始消息数组保持不变。固定 documentId 链接关联批准控件，支持前缀说明与分段。修订只能绑定当前版本，旧文本须完整正文及验证匹配。
- 未关联记录由 UnlinkedPlanRecord 提供同步状态及阅读入口，不作为 Agent 消息。文档消息尚未同步时不允许从未关联入口批准；旧文本记录保留独立阅读及既有批准能力。查看不批准，已有决定保持。
- 不删除真实历史重复，不重写任何源消息。既有权限、范围、原身份和批准复用不变。更新节点不自动改变已注入的旧上下文；恢复时显式读入当前 Skill，不新建会话或重复批准。

## 验证边界

全量检查和 macOS 提示测试 9 项通过。浏览器相关场景累计 41 项通过（失败项修正后定向复测），覆盖控制台与条目面板、同步延迟、前置修订、历史未关联记录、明暗主题与窄屏。

真实 Codex/Claude Code/OpenCode 均实际运行了完全虚构的最小 Markdown 样例，并将真实输出回放进本地两种会话入口。Codex、Claude 各输出一份；OpenCode 额外输出运行约束，回放必须保留它。此验证覆盖原文传入后的消息数量、顺序、固定文档链接和批准关联，不代表三个客户端完成了真实业务调查及生产批准往返。

内部完整规范载荷的外部发送被自动审查拒绝，因此改用非敏感最小样例；没有将内部 Skill 或实际条目发送给这些测试进程。实际业务生成质量仍须持续观察，不宣称提示词能够绝对禁止模型重复。部署后核对公开版本、Skill 与原会话只读展示，历史原文不改写。
