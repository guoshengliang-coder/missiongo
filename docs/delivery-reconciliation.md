# 交付证据、处理轮次与状态说明

条目状态、Agent 会话状态和实际交付分别记录。人工移动卡片不表示停止 Agent、撤回代码或完成验收；会话结束也不证明合并和发布。

## 当前交接

- 已退役的定时/手动状态检查不再触发自动校正，也不新增状态检查或关联弹窗。
- 原合法执行者独立核实真实集成后，用现有交接工具登记开发完成；需要发布时必须记录完整必需产物。
- 授权发布者可使用当前候选快照补齐缺失集成/范围与发布证据，不借用原开发会话凭据；不能替换冲突依据或覆盖人工打回。
- 完整发布证据与明确无需发布的验证提交分开；部分发布保持未完整交付。待验证不等于人工验收通过。

## 轮次与历史

普通人工移回待处理保留原轮次；明确验收失败、完成后重开、取消、重新开始及受控执行权交接按实际事件使旧依据不再适用。普通并行加入不改变轮次，不撤销其他会话授权。

交付范围变化需要重新核实，优先级修改或相同内容保存不据此失效；历史编辑缺少字段级证据时保守说明。旧交付仍在原时间线中，不能把它自动放进本轮当前交付列表。合法执行人可以重新核实实际 PR/MR/提交，登记本轮依据，而不是重放旧回执。

现有 delivery 与 MCP 上下文的 `deliveryExplanations` 逐份提供当前交付的只读说明，并在需要时保留最近历史交付的适用性解释。每份说明绑定实际交付 ID，分别列出缺少集成/范围/无需发布验证提交和尚缺的发布产物；最新交付已发布也不遮住较早交付的缺口。`deliveryExplanation` 保留最近一份的原兼容语义。没有可靠轮次或版本时明确依据不足，不编造失效原因，不改变候选资格。

## 恢复与阻塞说明

原会话以原身份恢复有效领取，恢复不创造授权；错误账号/客户端或无法证明归属仍通用拒绝。可安全确认时返回有限失败子原因，区分原领取回执未找到、记录缺失、身份歧义、旧轮次和明确撤权，不泄露凭据。

人工“重新开始”被真实活动或待执行命令阻止时，执行记录显示该动作的原因及处理角色。有当前账号访问权的真实原会话才显示入口；无入口时指明由原操作者/设备负责人核对，不提供强制解锁。该提示不构成独立派单或并行领取的全局锁。

领取、实施批准和原生工作权限相互独立。已保存授权、已批准方案、消息已排队与实际执行分别说明；同一有效方案不重复批准。常驻 Agent 接手入口保持移除，复用现有原会话控制与批准入口。
