# 交付证据与条目状态校正

条目状态、Agent 会话状态和代码交付是三个独立记录。人工移动卡片不会停止 Agent、撤回 PR 或撤销代码；会话本轮结束也不表示代码已经合并、发布或通过验收。

## 校正规则

- 原处理轮次有登记的交付关联，且授权执行端核实 PR/MR 已合并或提交已集成后，可将草稿、待处理、处理中校正为开发完成。
- 发布范围未确认时，开发完成保留并提示补充；明确无需发布的任务等待人工安排验证。
- 所有必需产物的当前公开版本均核实包含合并提交后，才进入待验证；验收通过仍只由人工决定。
- 未开始处理、无交付关联或证据不足时，不根据标题、会话结束、构建成功或 Agent 自述推断交付。
- 每次校正记录原状态、交付关联、合并提交和实际发生时间；人工操作历史保留。重复回执不重复写事件，后来再次人工移动可触发新的校正。

## 轮次与范围

普通移回待处理或草稿保留原轮次。明确验收失败、完成后重新打开、取消、新领取和执行权交接使旧证据失效；尚未再次领取的返工条目也不能被旧证据恢复。

需求标题、描述、问题详情的实际内容变化会使旧关联待复核，重新登记关联后需要重新核验。优先级调整、相同内容再次保存不改变轮次。旧版本没有记录具体修改字段的历史编辑保守地要求复核。

多个条目可关联同一个 PR，各条按自己的轮次和必需产物核验。一条进入新轮次，不影响其他条目交接，也不自动拆分代码、停止会话或替用户合并。

## 触发与恢复

登记交付、人工移回卡片、节点核验回传、共享发布记录到达，以及现有定时/手动检查会触发核对。缺仓库权限、节点离线或发布证明失效时，检查结果明确说明原因；系统不会把排队当作核验成功。已过期的发布证明须重新核实当前版本。

## 展示与重派

列表与详情分别展示业务状态和“等待回答 / 尚未领取 / 等待合并核验 / 等待发布核验”等进展。历史派单归属显式标为历史，当前派单优先，原生会话详情仍保持账号隔离。

重派资格由服务端按选中范围计算，并与实际创建派单共用同一校验：只有同账号、整组选择、尚未送达节点的排队派单可确认取消并替换。已送达、已启动、其他账号或范围不完整时，显示具体原因；拥有会话访问权时可打开原会话，不提供无效的强制重派勾选。
