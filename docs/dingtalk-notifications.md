# 钉钉待验证通知

系统支持两种单向通知：企业内部应用的机器人单聊通知，以及个人工作通知。机器人通知以机器人名称和头像出现在人与机器人的单聊会话中，只做系统推送，不接入聊天问答；不保证钉钉客户端隐藏输入框。两种方式均复用已有人员绑定，不需要通讯录查询权限。工作通知不需要配置机器人。

## 管理员配置

1. 在钉钉开放平台创建企业内部应用，将接收人加入应用可使用范围。使用机器人单聊时，在应用能力中启用机器人，设置名称、头像，申请“企业内机器人发送消息权限”（`qyapi_robot_sendmsg`），发布机器人及应用，并取得后台显示的 robotCode。无需为单向发送开发 Stream 连接或 HTTP 消息回调。
2. 打开「设置 → 管理设置 → 钉钉集成」，页面直接展示现有应用信息，密钥只显示是否配置。点击「配置应用」或「修改配置」，在弹窗选择“通知方式”，填写同一个应用的 CorpId、Client ID（AppKey）和 Client Secret（AppSecret）。选择“机器人单聊通知”时填写“机器人编码（robotCode）”；选择“个人工作通知”时填写 Agent ID。robotCode 须按后台实际值填写，不使用群机器人 Webhook 地址。已有配置升级后继续使用工作通知，须由管理员显式切换。保存后可点击「检查应用凭据」，在弹窗主动发起检查；此检查只证明访问凭据可获取，不证明机器人权限、组织、Agent ID 或接收人范围正确。
3. 人员列表直接展示姓名、邮箱、企业 userId、部门、绑定状态和最近测试状态，不使用展开表单。点击「配置绑定」或「修改绑定」，在弹窗录入企业内 userId，可选填姓名、部门；保存成功关闭弹窗并更新列表，失败保留填写内容。解除绑定须在弹窗中再次确认。邮箱、手机号和客户端展示的钉钉号不是 userId。手动填写的姓名、部门不代表已向钉钉核验。
4. 点击「批量导入」，在弹窗通过 CSV 批量导入，表头为「邮箱,钉钉用户 ID,姓名,部门」，最多 500 行、256 KB。邮箱只用于匹配现有账号，确认后按内部账号 ID 保存。预览展示重复、冲突、账号不存在和停用等问题；有问题不部分导入。确认时重新检查预览版本，其他管理员的修改不会被静默覆盖。
5. 点击人员行的「测试通知」，在弹窗核对通知方式、机器人编码（如适用）和真实接收人，再主动点击「发送测试通知」；打开弹窗不会发送。机器人模式请在钉钉机器人单聊会话查看。首次触达是否需要先打开会话，以真实测试为准；接口提示没有有效会话时，请先确认应用可使用范围，再尝试打开机器人会话。弹窗持续展示处理状态，关闭后仍可在列表查看最近结果。测试通知至少间隔 30 秒，发送结果独立于绑定保存状态；不需要对方回复。
6. 打开「产品配置 → 指定项目 → 通知」，开启待验证通知。系统管理员、项目管理员和项目创建者可以配置该项目开关。

机器人单聊可选择互动卡片模板：在钉钉卡片平台创建并发布关联应用的模板，配置普通文本变量 `projectItem`、`itemTitle`、`verification`、`itemUrl`，按钮绑定 `itemUrl`，并为应用开通 `Card.Instance.Write` 权限。服务器环境变量 `DINGTALK_CARD_TEMPLATE_ID` 设置为已发布的模板 ID 后，新待验证通知使用互动卡片；未设置时继续使用 ActionCard，测试通知仍为文本。工作通知不使用此模板。修改环境变量后须重启服务。互动卡片单个变量受钉钉 1 KB 限制，正文按 UTF-8 边界截取；链接过长时不发送。

真实配置和人员映射只保存到服务器数据库，不提交到源码。Client Secret 使用 AES-256-GCM 加密，前端不会取得已保存的原文；运行环境中持久化的会话签名密钥（SESSION_SECRET）用于派生独立的钉钉加密密钥，须与数据库分别妥善保管。更换该密钥后须重新保存应用凭据。更新部署应保留服务器数据目录及运行配置。更换钉钉组织前须解除现有人员绑定。

## 条目归属与通知

使用个人授权账号辅助提交的 AI 条目，以该账号人名作为提需者，辅助显示「通过 AI 辅助提交」。实际事件 actor、客户端和 Agent 信息保留，评论仍按真实作者署名。该账号提交和经 AI 辅助提交的条目统一进入对应提需者筛选。

SDK、公共令牌和历史缺失账号的条目不推断具体提需者。账号停用、删除或失去项目查看权限时不发送条目内容。

状态事件和通知队列在同一事务中写入。每次真实进入待验证只产生一条记录，打回后再次交付产生新一轮；重复请求不产生重复通知。默认关闭，开启不扫描或补发历史。未开启、未绑定、未配置等原因在条目详情的钉钉通知记录中可见。

通知展示项目、条目编号与标题；有本轮发布凭据时列出验收版本，并按 Web、App 和其他产物分别提示验收方式。人工直接调状态或没有发布凭据时，提示查看条目的验收环境，不推测版本或下载方式。点击进入条目后，由人工验收；消息送达不自动改变条目状态。

## 发送结果

- 等待发送 / 正在发送：持久化队列处理中，服务启动后继续处理。
- 已受理：钉钉返回任务编号，尚不等于发送成功；后台继续查询结果。
- 发送成功：工作通知发送结果包含目标用户的已读或未读记录；机器人模式须查询到 `sendStatus=SUCCESS`，并包含目标用户的 `READ` 或 `UNREAD` 记录。均不代表已验收。
- 发送失败：明确失败最多尝试三次，有项目操作权限的人可以在条目详情补发。
- 未发送：展示项目关闭、未绑定、账号停用、无查看权限或条目已离开本轮待验证等原因。
- 发送结果不明：请求中断、进程在发送时退出、查询窗口过期或应用配置变化后无法核实。停止自动重发，人工核实后再确认补发，可能产生重复通知。

补发只针对当前仍待验证的最新轮次，已确认成功的通知不可补发。人员绑定变更、测试、开关和补发等操作记录在服务端审计表中，不记录应用密钥。
