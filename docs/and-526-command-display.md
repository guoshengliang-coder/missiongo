# AND-526 常用指令展示与焦点

沿用现有选择弹层、卡片边界与主题令牌，突出短名称并保留完整指令的选择前核对能力。

## 行为

| 对象 | 默认展示 | 边界 |
|---|---|---|
| 短名称 | 标准正文令牌，500字重，最多两行 | 名称截断也能展开 |
| 有名称的正文 | 摘要令牌、辅助文字色，最多两行 | 保留原换行 |
| 无名称的正文 | 标准正文令牌、常规字重，最多三行 | 长连续字符串可换行 |
| 全文入口 | 仅真实截断时显示 | 同卡片原位展开、收起，不填入、不发送 |
| 选择主体 | 保留右箭头与完整正文填入 | 保留插入位置、草稿、长度保护与撤销 |
| 搜索 | 主动聚焦，名称与正文均可匹配 | 不更改现有搜索算法 |

`CommandChoice` 是 `CommonCommandProvider` 内共用选择行。正文按钮与展开按钮为兄弟，避免嵌套交互；展开按钮具有 `aria-expanded` / `aria-controls`。`ResizeObserver` 根据实际文字布局检测截断，容器宽度、字号和内容变化会重新计算；展开时不因已显示全文而移除收起入口。

打开或从管理页返回时，现有头部管理按钮通过 `data-initial-focus` 接收焦点。该按钮位于搜索输入之前，沿用 `Modal` / `useModalSurface` 的现有契约。编辑表单继续自动聚焦正文，不更改全局策略。关闭、Esc、返回、管理页往返和草稿恢复继续由公共浮层处理。

回归中发现从选择器直接切换新建/编辑表单时，旧弹窗的焦点恢复会覆盖新表单焦点。因此仅在此处通过现有 `afterTopOverlayCloses` 先关闭选择器再打开编辑器；保持返回选择器及草稿语义，不修改共享浮层策略。

## 共用组件与覆盖入口

- 复用 `CommonCommandProvider`、`CommonCommandMenu`、`Modal`、`OverlayMenu`、既有文字按钮和主题字号令牌。
- 覆盖控制台已有会话、条目内会话与新会话草稿。管理页完整正文与编辑保存流程不变。
- 新增“查看全文／收起”中英文文案；无数据接口、迁移或原生客户端变更，无样式豁免扩展。

## 验证

`and-526-command-display.audit.spec.ts` 覆盖320px触控与1440px桌面、明暗和三档字号，检查层级、实际字号/字重、2/2/3行限制、真实截断入口、展开收起与焦点、长连续文本、无横向溢出、双字段搜索、完整插入、草稿与撤销、未发送、设置往返与编辑表单聚焦。

既有 `and-512-common-commands.audit.spec.ts` 与 `new-session.audit.spec.ts` 回归共用入口和保存、同步、冲突及草稿保护。全量检查结果记录在条目交付评论。

浏览器移动模拟不能证明真实Android WebView或iOS软键盘行为；发布后仍需真机验证。此改动尚未代表生产发布或人工验收。

## 独立审计补修

- 生命周期复查复现了账号清理后，等待历史层退出的旧回调重新打开编辑器/选择器的问题。延迟弹窗、设置跳转与填入后焦点恢复现在绑定原账号代次；旧菜单持有的打开/编辑方法也拒绝跨代次继续。不改变共享浮层实现、服务端或权限。
- `and-526-command-lifecycle.audit.spec.ts` 使用隔离组件夹具暂停真实历史协调器，覆盖编辑器、返回选择器、设置跳转与菜单四个延迟入口。清理后释放历史必须不复活旧动作，组件身份须保持，且当前账号仍能正常重新打开选择器，避免以页面重载或永久禁用掩盖失败。
- WebKit复查覆盖明暗、三档字号、320px/1440px、长正文、无名称及四个生命周期场景。macOS WebKit的默认Tab顺序尊重系统输入控件导航规则；全文展开另以键盘Enter验证焦点保持。结果不代表真实Safari/iOS设备验收。
- 无短名称的测试数据改用普通指令正文，并显式断言不存在短名称节点；产品从未添加“无短名称的完整指令”这类固定提示。

各轮复现、最终回归、完整检查及提交记录以本轮条目评论为准。
