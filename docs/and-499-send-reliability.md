# AND-499 消息发送反馈与可靠恢复

## 行为与范围

本轮交付 Web/Server，普通派单、项目会话与外部会话的后续消息使用同一发送流程；条目内面板和控制台共享页面持有的尝试记录。新会话首发保留原有 prepare/finish 幂等，只补上传稳定键、同步提交锁和阶段反馈。不修改节点协议或附件类型范围。

| 阶段 | 依据 | 行为 |
|---|---|---|
| 上传附件 | 当前文件与已完成数量 | 显示当前项/总数；只补未完成项 |
| 提交消息 | 原请求尚未返回 | 保留草稿，冻结请求键与参数 |
| 服务器排队 | queued 命令 | 沿用撤回编辑，不冒充节点收到 |
| 节点已接收、送达中 | delivering 回执 | 不表示执行开始或完成 |
| 已送达、待执行 | delivered 回执 | 等原生回显，沿用现有窗口规则 |
| 提交待核对 | 提交或查询结果不明 | 停止发送转圈，提供核对及原请求重试 |
| 节点送达未知 | delivery_unknown | 继续要求人工回原会话核实，绝不自动重放 |

## 请求身份与事务

`commands` POST 可选 `requestKey`，本轮普通消息入口一律提供；独立的权限答复与方案批准流程保持原契约。`SessionSendRequests` 使用现有 `idempotency_keys`，作用域为账号、会话、操作和键，保存内容 SHA-256 与原结果 ID，不重复存储长正文或文件。命令使用规范化文字及有序附件 ID 计算摘要。

同键同参返回原命令的当前状态；同键异参返回 `agent_send_request_changed`；新键相同文字是新请求。命令、附件绑定、请求记录在同一事务内提交或回滚。重复识别发生在 pending 及附件已绑定检查前。无键旧客户端维持原契约，不能推断其具有本次保证。

GET `send-requests/:requestKey` 是受现有账号、产品及会话读取权限保护的领域接口，按原命令 ID 返回当前状态或 null，不用最新消息、文字或时间近似匹配。查询不授予写权限，POST 保留执行授权及既有状态保护。客户端不因 GET 返回 null 就自动重新 POST；只有用户明确重试才复用原键。查询失败（包括旧服务不支持接口）时保持待核对。

## 附件与草稿

上传请求使用 `X-MissionGo-Request-Key`，来源为发送键加文件序号；摘要绑定规范文件名、类型及文件 SHA-256。原上传的响应丢失后同键可恢复，内容变化拒绝。并发重复上传在最终事务内复查，重复临时文件删除；数量检查在登记事务内执行，避免并发超额。同键恢复不占用额外草稿额度，已绑定的原上传仍可按键取回。

上传失败保留原 File、成功项和同次键。用户在明确未提交的失败后修改内容开启新尝试时，清理已知未绑定上传；未知提交不清理。无主上传继续适用原24小时回收规则，已清理的旧结果不会用旧键悄悄创建新文件。文字和文件仅在当前页面保存，不增加浏览器文件内容持久化；刷新后不承诺恢复 File。

共用发送器同步登记进行中的 Promise，双击/Enter 同次合并。请求绑定原会话，迟到响应仅结算匹配草稿；账号切换清除记录，迟到结果不重建旧尝试。成功释放原 File 引用，原服务器附件继续由命令记录读取。`preserveDraft` 的交付引导保留既有草稿语义。

| 轮次 | 核查与发现 | 补修 |
