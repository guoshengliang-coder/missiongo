# AND-346 评论元信息与分类筛选

本轮返工按用户在会话中批准的三项选择实施：匹配评论单独展示并保留上下文入口；按账号在当前设备记住筛选、跨条目沿用、初始全选；去掉“处理记录”标题并合并工具栏。

## 共用实现与覆盖入口

- `DetailPane` 的讨论和全部动态共用筛选工具栏，窄屏可以换行。人工评论、Agent 评论和流转及其他记录按事件种类分类，状态流转不会因操作者身份被误算成评论。讨论只提供前两类。
- `filterDiscussionTimeline` 在完整分组后筛选，只渲染匹配的正文，保留被隐藏根评论和直接回复对象的简短上下文入口。讨论排序和回复计数使用匹配内容。
- `CommentGroup` 继续用于人工、Agent、原评论与回复。作者及操作保持首行对齐，时间、来源标记和回复对象在占满卡片宽度的下一行连续排列，不足时自然换行；长名称可点开查看。上下文使用共享 `Modal`，随原记录刷新，撤回后沿用既有已撤回折叠展示，不再继续展开正文。
- 评论链接和原文定位可临时显示被筛掉的目标，不改保存的类别；恢复筛选会清除定位链接，避免刷新后再次展开。草稿和具体回复对象保留。
- `useCommentFilters` 按账号保存本机偏好；存储失败时保留当前筛选并明确提示未持久化。空态提供重置入口。
- 仅修改界面显示，服务端时间线、MCP 完整读取、通知和钉钉配置均未变更。Web 声明递增为 1.1.9，交付产物为 `web`。

## 人工验证与交付边界

合并并发布后，在手机和桌面切换讨论／全部动态，选择人工、Agent 和流转类别，核对混合讨论只有匹配正文、上下文可查看、草稿不丢失；刷新和切换条目应沿用本账号选择。通过评论链接定位被隐藏的回复，再恢复筛选，确认定位与回复对象正确。检查短名称元信息同行、长名称自然换行及可查看全文。

自动化使用 Chromium，Safari、Android WebView 和 macOS 宿主仍需真机验证。PR 提交、合并和发布是不同阶段，最终验收由人工决定。
