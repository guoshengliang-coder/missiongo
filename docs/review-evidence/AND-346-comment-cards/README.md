# AND-346 评论卡片返工证据

用户在本轮选择并批准：原评论和每条回复独立浅色卡片，保留讨论关系；人工与 AI 长评论统一折叠，在原卡片内展开全文、可收起。回复采用顶部右侧常驻图标加文字。

## 实现与覆盖入口

- 共用 `CommentGroup` / `CommentBody`，沿用原生 `details`、评论更多菜单、附件查看器、提醒结果和主题令牌。
- 讨论、全部动态、评论回复、回复的回复共用同一结构；展开后正文、结构化 AI 分析和附件仍由各自评论卡片承载。
- 长作者名可点击查看；窄容器缩小回复缩进，保留右侧操作的触控区域。人工和 AI 长评论继续使用既有 320 字符阈值和摘要生成规则。
- 本次只涉及 Web 评论呈现与回归，不改数据结构。浏览器使用隔离测试数据；没有向真实用户发送消息。

## 本地验证

- `npm run check` 通过：72 项脚本测试；Web 522、契约 9、领域 43、服务端 810 通过，2 项既有跳过；类型、构建及各项门禁通过。
- 评论浏览、草稿、回复、提醒、混合附件和新卡片矩阵共 40 项浏览器测试通过。增加短评论及长作者名查看验证、修正截图采集方式后，14 项新卡片矩阵复验通过。
- 新矩阵为 320×812、375×812、812×375、768×1024、1180×820、1280×800、1440×900，每档明暗主题、三档字号。测量右侧回复的位置、图标、触控尺寸及可见性、全文在卡片内的边界和横向溢出，并验证回复对象与作者全文查看。
- `npm run check:styles -- --base <本轮基线提交>` 通过，没有扩大样式豁免；最终测试文件 lint 通过。

## 人工验证

在发布后的版本中，检查短评论、人工长评论、AI 分析及带附件的长评论；点击右侧回复，确认对象正确；展开和收起时，正文与附件保持在原卡片里。手机与桌面均检查浅深色、大字号、长作者名以及同一讨论中的多条回复。

本地浏览器验证不等于 Android WebView、Safari 或 macOS 宿主真机验收；本轮未合并、未部署。
