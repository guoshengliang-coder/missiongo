# AND-375 会话加载审计

基于 `6161ca0` 加本次修复。本机 Chromium、隔离测试实例及合成会话，不是线上截图，也不是 Linux 像素比较基线。

## 同类入口与共用实现

| 入口 | 发现与处理 |
| --- | --- |
| Agent 控制台的手动授权、自动拒绝后的人工重试 | 列表摘要可先于正文提供审批数据；纳入详情就绪边界，保留已有权限选项、提交锁及来源请求消失后的清除规则 |
| 计划批准、其他待处理提醒、已标记无需处理 | 原先直接按列表摘要渲染；与正文一起显示，批准和无需处理操作沿用现有实现 |
| 失败卡、异常恢复、外部连接、归档和节点离线说明 | 同属消息区内提前显示的摘要卡片；共用相同边界。头部会话识别信息继续可见 |
| 运行详情 | 原有初次加载检查会在后台刷新失败时隐藏已显示状态；改按已缓存详情是否存在显示，复用 `AgentRunDetails` |
| 无原生会话的派单 | 无详情请求可等待，保留派单进度与恢复操作 |
| 条目内 `AgentSessionPanel` | 已按详情数据存在与否渲染正文，无列表摘要审批先显示路径，无需修改 |

就绪条件绑定当前会话查询键，以详情是否存在判断，不依赖消息条数或 `isFetching`；缓存重开和轮询保留内容。消息区继续复用 `AgentSessionFailureNotice` 等已有组件，没有新样式、浮层或权限范围。

## 验证边界

- 新增时序回归覆盖 320/375/1440px、明暗主题、权限/计划/无需处理/失败/离线五类卡片、切换后的旧响应、缓存重开、空会话、首次失败重试、后台刷新失败及无原生会话派单。
- 原 `and-349-approval-banner.audit.spec.ts` 加载阶段曾断言提前出现审批栏，本次改为等待正文；保留原有加载后高度、对齐、触控尺寸、展开原因和状态更新断言。
- 既有授权、计划批准、恢复、外部原生会话测试验证已加载状态下的行为。三档字号由既有统一权限请求矩阵覆盖。首次失败提供重试，加载状态通过 `role=status` 和 `aria-busy` 表达。
- 本次没有修改认证、授权范围、状态流转、附件协议、返回历史或草稿保存逻辑；没有扩大样式例外或更新 Linux 基线。
- 未验证 Safari、Android 真机/WebView、macOS 原生宿主及生产慢网环境。自动化响应控制证明渲染时序，不能代替这些环境的人工验收。

发布范围为 Web；代码提交和本机测试不代表已合并、已发布或验收通过。
