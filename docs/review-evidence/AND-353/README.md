# AND-353 执行记录融合

条目详情将会话、派单和非评论钉钉通知放在同一个带底色的“执行记录”框中。默认仅显示数量和展开入口；展开后按时间从早到晚显示摘要，各条记录可独立展开、收起。关联的会话与派单只算一条，每条钉钉通知单独计数。评论通知仍留在对应评论旁。

## 验证

- `npm run check` 通过；样式检查无新增违规。
- 相关 UI 回归覆盖 `execution-records`、`item-mobile-clarity`、`builder-delivery`、`dispatch-attention`、`agent-question-scroll` 和 `comment-discussions` 六个 audit 文件，共 62 个场景。首轮的失败场景在调整测试断言和可见区域准备后独立复跑通过。
- 混合记录最终 6 个用例全部通过：排序及去重计数、独立折叠、键盘展开收起、展开状态在补发结果更新后保留、结果不明时先确认再补发、只有通知记录以及执行数据源失败时仍可查看通知。
- 会话滚动最终 4 个用例全部通过。新增记录摘要改变了页面高度，测试先让消息视口完整可见，再测内部滚动；原有滚动位置和选项可见性断言保留。
- 检查移动端和桌面端、明暗主题、无横向溢出、可见文本至少 11px、普通文本对比度至少 4.5:1、记录摘要触控区域至少 44 × 44。

## 人工验证

1. 打开同时有会话／派单和钉钉通知的条目，确认默认仅显示“执行记录（数量）”与“展开”。
2. 展开总框，核对顺序和数量。展开其中一条，再展开另一条，两条应独立保持状态；收起总框后重新展开，各条状态应保留。
3. 检查会话入口、执行详情及有权限时的执行更新。通知详情应保留接收人、发送结果、原因、时间、尝试次数和符合原权限条件的补发入口。
4. 在可控测试环境检查结果不明的通知：点击补发先显示确认弹窗；取消不发送，确认后才调用补发。真实钉钉送达需由接收人核验，自动化仅证明界面与请求行为。
5. 核对评论通知仍在评论旁；在 Android WebView 中复核触摸展开和滚动体验。

本次交付产物为 Web；未改变通知发送规则、业务状态机、接口或数据库结构。代码合并和正式发布仍需分别核实。
