# 安全边界

## 敏感信息规则

严禁提交以下内容：

- 真实域名、IP 地址或端口；
- 数据库凭据，或包含私人机器信息的路径；
- MCP、SDK、会话、GitHub 或 AI 服务商 Token；
- Android 密钥库、Apple 证书、描述文件或签名密码；
- 本机代码仓库路径；
- 生产日志、截图、附件或数据库快照。

仓库中可跟踪的示例只能使用空值或明确的保留示例值。

## 角色、状态与交付权限（AND-357）

完整矩阵及自动校正规则见 [AND-357 实施核对](and-357-role-state-policy.md)。验收通过限登录的系统管理员、所属项目管理员和提需者；验收打回、取消及恢复已取消允许这三类人与当前 Builder。重开已完成限管理者或提需者，已完成不能直接取消。角色叠加，责任转交后不凭历史 Builder 身份继续操作。

项目创建者默认成为项目管理员，之后管理权依据当前角色。普通操作权不自动赋予他人条目的业务决定权；只读提需者可在查看权限内决定自己的需求。人工 Builder 不要求 AI 权限，Agent 写入同时检查操作权、AI 权限与本轮执行凭据。SDK 只创建反馈；运维凭据不能冒充人工写条目或决定验收。

状态、内容和责任变化使版本前进。单条及批量写入绑定预期版本和幂等键，人工交付确认再绑定交付关联版本；过期页面不能验收新的成果。打回、取消、重开使旧轮次和执行凭据失效，暂缓保存原阶段并保留事实。交付系统只依本轮证据推进开发完成及待验证，不能代验收，也不能覆盖暂缓、取消或重开。

MCP 交接可提供原 `dispatchId`、外部 `sessionId` 或原生/跟踪 `session`，服务端依据原领取回执定位内部凭据，并核对原账号、OAuth 客户端、条目、当前轮次与撤销状态。身份不是通用授权：后来关联、另一会话或另一条目不能代替原领取，缺失/歧义证据拒绝，Builder 交接仍永久撤销旧授权。不得仅按同一登录账号选择任意有效领取。

领取/恢复的 `authorizationMode: "conversation"` 不在文本或 `structuredContent` 返回执行凭据，新版 Skill 使用此模式；文本仅含后续可用的非敏感身份。旧客户端省略模式时仍保留凭据返回，迁移前的上下文暴露风险没有被消除。该兼容路径及内部原始回执不应被打印到日志。无状态 MCP HTTP 没有额外的对话认证，本改动沿用原恢复接口的账号、OAuth 客户端和领取关联校验，不把模型自述的会话标识当作独立认证。

列表、启动快照、详情与状态返回提供条目可用动作及拒绝标识。不可访问的项目仍返回不存在。本地未配置认证的开发模式使用本地管理员身份，不能用于生产。

## Token 类型

- 管理会话：管理员账号拥有完整管理权限；普通账号在授权范围内协作，当前项目管理员可治理所属项目，包括归档、恢复及成员授权。历史创建者身份本身不保留永久管理权。
  会话与 AI 令牌都是签名串，不落库；账号被删除、停用或改密后，凭据时间戳不再匹配，已签发的会话和
  令牌立即失效。代价是无法单独吊销某一个会话，只能整体作废该账号的全部凭据。
- `ADMIN_API_TOKEN`：部署级运维令牌，不携带账号身份，因此**绕过产品权限**，读取部署范围内的诊断信息；配置维护以机器来源审计，条目写入和人工业务决定另行校验——它没有账号身份可供判定。它是给运维脚本和备份用的机器凭据，不是登录方式；
  泄露等同于泄露整个部署。放在反向代理之后，不要发给人。条目创建、编辑、协作与状态操作要求领域账号；项目授权及归档恢复不能借此冒充人工（AND-357）。
- SDK Token：只能提交反馈，并限制到一个产品或组件。
- MCP AI 授权：由现有账号登录后签发，范围为 `missiongo:read`，或读取加 `missiongo:write`。
  写入范围只允许在有权访问的产品的条目上追加评论、领取待处理条目、在 PR 合并后标记「开发完成」、
  在所有相关产物核实发布后推到「待验证」，以及经用户确认创建条目（服务端无法验证用户的确认，
  故另按来源条目或产品限流）；不能修改条目内容与字段、删除条目、撤回评论，或做验收、退回、
  搁置这类判断性流转。部署侧另有 `MISSIONGO_WRITE_TOOLS` 档位开关，默认关闭：档位决定这个部署
  提供什么，范围决定这次连接被允许做什么，两者都满足才能写入。
- 未来的节点 Token：绑定一台 AI 工作机器及其允许的能力。

AI 客户端不得保存账号密码；首次连接时密码只提交给 MissionGo 登录页。OAuth 授权必须绑定账号、客户端、权限范围和有效期。
令牌签发给在授权页上登录的那个账号，并继承该账号的产品权限；权限从账号表实时读取，不写进令牌，
所以在控制台取消勾选对已签发的令牌立即生效。

每一次授权都会记录在 `ai_authorizations` 里，账号所有者可以在控制台看到已连接的 AI 客户端——授权
时间、最近使用时间、有效期和权限范围——并**单独撤销其中一个**，不影响该账号的其它客户端和浏览器
会话。记录不含密钥，令牌本身仍是签名串；校验仍然基于签名，只向这张表问一个问题：这次授权是否已被
撤销。撤销能力上线之前签发的令牌没有对应记录，因此不受影响——这是有意的，否则上线撤销功能本身就
会撤销掉所有人。它们仍可按原有方式（改密或停用账号）整体作废，并在有效期内自然过期。

授权只能由它的所有者查看和撤销。管理员管理的是账号，而一次授权是账号所有者自己授予的凭据；管理员
对应的手段是停用该账号，那会一次性切断它的全部凭据。

## 托管决策的人工批准（AND-231）

`/api/v1/managed-runs/:runId/decisions` 与 `/api/v1/managed-decisions/:id` 系列是独立人类 Cookie 入口，不继承运维 Bearer 的产品绕过。混合 Authorization 头也拒绝。写入要求配置的同源 Origin；权限与会话在写事务内重新验证，完整冻结范围逐项核对。批准需 operate + ai，撤销需 operate；无认证部署不能批准。

本功能只记录批准，不启动 Agent，也不改变现有手动派单。详细身份、幂等、撤销和未来执行消费边界见 [managed-decisions.md](managed-decisions.md)。

## 产品授权（AND-58）

系统管理员或当前项目管理员可以授予、移除本项目的普通能力。创建者在建项目时默认成为项目管理员，后续管理权随角色调整。普通成员获授操作或 AI 能力不形成再授权链。AI 范围显式配置为全部、指定或禁止，空白指定清单是没有 AI 项目，不解释为全部。项目侧授权不能改动账号全局 AI 范围；全局禁止优先于项目授权。

账号名单仍然只有系统管理员能通过账号管理接口完整读取。项目侧授权面板改为可搜索选择器（AND-390）：
**能管理某个产品授权的项目管理员可以从该产品打开一个候选账号列表**，按昵称或邮箱搜索，用于选择要授权的人。
列表只返回 `{id, email, nickname}`，不含角色、停用状态、`credentialsChangedAt` 或任何凭据字段；已停用账号
不出现，因为它本来就不可授权。列表最多返回 50 条，超出部分靠输入关键字收窄。产品授权表本身仍然收窄：
项目管理员看到的行是「在这个产品上确实持有权限的账号」加「全部管理员账号」，其余账号不出现在行里，
尽管它们会出现在候选列表中。

**已知取舍：候选列表等于账号枚举口。** AND-390 之前，不做这件事的理由是「不给名单、只按邮箱精确添加」；
用户在 AND-390 中明确选择放宽为 GitLab 式选择器，因此任何能管理某产品授权的人都能读到全部可授权账号的
昵称和邮箱。任何登录成员都能自己建一个产品并打开它的授权面板，所以**全部可授权账号的昵称和邮箱对任何
成员可见**（此前只有管理员邮箱可见）。按邮箱添加仍然保留，并且仍然不区分「地址不存在」和「账号已停用」：
两种情况返回**完全相同**的错误。一次请求最多 200 条 entry。

创建者不能改动自己那一行，也不能改动任何管理员那一行。前者会让产品从自己的列表消失、连设置页一起带走；
后者会移动那个管理员的 AI 可达范围——管理员的 AI 范围恰好由这些行界定（没有行＝全部产品，有行＝仅这些产品），
两个方向都能被滥用：加一行把它收窄，清掉唯一一行把它放宽到全部产品。

## 不可信反馈内容

描述、评论、日志、OCR 结果、文件名、图片和视频都可能包含恶意指令，必须明确标记并按数据处理。服务端和 Skill 都不能允许这些内容覆盖系统指令、用户指令、代码仓库规则或安全规则。

## 附件安全

- 存储文件名由服务端生成。
- 限制文件大小、数量、MIME 和扩展名白名单。
- 防止路径穿越，禁止直接公开附件目录。
- 只通过带鉴权的端点或短期访问地址提供内容。
- 展示用户文件名时必须转义。

## 审计事件

当前条目时间线记录创建、编辑、状态变化、附件变化、评论、评论撤回和人工验收等业务事件。服务端日志记录请求与鉴权异常，但不得记录明文密码、完整 Token 或受保护正文。

AI 写入的事件和评论记录归属：账号、OAuth 客户端和所属执行。这不只是审计——AI 在动作前会重新读取条目，分不清哪些是人给的事实、哪些是上一个 AI 的推测，就会把自己的猜测当依据反复强化。

人工写入同样记账号。以前不记是因为只有一个管理员，`actorKind` 已经指明是谁；多账号之后这句话不再成立。运维配置维护使用机器来源记录，不能伪造带人工身份的条目决定。

账号的展示名现在随时间线和评论一起下发，所以**能看到一个产品的成员，就能看到在该产品上写过东西的
其他账号的展示名**——昵称，或者未设置昵称时邮箱 `@` 前面的部分。此前账号清单只有管理员看得到。这是
有意的有界披露：署名要能回答「谁写的」，否则记归属就没有意义。**完整邮箱和域名不在其中**，展示名的
回退只取 `@` 之前的部分。展示名是自述标签且不唯一，不构成身份证明。

退回待处理时必须填写的原因同样写进时间线，随条目对所有能看到该条目的账号可见，也会被重新派单的
AI 读到——它是写给下一个接手的人的，不是私记。

已撤回的评论保留在库中但不再返回给 MCP，撤回动作本身写入时间线。撤回只由人执行；AI 不能撤回任何评论，包括自己写的。

产品管理员配置与账号／项目授权变更保存前后快照、操作来源及账号。状态决定另保存当时角色、授权依据、内容版本、处理轮次和证据，人工纠偏必须留原因。

Token 生命周期审计、附件访问审计、导出审计，以及未来 AI 领取和租约事件，属于后续安全增强项；在对应能力上线前必须先建立持久化审计模型。


## AND-232 受监督原生执行

[managed-execution.md](managed-execution.md) 定义默认关闭的协调者/Node 控制面。仅明确允许的现有 OAuth 客户端可协调，Node 只能领取和报告其绑定意图，worker 不取得业务写入、领取或批准权。人工决定仍使用 AND-231 独立人类入口。启动意图、批准绑定及已注册单 Node 本地执行器域的写者所有权先持久化；未知执行不随 TTL 释放，终态与清理观察分开。旧手动写者没有被忽略；未核对历史可能阻塞启用。

复用原生 Codex 沙箱和线程配置，不引入 OS 隔离或全客户端网络封锁；worktree 与监控不是隔离。线程对所有 MCP 注册核对 disabled 状态及空工具清单，拒绝改名业务写服务和未知状态；只有 fixture 验证，目标 Codex 版本的真实 thread-scoped 能力语义仍需独立验收，不能证明用户未通过其他凭据授予权限。审核只读、验证独立目录、作用域输入/停止都必须通过真实原生 fixture 另行验收；没有自动 continuation Bridge、发布或 AND-229 完整试运行。

## 条目交付责任与执行记录（AND-304）

Builder 是条目上的账号归属，不是全局角色，也不授予额外权限。人工候选须具有实际操作权限且账号启用，实际 Agent 执行另查 AI 权限；模块默认 Builder 仅给新条目或首次补充来源模块的未分配条目自动分配，不覆盖已有责任归属或人工选择。停用、删除或收回权限后保留历史归属，并标注需要重新分配。

默认负责人由拥有产品操作权限的系统管理员或项目管理员配置。条目责任转交和执行安排仅允许拥有该产品操作权限的当前 Builder、系统管理员或项目管理员操作。执行人可以更新自己的执行进展，也仍须拥有产品操作权限。专用接口仅接受登录会话，不接受运维 Bearer 或 AI Token 代替用户身份；列表只提供必要的账号 ID 与展示名，不暴露完整邮箱或凭据。

人工与 Agent 执行记录允许并行及多轮交接，关联具体条目、授权账号和真实会话。Agent 会话必须已经关联当前条目，不能凭任意会话 ID 建立关联。执行交接会保留前一轮的范围、结果、开始与结束时间；终结的记录不可再次修改；返工通过显式的后续执行关联到历史记录，不覆盖前一轮结果。安排到已有 Agent 会话只登记本轮工作，不自动启动、停止或向该会话发送指令，实际执行沿用已有派单与会话交互。

责任转交使用预期的旧 Builder 做并发检查，交接及其时间线在同一事务内写入。执行状态、会话运行状态和条目状态保持独立，任何执行完成都不代表条目已发布或验收通过。筛选、分页、状态计数和启动快照使用相同的 Builder 条件，并始终受产品查看权限限制。
