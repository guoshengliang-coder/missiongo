# UI / UE 复盘与改进方案

> 文档版本：v1.0（待评审）
> 日期：2026-09-22
> 依据：main @ `465a042` 的代码通读、382 个提交的历史回溯，以及本地实例实测（Chrome；375×812、768×1024、1440×900；浅色与深色）
> 配套规范：[设计规范](design-system.md)

本文回答三个问题：**现在是什么状态**、**反复出问题的根因是什么**、**接下来怎么做**。
每条结论后面标注证据来源：「实测」表示在浏览器里复现过；「代码」表示读代码得出、尚未实测。

局限：MissionGo MCP 在本次会话中不可用，所以没有列出 MissionGo 里尚未关闭的 UI 条目。本地实例没有数据，列表密度和详情页相关的结论来自代码和历史，不是这次实测。

## 1. 结论

1. **Web 端的令牌层已经成型，但只有颜色是真正落地的。** 字号、圆角令牌定义了却绕开用，间距、层级、动效、焦点环连令牌都没有。所以每次改 UI 都在发明新数值。
2. **适配问题的根源是「断点各自为政」加「没有视觉回归」。** 7 个宽度断点加 1 个容器查询；过去 30 起 UI 事件里至少 7 起是断点错位，至少 4 起是修复又带出新回归。
3. **深色模式有一批确定会出错的地方。** 共 9 处：写死的浅色值、不存在的变量、只在浅色下成立的颜色搭配。其中 2 处已经实测复现。
4. **三端没有共享同一套设计语言。** macOS 只用系统蓝和系统色；Android 原生层只有浅色；反馈 SDK 页面字号降到 9–10px；派单状态在三端有 3 套叫法。
5. **方案**：先用 1 周修掉确定的缺陷（D0），再花 2–3 周补齐令牌与断点体系、建起防回归护栏（D1–D2）。组件收敛（D3）和跨端统一（D4）分批推进。**护栏必须和修复同批上线，否则这次修完还会再坏。**

### 2.2 已经做对的

以下做法保持不变，并写进了[设计规范](design-system.md)：

- **文字与颜色**：中性文字色全部达到 WCAG AA；最小字号令牌是 11px（UI-05/06）。
- **深色模式**：只重定义令牌，不写主题分支。（本意是在首帧前写入 `data-appearance`，但这一步在生产环境没有生效，见 B12。）
- **视口与安全区**：先写 `100vh` 再用 `100dvh` 覆盖；设置 `viewport-fit=cover`；安全区通过 `--safe-*` 令牌引用。
- **弹层**：用原生 `<dialog>` 加 `showModal()`，背景自动 inert，Esc 交给 `onCancel` 处理。
- **移动端交互**：录入表单的提交栏吸底；输入框字号 16px，避免 iOS 聚焦放大；动效会遵守 `prefers-reduced-motion`。
- **Android 返回栈**：由前端上报历史深度，原生层按深度回退（AND-28 修了三轮之后稳定下来）。

**根因。** 这一组问题的共同原因是「设备模型」只有一个维度，也就是宽度。对设备的真实划分至少要看四个维度：

1. 宽度：决定布局；
2. 输入方式：`pointer: coarse` 还是 `fine`，决定触控尺寸和悬停；
3. 可用高度和屏幕方向：决定吸顶、吸底元素怎么放；
4. 内核版本：决定能用哪些特性。

现在只处理了第一个维度。所以在 R1–R8 之外，新增一条 **R9：设备模型只有宽度一个维度**。

## 5. 改进方案

### 5.1 原则

1. **先装护栏，再大改。** D1 的检查和截图基线必须在 D2、D3 的重构之前上线，这样重构有对照。
2. **每批都能独立上线、独立验收。** 不搞一次性大重写。
3. **机器能查的就不靠人记。** 未定义变量、裸色值、断点值、触控尺寸、对比度都写成检查。
4. **沿用现有做法。** 条目用 AND 编号，一批一个 PR，合并后进入待验证。

## 6. 非目标

- **不换技术栈。** 不引入 Tailwind 或组件库，也不迁到 CSS-in-JS。现在的令牌加普通 CSS 方案够用，问题出在纪律，不在工具。
- **不重做信息架构和视觉风格。** 米色底、navy 加 mint 的品牌基调保持不变。
- **不引入 Storybook。** Playwright 截图覆盖真实页面，维护成本更低；等 D3 的组件数量稳定后再评估。
- **不做平板专属布局。** 平板沿用紧凑外壳，只保证触控和悬停的可用性。
