# 结构化方案摘要修复

## 问题与实现

用户提供的单条目截图中，诊断、证据、修改、范围、审批和执行记录混成长段。此前规范以“单条 150–300 字、多条每条一行”组织，并只将表格视作可选形式，未明确单条目的多个问题同样需要结构化。

统一生成规则：一句诊断与推荐 → 按问题数量选择短表或分行列表 → 必要边界与验证重点 → 固定文档与一次审批说明。多个独立问题（包括同一条目）默认三列表，每格一个短要点；一个简单问题用诊断/修改短列表。保留未复现事实、待决项、用户选择、附带范围与验证缺口。领取、worktree、命令和测试数量进入详细文档。字数不成为压成一段或删掉决策条件的理由。

Skill 5.63.0 为完整来源，macOS/Node 的派单和项目启动提示同步；MCP 账号契约 v4、prepare_plan_document 描述和 summary 参数同样约束保存前结构。准备后始终原样展示返回的 plan，不在客户端转换，也不在服务端重新格式化已存或已批准文档。

共用 MarkdownText、既有文档与审批入口，无新增组件、样式、审批门槛或历史改写。返工沿用当前版本与有效授权规则。用户明确指定格式时以用户为准。

## 验证与边界

- 生成规范契约测试核对 Skill、Node/macOS 两入口规则一致及 MCP 保存前提示；不能单凭字符串测试声称生成体验通过。
- 文档集成测试使用单条目三问题表，核对保存、MCP/Web读取、审批、重试与评论附件不改变结构。
- 真实 Codex、Claude Code、OpenCode CLI 的虚构单条目多问题与简单问题样例均生成三列表和分行列表，保留未复现事实、范围及链接，没有复述执行记录。Claude 仍增加了风险解释；OpenCode 额外生成原生模式提示，完整保留，不以隐藏使各模型输出看起来一致。该实验是表达能力样例，不等于真实业务调查或生产批准往返。
- 将三端原始输出回放到控制台与条目面板，375px/1440px 共 12 项浏览器回归通过；桌面与窄屏截图人工检查表格、分行层次、链接和溢出。无新组件或样式变更。
- macOS LaunchPromptTests 9 项通过，覆盖各客户端模式与派单/项目会话；全量检查结果以合并 CI 为准。
- 提示不能保证模型绝对遵从；本轮不宣称所有真实业务原生审批往返已验收。节点升级与旧会话重读 Skill 后才适用新引导。
