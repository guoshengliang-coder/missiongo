# AND-502：Linux Codex 失败诊断

Linux Codex 适配器此前只根据最近回合标记失败，没有上报公开错误详情；Web 恢复文案还固定指向 Mac。
隔离基线复现已确认：即使原生回合提供错误与 HTTP 502，普通快照、控制快照均没有 `failure`。
这说明诊断链路缺失，不能据此确定历史派单的原始失败原因。

## 行为与边界

- `codex-failure.ts` 将公开 `codexErrorInfo` 映射到既有稳定错误码；HTTP 401/403、429 和连接错误分别按现有语义分类。未知类型保持未知，不按消息关键词推断根因。
- 只读取 `error.message`、错误类型、合法 HTTP 状态与安全回合标识，经过领域脱敏和限长。`additionalDetails`、请求体、配置、stderr 和任意协议对象不进入诊断。
- 两类快照复用相同解析；终态错误通知仅作为相同回合缺少元数据时的有界补充。正在重试的错误不会变成失败卡。
- 宿主恢复时移除已持久化的旧诊断；迟到回执保留最新可信状态及对应诊断，不复活旧回合错误。
- Web 全部失败恢复分支指向执行节点；控制台和条目内会话复用 `AgentSessionFailureNotice`、原有详情/复制交互及 danger 令牌，没有新样式或豁免。
- 没有增加自动重试、权限放宽、数据库迁移或任意原始错误上传。投递失败、历史读取警告及其他 Agent 的反馈保持独立。

| 原生协议 fixture | 普通/控制快照、回合元数据、终态通知补充、缺少详情、重试中及恢复；重复观察不重放输入 |

| 浏览器 | 失败卡详情/复制与复制失败、手机触控、320px/桌面、明暗、条目面板与控制台、旧列表残留、手动续聊及送达不明不重放 |

首次实施的专项 Node 测试 56 项、Web 失败卡测试 17 项通过；失败卡浏览器回归 12 项通过。
`npm run check` 完整通过，包含 lint、身份/平台/迁移/样式契约、全量单测、类型、构建和性能预算；存量服务端套件有 2 项跳过，未改动或扩大跳过范围。
截图已人工查看手机深色与桌面浅色，诊断可读且无水平溢出；浏览器验收不替代真实 Linux 节点验证。

真实历史失败详情没有原始日志可恢复，不能伪造回填；未升级节点仍可能缺少详情。
最终需在获授权发布后，用更新后的 Linux 节点验证真实 Codex 失败与续聊。必需产物为 `linuxCli` 和 `web`。

## 后续三轮审计与补修

用户授权最多三轮独立审计并补修；按并发状态、诊断语义、完整安全与跨入口回归三个视角分别检查，沿用原实施范围。

| 轮次 | 发现与复现 | 补修与结果 |
|---|---|---|
| 1：并发快照 | 历史读取中的旧 active 快照会清空后来收到的终态错误缓存；新增确定性并发测试先失败 | 快照读取保持只读，由原生回合事件维护单份有界缓存；同一回合及 failed 状态检查保留，42 项适配器测试通过 |
| 2：诊断来源 | 历史读取警告被误作 Codex 故障原因；结构化错误无详情时把存储回填的错误码当详情；两项新增测试先失败 | 共用历史警告判定，结构化详情以自身字段为准，缺失时显示缺失；19 项失败卡单测通过 |
| 3：安全与组合检查 | 复查公开字段、脱敏、安全回合标识、旧节点兼容、两处入口及手动续聊；未发现其他问题 | `npm run check` 再次完整通过，包含性能预算；16 项浏览器回归通过 |

并发回归使用原生协议 fixture 加受控历史读取屏障，真实经历旧读取开始、新失败事件、控制观察、旧读取结束、再次控制观察的顺序，不以延长超时掩盖竞态。
浏览器新增四项用例分别在控制台和条目面板验证历史警告独立可见、错误分类无详情时准确说明缺失。

补修只涉及 `codex.ts`、`agent-session-failure.ts` 及对应单测、浏览器用例和本文。
最终完整检查中 Node 166 项、Web 738 项、服务端 1495 项通过；存量服务端 2 项跳过未改变。
没有推送、建 PR、合并、发布或真实 Linux 节点复测；历史故障根因和旧节点升级验证仍保留上述限制。
