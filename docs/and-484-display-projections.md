# AND-484：展示物化与列表投影

本次将合并交付展示从请求时重算改为源写入时派生；条目列表使用独立摘要行。展示结果不授予任何执行、合并、发布或验收权限，实际操作仍检查实时源数据。

## 实现与兼容

| 对象 | 变化 | 边界 |
|---|---|---|
| 数据库 | 新增迁移 `202611090156`、依赖映射与投影表 | 源事件不改写；旧库在服务初始化时回填 |
| 写入 | 触发器收集受影响对象，最外层提交前更新 | 单语句、RETURNING、嵌套回滚均受同一事务约束 |
| 合并展示 | 交付、批次 presentation、attention、会话阶段直接读投影 | 批次仍取最近 20 份，不删除历史以改善指标 |
| 时间边界 | 保存证据新鲜度区间、发布心跳截止及到期状态 | 不等下一次业务写入，不把过期心跳当作发布中 |
| 条目列表 | 分页只选行标识，再批量取列表投影 | 列表排序位置也在写时保存，不逐行读取时间线 |
| 新列表契约 | `projection=list` 返回独立 `WorkItemListRow` | 摘要、缩略图、诊断计数、权限与徽标保留 |
| 旧列表协议 | 保留完整字段响应，读取写时保存的兼容快照 | 不逐行重算详情、证据或时间线；详情接口仍实时组装 |
| Web/MCP | Web bootstrap、后续分页及 MCP list_items 使用摘要行 | 不能把摘要行写入详情缓存或作为完整附件清单 |
| 列表操作 | 更多菜单和批量操作先取得完整详情 | 加载失败可重试；筛选切换后的旧响应不打开操作 |

迁移及投影更新按账号、项目和实体依赖定向处理。源会话新输入、设置、节点撤销、Builder/处理轮次/状态、协作目标变化、开发及发布凭据均会触发相应刷新。普通 Agent 输出、相同快照及普通评论不会重建合并展示。派生过程内共享只读计算结果，离开写入即释放，不作为跨请求缓存。

公开 HTTP 读取仍先校验当前产品权限；领取、交付、合并与发布动作继续使用实时源授权。投影不是凭据，不能用于制造批准、推进业务状态或代替发布证据。

### 旧库与恢复

首次迁移给已有条目、交付和批次登记回填任务；Store 和 MergeDeliveries 初始化时、对外服务前消费这些任务。任务删除与源写入、投影写入处于同一事务，失败回滚后保留待处理任务；重启继续处理。新迁移只新增派生表和索引，没有修改历史状态事件。

正常应用写入使用同一数据库连接及事务入口。历史迁移测试为构造旧模式，会在关闭 Store 后使用独立原始连接移除较新的派生模式，避免运行中的派生写入器面对被测试主动拆除的表；没有删除或放宽旧迁移断言。离线外部工具直接修改数据库不属于在线应用写入入口，重新启动后才消费其留下的变更标记。

## 性能实验方法与限制

使用全新 SQLite 合成数据，在一个账号/项目内构造 500/1000 条目、100/200 个历史批次、每批 20 份交付（共 2000/4000）、100 条较长诊断事件。交付集中关联同一个源条目和会话，这是偏重共享依赖的压力形状，不冒充真实生产分布。每次返回最近 20 个批次。

参考侧执行原四组全量计算；新侧通过已登录的 Fastify 注入请求执行完整 GET，重复 30 次并记录首次、p50、p95、最大值。准备查询计数包含权限等请求开销。普通读取在禁止时间线组装时必须成功，查询数须固定且少于 25；墙钟测量输出到日志，不把偶发 CI 调度抖动写成脆弱单测断言。

| 合成规模 | 全量参考查询数 | 新 GET 查询数 | 本机 GET p95 / 最大值 |
|---|---:|---:|---:|
| 500 条目 / 100 批次 / 2000 交付 | 62,973 | 9 | 4.27ms / 10.99ms |
| 1000 条目 / 200 批次 / 4000 交付 | 76,073 | 9 | 10.37ms / 16.66ms |

上述带查询计数的测量与浏览器回归并行运行，包含本机调度负载。较早的独立测量中，稳定读最大约 3ms；不选择较小数字冒充唯一结果。批量生成源数据并派生投影约 2.7s/12.2s，无关单条更新约 0.9ms/1.6ms；此生成成本包含写入与首次派生，不能说成纯启动耗时。生产首次回填、关联大量历史的写入及磁盘空间开销仍需发布窗口观察。

验收目标仍为生产量级单次轮询 <50ms。这里证明合成基准中的请求低于目标、读查询数与历史规模脱钩；未导出生产数据，未采集生产规模统计，也未执行上线性能验收。网络端到端耗时不由本机 inject 基准证明。
