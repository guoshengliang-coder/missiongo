## 诊断证据

四条正文、完整时间线与全部 10 张图片均已读取；无遗漏附件。图片证明空列表、重复指令、缺少详情阶段、默认值按钮及选中行不在视口中的现象。

重复提醒源于交付归因的覆盖边界：明确 `deliveryOnly` 才承接重复指令，而旧逻辑排除 `batched`。本轮补齐当前归因与合并阶段承接，仍保留独立指令、来源权限、正式审批、问题及异常；归因失败保持可见。旧分类补核只处理当前有效交付的当前消息一次，失败不循环分类，不批量重算历史。

原进度只支持待合并/合并中徽章，详情只显示尚未批次化的交付卡。现已增加统一的服务端当前会话投影，历史合并/发布事实与当前标签独立。

## 行为与兼容

### 默认值

复用 `DispatchDialog`、`Select`、原生 checkbox、公共 Modal 草稿及 pending 保护。配置与默认值不同或默认值为空时显示；每次打开、配置组合变化后均默认不勾选。相同配置不显示勾选。默认值读取失败明确提示并允许重试，普通派单不会因此自动改写偏好。

普通派单与接手在创建被接受的同一事务保存；保存失败则整次回滚，不创建半份派单。新项目会话只在首条消息与附件实际进入启动事务时保存；仅配置、预留会话或上传失败均不保存。相同预留与 start 重试不会重复创建命令。节点在接受之后启动失败不回滚已保存的默认值。

模型与强度仍通过既有能力校验；草稿快捷配置或能力刷新改变组合时撤销旧勾选意图，文字和附件保留。没有放宽权限模式。

### 交付状态与真实证据

`MergeProgressBadge`、`DeliveryCards` 和 `SessionDeliveryNotice` 在控制台、条目内会话面板及列表共用服务端投影。合并完成沿用蓝色令牌，已发布沿用紫色令牌与 CloudUpload 图标；无新增样式豁免。

- 合并事实只取已登记的真实结果；发布事实只取匹配原 PR 且覆盖完整必需产物的正式凭据。部分合并、部分发布与发布待核实分别表达；混合无需发布的交付不阻止其他必要产物的完整发布结论。
- `record_merge_integration` 增加 `publication_progress`，受原 batch/dispatch、权限、版本、幂等键、全部已知结果、发布选择、部分发布人工决定及有效组合验证约束。`resultsDigest` 由 `get_merge_batch` 返回，不能自行猜测。仅限有限的 publishing/failed/ended 阶段，不提供 SQL 或任意字段写入。
- publishing 信号五分钟内续期；过期显示待核实。ended 不表示已发布，仍须完整正式凭据；有未结束的有效发布信号时不能结束批次。
- 完成标签以合并时的会话输入、设置及派单身份为边界。成功接受的新消息、执行设置变更或重启身份改变后收起；失败请求、阅读、收藏、展开、轮询与迟到的旧消息不清除。历史结果不删除，不恢复旧批准或撤销真实发布。
- 旧批次无快照时，只在匹配正式完成事件、输入时间及初始设置修订足以核实未调整时显示完成标签；无法核实则保留历史详情，不伪造当前完成状态。旧客户端未上报阶段时不猜“发布中”。
- 列表轮询只读所需的正式凭据事件，不加载评论或会话历史正文；原始消息不插入、裁剪或重排。

仓库分发 Skill 与服务端期望同步提升至 5.66.0，新增阶段上报指引；未修改本机全局 Skill 文件。需要部署后客户端按正式分发流程更新，旧会话不可假定已经加载新文本。

### 列表与定位

条目查询消费取消信号，旧条件请求不能接管新条件。只用当前首屏自己的 summary 与当前状态核对，不借其他筛选的缓存数字。真正空结果仍显示空态；后台失败保留已有数据；数量冲突不会清空用户筛选或循环自动请求。

会话定位复用现有列表及稳定选中项，在跳转、目标到达、列表重新可见及尺寸变化后检查几何边界。只调整列表 scrollTop，不调用整页滚动，不改变聊天阅读位置。普通轮询和用户滚动不触发重新定位。镜像别名使用既有 canonical 身份。
