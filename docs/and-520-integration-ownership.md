# AND-520 待集成归属与生命周期修复

## 问题与实现

合并登记早于批次结束，旧队列只按 merged 与产物凭据分类，导致同一在办交付重新计为待发布；正常无需发布交接也被计为独立异常。仅发布与额外覆盖还必须保留旧合并引用，不能重写 batchId 来表达当前归属。

服务端在原显示投影派生 processing_batch_id，覆盖所选 revision、引用与冻结候选的精确开发事件／处理轮次。活动内容退出新待办和未关闭异常计数，历史与已关闭核查保留。原集成详情显示交接障碍和额外发布责任。正式发布候选、执行门禁与人工状态独立。

清单以只读事务返回行、数量与项目占用。只有原账号取得会话和原请求身份；其他账号仅见占用。新 Web 共用这份快照，旧服务缺字段时兼容旧读取。未知响应仍可按原冻结参数重试同次已受理请求，不能重复启动。

迁移 202611140247 仅增加派生列与索引并重建投影。批次写入会同时刷新先前归属及新冻结范围，结束后回流剩余有效待发布；未知结果、超时和断线不释放归属。源确认、batchId、Git 结果、正式凭据与人工事件不改写。历史引用与冻结额外范围保留反向依赖，即使批次已结束，后来补齐的正式凭据也会刷新其只读详情；这不恢复活动归属或授权。
