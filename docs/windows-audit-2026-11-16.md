# AND-399：主线同步后的三轮审计

本轮起点为 `f3b1b1fb`。审计前重新获取 `origin/main`，仍为 `7e2ad5b545d11848ff3560fab104ac6fd10ec262`，分支已包含该主线。只在原独立工作区补修，不推送、合入main或发布。各轮顺序进行，独立核查不同边界并复核已有修复；不冒充其他审阅者的结论。

## 第一轮：Agent识别与真实环境

发现并复现：配置路径不变而环境脚本内容改变时，版本检查使用新环境，模型/控制握手缓存仍使用旧配置键。新环境已拒绝控制握手，探测却继续返回ready；Claude权限能力也可能沿用旧环境证据。

补修：模型和原生权限缓存共同绑定实际解析的启动器与环境摘要，保留原有TTL和数量上限；只保留SHA-256键，不把模型凭据原文放入缓存键或日志。

验证：新增回归在补修前失败（错误返回ready），补修后Node完整22个文件、223项通过；包括环境改变后的控制拒绝与Claude模式证据刷新。lint/typecheck通过。首次沙箱内全套因Unix socket `listen EPERM`失败，获准在本机权限下完整重跑通过，未放宽断言。真实Codex Skill摘要保持原值。

## 第二轮：异步配置与登录生命周期

发现并复现：设备改名等待服务器响应时持有旧配置；响应晚于退出或凭据替换时，保存旧配置会恢复原Token/节点，亦会覆盖等待期间修改的Agent及受控执行设置。

补修：服务器确认后重新读取本地配置，核对服务器、节点、安装身份和凭据仍相同，仅修改当前配置的名称；身份变化时拒绝旧结果。worker只在显式`--worker`入口消费RPC，导入实际处理函数不再意外接管测试进程stdin。

验证：新增3项真实请求处理函数回归在补修前均失败，补修后Windows全套13项通过、11项原生条件跳过；lint/typecheck及Windows构建通过。此结果不等于Windows原生DPAPI或Electron实机验证通过。
