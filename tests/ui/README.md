# 界面检查（D1-1、D1-3）

这里的通用测试用 Chromium 打开控制台，在 5 种视口 × 2 种主题下检查界面；其他页面和交互另有专项测试。对应
[UI/UE 复盘与改进方案](../../docs/ui-ue-review-2026-09.md) 的 D1-1 与 D1-3，规范见
[设计规范](../../docs/design-system.md)。

## 两个项目

| 项目 | 命令 | 查什么 | 在 CI 跑吗 |
|---|---|---|---|
| `audit` | `npm run test:ui` | 量出来的数：字号下限 11px、文字对比度 4.5:1（大字 3:1）、触屏下点击区域 44×44、横向溢出、深色下写死的浅色块 | 是 |
| `visual` | `npm run test:ui:visual` | 截图和基线逐像素比对 | 是（用 Linux 基线） |

`audit` 的结论是数字，在哪台机器上都一样；`visual` 的基线和渲染平台绑定，Linux 和 macOS
的字体不同，排版就不同。

## CI 并行与耗时

main push 和普通手动运行执行全量 UI 测试；PR 先生成变更影响计划：

| PR 变更范围 | UI 执行范围 |
|---|---|
| 仅仓库根 Markdown、`docs/*.md`、原生客户端/SDK、未被产品导入的 Web 单元测试 | 跳过行为与截图任务 |
| 仅发布说明 JSON 或 `released.json` 的版本、来源、摘要 | 校验格式、来源祖先关系和声明版本后跳过 UI；改变制品清单或构建输入仍全量 |
| 已审查的独立功能边界及其私有依赖 | 相关专项 + 核心冒烟，单 runner；全部 30 张截图独立比对 |
| 仅某个 UI 专项测试 | 该文件 + 核心冒烟；全部截图比对 |
| 仅现有 Linux 截图基线 | 仅截图比对 |
| App 主入口、共用样式/组件、权限、API、服务端、共享包、构建/CI/测试配置、删除或未知输入 | 八分片全量行为 + 全部截图 |

计划出现在 `ui-plan` 的 Job Summary 中，包含模式、原因、选中的专项文件和提交。无法取得 PR base、
无法解析导入、出现动态依赖或新的消费者时，回退全量；计划生成失败时，`ui` 不能通过。
分片失败、取消、意外跳过，或 main 使用缩小范围的计划，也不能通过汇总门禁。
`ui-plan` 拉取完整 Git 历史以验证基线祖先关系；只补取 base 对象无法修复 depth-1 checkout 的提交断链。
发布元数据校验失败会直接阻止计划成功，不能借跳过 UI 获得绿灯。Web/后端与契约检查始终执行；原生平台按下述规则选择。
同一 PR 的新提交取消旧 CI；main 和手动运行各自保留，不因新提交取消发布依据。

原生平台共用同一份提交差异证据；main、手动运行、缺失证据、删除/类型变化和未知路径均全量：

| PR 文件范围 | 原生构建 |
|---|---|
| `apps/macos/` | macOS |
| `apps/android/`、`sdks/android-feedback/` | Android |
| `apps/node/` | 两个 Ubuntu 版本的 Linux Node |
| `apps/web/`、`tests/ui/`、文档、已校验的发布元数据 | 无关原生构建可跳过 |
| 共享包、服务端、产品声明、根依赖、构建/CI 脚本及其他未知输入 | 全部平台 |

混合变更取并集。`android`、`macos` 和 `linux-node` 汇总检查验证计划属于当前提交，且实际构建的 success/skipped 与计划完全一致；计划失败、构建失败、取消和意外跳过都不能获得成功。主线汇总还强制所有平台必须执行，保留发布门禁所用的固定检查名。

功能边界和专项对应关系在 `impact-map.json`。当前只收窄统计、独立决策页、下载面板和 Agent 产物预览；
沿实际静态导入、再导出和字面量动态导入追踪私有依赖，多个功能同时受影响时取并集。共享 URL、权限
或数据辅助函数即使名称带某个功能，也可能仍直达 `App.tsx`，这类变更全量检查。
增加边界时须审查消费者和跨入口专项，不能仅按名称前缀推断。修改映射本身也会触发全量。

核心冒烟包含 `audit-engine.audit.spec.ts` 的测量器回归，并复用 `audit.spec.ts` 的完整视口/主题矩阵、
`agent-console-enter.audit.spec.ts` 的消息输入交互和 `capture-permissions.audit.spec.ts` 的录入权限与草稿保护。没有缩减它们内部的断言或主题覆盖。

全量模式下：

- `ui-audit (1)` 到 `ui-audit (8)` 根据 `audit-durations.json` 的历史文件耗时分配，优先把长文件放入预计最空闲的分片，各自启动独立的服务、数据库和账号。新增或改名文件以最大历史耗时估计，仍纳入完整目录；旧文件的估计不会导致执行已删除文件。
- 调整慢用例后，使用完整、成功且覆盖当前目录的 CI 样本刷新权重，并在 `sampleRuns` 记录来源；不要把失败、重试或只运行部分专项的耗时作为全量样本。权重只决定分组，不决定是否覆盖。
- 计划包含每片完整文件清单，校验所有当前专项恰好覆盖一次；遗漏、重复、未知文件、旧版计划均不能执行。执行器直接传入本片文件，使用 `--shard=1/1`，不能再对该子集二次分片。
- 每个分片仍只有一个 worker，文件内按原顺序执行；不要直接开启 `fullyParallel` 或增加 worker，共用账号的通知计数、派单默认值等会互相影响。
- `ui-visual` 独立执行全部截图比对，不等行为测试结束。手动勾选更新基线时，只运行截图生成，仍使用 `--update-snapshots=all`。
- `ui` 汇总前两类任务，保留发布门禁检查名；行为测试失败、取消或意外跳过，均不能通过汇总检查。

行为报告与附件分别在 `ui-audit-1` 到 `ui-audit-8`；截图基线与报告仍在 `ui-snapshots`，互不覆盖。
完整报告包含每条测试耗时，可用于后续对比分片耗时和调整测试组织。

行为与截图任务使用官方 Playwright Resolute（Ubuntu 26）容器，保持现有 Linux 基线的系统版本；镜像版本由 `ui-plan` 安装的锁定 `playwright-core` 版本生成，
与测试任务的同一份锁文件保持一致。镜像预装浏览器、系统库和字体，不再在每个分片中运行 apt 和浏览器下载。
截图仍比对原有 Linux 基线，不自动改写；环境变化造成的差异必须先诊断。宿主固定 `ubuntu-24.04`，容器使用独立 IPC 配置运行 Chromium。
官方容器未包含原 runner 的 DejaVu 等宽字体，因此只读挂载宿主现有 DejaVu 字体目录，刷新字体索引并确认 `monospace` 仍匹配 DejaVu Sans Mono；缺失或匹配变化直接失败，不下载替代字体或放宽图片阈值。任务时区显式设为 UTC。

本机查看当前分支的 PR 计划：

```bash
GITHUB_EVENT_NAME=pull_request UI_BASE_SHA="$(git rev-parse origin/main)" node scripts/ui-test-plan.mjs
```

原有 `npm run test:ui`、`npm run test:ui:visual` 始终保持全量；只有 CI 的 `run-ui-tests.mjs`
按已验证的计划选择文件，并校验计划提交与当前 checkout 一致。

本机运行与 CI 相同的一个分片，可将 `ui-test-plan.mjs` 的输出设为 `UI_TEST_PLAN`，再运行
`node scripts/run-ui-tests.mjs --kind=audit --shard=1`。原生 `npm run test:ui -- --shard=1/8` 使用 Playwright 默认分配，覆盖总量相同但分组不同。不要在同一 checkout 同时启动多个
Playwright 命令：它们会覆盖 `.auth` 和报告；并行验证须使用独立 checkout 和不同测试端口。

验证状态随轮询刷新的测试，在导航前 `page.clock.install()`，修改 mock 或通过 API 更新夹具后，
按实际轮询间隔推进浏览器时钟，再断言实际读取后的界面；会话轮询复用 `polling.ts`。详情、列表仍走真实轮询回调和 HTTP 请求，
不修改产品轮询间隔，也不以刷新页面代替自动更新。验证平滑滚动、动画或真实时间间隔的测试继续使用真实时间。
评论撤回、跨标签页待处理计数和模拟钉钉通知进度也复用该帮助函数，推进五秒轮询并等待对应真实 GET 完成；通知测试额外检查已受理的中间状态。模拟通知始终在测试 API 边界截获，不发送外部消息。

## 基线归 CI 所有

版本库里只放 CI 用的 Linux 基线（`*-linux.png`）。本机跑 `visual` 会生成 `*-darwin.png`，
这些文件不进版本库（见 `.gitignore`），只用于你在本机比较改动前后。

界面确实要改、需要更新基线时：

1. 在 GitHub Actions 里手动运行 CI 工作流，勾选 `update_ui_snapshots`；
2. 下载 `ui-snapshots` 产物；
3. 把里面的 `*-linux.png` 覆盖到 `tests/ui/visual.spec.ts-snapshots/`，作为改动的一部分提交。

比对失败时，同一个产物里有差异图和 Playwright 报告。

## 测试环境从哪来

`tests/ui/fixture.mjs` 会另起一个 MissionGo：临时目录当数据库、临时生成的测试账号、
独立端口（服务端 8799，前端 5199）。它不读仓库里的 `.env`，也不碰你本机的数据。
种子数据由 `scripts/seed-ui-fixture.mjs` 写入，每次内容相同：五种类型、七种状态、两张截图、
一个日志附件、一条评论和一个长链接。

这个种子脚本也可以单独用在本地的临时实例上：

```bash
node scripts/seed-ui-fixture.mjs --base http://127.0.0.1:8799 --cookie "<会话 cookie>"
```

## 审计准确性与用例整理

文字、背景和下拉框边界共用 `audit-colour.mjs`。普通 RGB 保留浮点精度，现代 CSS 颜色
（`color-mix()`、`color()`、Lab/LCH、OKLab/OKLCH 等）由浏览器转换到 sRGB 后测量；结果按 8 位颜色量化。
无法转换时测试明确失败，不能将该文字跳过或用 `NaN` 通过比较。透明背景沿实际祖先逐层合成，
透明根节点使用浏览器当前 `color-scheme` 下的系统画布色；深色主题的品牌色豁免按颜色与透明度判断，不依赖 CSS 字符串格式。
全透明祖先里的文字不参与测量。测量器的 18 个小型浏览器用例检查这些规则，也随 PR 核心冒烟执行。

| 检查组 | 处理 | 保留的保障 |
|---|---|---|
| 通用矩阵的可读性与触控尺寸 | 同一页面一次加载、一次扫描，触控断言作为单独 step；去掉 24 次重复加载 | 全部 5 种视口、2 种主题、3 个页面，以及 44×44 零豁免；软断言让可读性失败时仍检查触控 |
| `overlay-history` 的 4 个截图取证用例 | 删除重复的可见性检查与未做基线比较的截图取证 | 通用 30 张基线仍保留；`overlay-contract` 检查预览关闭、逐层 Back 与焦点，`toolbar-font-contract` 检查 320px、大字号和真实控件可达性 |
| 各页面专项中的相似扫描 | 保留 | 设置、审批、筛选和弹层的状态并不相同，不能用列表首页的一次扫描替代 |
| Select 组件与业务接入 | 保留两层 | 前者检查键盘、分组、碰撞、表单值；后者检查真实筛选入口和 SDK 提交参数，覆盖不同故障 |
| 输入、权限和嵌套弹层 | 保留 | IME/Enter、触控发送、权限拒绝后草稿、焦点恢复、层级返回、转派跳转竞态 |

## 已知的豁免

- `audit.spec.ts` 里的 `SMALL_TARGET_ALLOWANCE` 已为 **0**，触控目标不允许小于 44×44；原先的 8 个豁免已清理。
- `font-size: 0` 不算违规：图标按钮用它隐藏文字标签，同时保留无障碍名称。

## 覆盖边界

通用矩阵见 `fixture.mjs`：375×812、812×375、768×1024、1180×820、1440×900，覆盖列表、详情与 Agent 控制台。设置、筛选、审批等另有专项，但不是所有状态都进入通用截图矩阵。

颜色对比度仍基于元素的文字色和背景色，不模拟背景图片、渐变、混合模式、滤镜、伪元素遮挡或
半透明祖先整组绘制后的最终像素，也不能证明实际点击区域未被其他元素遮挡。这些情况需要截图和交互专项。

UI 测试通过不代表 Safari、Android WebView 或 macOS 原生界面已验收。本轮新增的 `overlay-contract.audit.spec.ts` 覆盖分层返回、草稿、焦点恢复、iframe 和 SDK 桥接；`toolbar-font-contract.audit.spec.ts` 与 `visible-control.ts` 检查控件及裁切祖先、三档字号、320px 和断点两侧。这些专项不能证明所有入口或平台都没有缺陷；原始案例见 [2026-10 审计](../../docs/ui-ue-audit-2026-10.md)。新增入口需按[设计规范 §8–§9](../../docs/design-system.md)补同类交互验证。
